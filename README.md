>
> 本仓库的**文档、基础设施与示范代码**由 AI 撰写与维护；

## 这是什么

**Lean4Practice** 是一个 **Lean 4 学习与实践**项目。

它目前处于**最早期阶段**：已建立**最小可编译基线**（Lean 4 + Lake，`lake build` 通过），并已开始跟练教材 **[《Theorem Proving in Lean 4》](https://leanprover.github.io/theorem_proving_in_lean4/)**（TPIL），从**第 3 章「命题与证明」**起——那是真正开始写证明的地方。

> ✅ **现状提示**：Lean 工具链（**`v4.34.0`**）已安装，`lake build` 已**实测通过**，构建缓存通过符号链接放在 Linux 侧。当前**有意不引入 mathlib**（TPIL 前几章不需要它）。详见 [`AGENTS.md`](./AGENTS.md) 的 D7。

学习进度、讲义与练习入口见 [`TPIL/进度.md`](./TPIL/进度.md)。

## 「AI 主导、人类习作」意味着什么

这不只是一句口号，而是一条会影响你如何使用本仓库的**实质性声明**。

### 分工

| 角色 | 负责 |
|---|---|
| **人类** | 提出需求、拍板决策、**完成 Lean 习题的证明**、发起 git 提交 |
| **AI** | 讲解与批改、示范代码与文档的撰写、自检、**自行维护项目约定文件** |

为什么不让 AI 把证明也写了？因为 **Lean 的学习恰恰发生在「写不出来」的那一刻**。如果 AI 把 `induction` 该用哪一步都填好，学习者就跳过了真正长出能力的过程。所以本仓库刻意把**习题**留给人类：AI 给示范、给提示、给批改，但不代做。

**git 是另一处边界**：**提交与推送一律由人类主动发起**。AI 可以随时修改工作区文件，但**不会自行提交**——它只在改动完成后列出待提交内容，由人类决定何时提交、提交什么。

### 由此产生的两点须知

1. **AI 产出的部分可能出错，请保持审慎。**
   本仓库的**文档与示范代码**由语言模型生成，可能存在事实错误、逻辑漏洞或过度的自信表述。**「AI 说已验证」不等于「真的验证过」**——尽管本项目已明确要求 AI 区分「已实测事实 / 推测 / 待确认」，但这条要求本身也是靠自觉执行的。
   （`TPIL/` 下由人类完成的习题不在此列——那些证明的正确性以 Lean 编译器为准。）

2. **项目约定是自我维护的。**
   本项目的规则不是人类预先写好的教条，而是 AI 在实践中**自己沉淀并持续回写**的结果。参见下方的 `AGENTS.md`。

## 项目约定入口：AGENTS.md

[`AGENTS.md`](./AGENTS.md) 是本项目的**长期记忆与协作契约**，也是**唯一**的约定入口。

它存在的目的：**即使历史会话被删除、或换到全新会话、新模型，只要读这一个文件，就能按同样的方式接续开发，不必重新摸索，也不该重复犯同样的错误。**

它记录了：

- **环境事实**——经实测验证的本机约束（勿重新摸索）
- **关键决策**——ADR 风格的决策记录及理由
- **踩坑清单**——每条都附可执行的对策
- **维护协议**——AI 在何种时机、以何种方式更新该文件
- **待定事项**——明确标注「尚未确定」，禁止凭空假设

> 该文件由 AI 主动维护：形成新工作流、被用户纠正、踩到新坑、环境变化、决策落地等时机都会触发更新，并留有变更记录。

## 如何接续开发

新会话（无论换模型还是换工具）请按此顺序开始：

1. **先读 [`AGENTS.md`](./AGENTS.md)**，再动手。
2. **再读 [`TPIL/进度.md`](./TPIL/进度.md)**，了解学习进行到哪一章、有哪些卡点。
3. **遵守其中的环境约束**——尤其「不运行无缓存的全量构建」这条硬约束（本机仅 2 核 / 3.8 GiB 内存）。
4. **遇到 `AGENTS.md` §7 标注的「待形成」事项，先与人类确认**，不要自行当作既定规则。
5. **⚠️ 不要替人类做习题**——讲解、示范、批改都可以，**代做不行**（见上文「分工」）。

## 本地构建与检查

```bash
export PATH="$HOME/.elan/bin:$PATH"   # elan 不会自动进入非登录 shell 的 PATH
lake build                            # 构建库：首次约 25 秒，增量接近瞬时
lake env lean TPIL/03-习题.lean       # 逐文件检查习题
```

习题**不属于构建库**，所以 `lake build` 不会检查它们，必须单独用 `lake env lean` 检查。

> ⚠️ `sorry` 只是 **warning**，退出码仍是 **0**——「能通过」**不代表**做完了。完整验收命令见 [`TPIL/进度.md`](./TPIL/进度.md)。

构建产物通过符号链接落在 Linux 侧，不占用 Windows 盘。

## 仓库结构

当前**实际存在**的文件（可编译通过）：

```
Lean4Practice/
├── README.md            # 本文件
├── AGENTS.md            # 项目长期记忆与协作契约（唯一约定入口）
├── LICENSE              # MIT 许可证全文
├── lean-toolchain       # 固定的 Lean 版本：v4.34.0
├── lakefile.toml        # Lake 项目定义
├── lake-manifest.json   # 依赖锁定（当前无依赖）
├── Lean4Practice.lean   # 库根模块，负责 import 各子模块
├── Lean4Practice/       # 源码目录
│   └── Basic.lean       # 冒烟测试：几个 trivial 证明
├── TPIL/                # 学习目录（不属于构建库，逐文件检查）
│   ├── 进度.md           # 学习进度、卡点、验收命令
│   ├── 03-讲义.md        # 第 3 章讲义（AI 写）
│   ├── 03-示例.lean      # 示范示例（AI 写，已通过编译）
│   └── 03-习题.lean      # 习题（【人类作答】）
├── .gitattributes       # 文本固定 LF、二进制显式标记
├── .gitignore           # 忽略 .lake 符号链接与构建产物
├── .lake -> Linux 侧构建缓存   # 符号链接，本机专属，已被忽略
└── .git/                # 本地仓库
```

> 注：`.lake` 在本项目中是一个**符号链接**，指向 Linux 侧的构建缓存（源码在 Windows 挂载盘上，而该盘读写慢且权限位无效，故构建缓存必须外置）。它只在本机成立，**已被 gitignore，绝不能提交**。
> 注：新增 `.lean` 文件后，需要**在 `Lean4Practice.lean` 中加对应的 `import`**，否则 `lake build` 不会编译它。
