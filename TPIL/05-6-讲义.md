## §1 上一课留下的「啰嗦」

05-4 教你拆一条假设要这么写（**长写法**，06 之前的正规写法）：

```lean
example (p q r : Prop) (h : p → q → r) : p ∧ q → r := by
  intro hpq
  cases hpq with
  | intro hp hq => exact h hp hq
```

05-5 教你造目标也用长写法（`constructor` ＋ 一行交一个）。
这些都对，但有四处**啰嗦**：

| 啰嗦在哪 | 本课的省事工具 |
|---|---|
| 拆**假设 `h`**（它的类型是 `∧`）要 `cases h with \| intro hp hq =>`（还要自己写构造子名） | **`rcases h with ⟨hp, hq⟩`**（§3） |
| 把**目标左边那块**请进来时想顺手拆**它**：`intro` 只能拆**一层**（`intro ⟨hp, hq⟩`）、**分两条路**要写 `intro` ＋ `\| 构造子全名 => …` | **`rintro`**（§2；多一种**交替模式** `(hp \| hq)`，其余与 `intro` 等价，见 §2.4） |
| 分支一多，`cases … with` 里**每条分支只能写一个 tactic** | **`match`**（§4，分支是 tactic **序列**，还能**一次把好几个表达式都分开**） |
| 手上有矛盾时，要自己把 `False` 造出来再消掉（`False.elim (hnp hp)`／`absurd h hnp`） | **`contradiction`**（§5，一步把**当前目标**交掉） |

## §2 `rintro`：`intro` 的**模式版**（多出来的只有「交替模式」）

`rintro` 请进来的是**目标左边那块**；被拆的也是它——它在变成假设的那一瞬间就按模式拆开。

⚠️⚠️ **先说清楚**：`intro` **也能**收模式（`intro ⟨hp, hq⟩`）、**也能**一行收好几个名字（`intro hp hpq`）、
**也能**分支（`intro` ＋ `| Or.inl hp => …`）。`rintro` 相对 `intro` **只多「交替模式」**这一件——**逐形态实测见 §2.4**。

### §2.1 收**名字**：一次请进来**好几条假设**（不拆）

```lean
example (p q : Prop) : p → (p → q) → q := by
  rintro hp hpq
  exact hpq hp
```

（⚠️ **`intro hp hpq` 一行就行**——`intro` 也能收多个名字；所以这一小节里 `rintro` **不比 `intro` 短**。差别见 §2.4。）

⚠️ 这里**故意不写**一条和待证命题一模一样的假设（即 `(h : p → (p → q) → q)`）——
那样 `exact h` **一行就完了**，反而看不出 `rintro` 在干什么。

⭐ 这两个名字收到的是**两个依次的假设**。实测（只有这两个名字，目标 `p → (p → q) → q`）：

```text
example (p q : Prop) : p → (p → q) → q := by
  rintro hp hpq
```

```text
error: unsolved goals
p q : Prop
hp : p
hpq : p → q
⊢ q
```

（看：`hp : p`、`hpq : p → q` 是**两条各自独立的假设**。）

⚠️⚠️ **别把 `rintro hp hq` 当成「拆 `p ∧ q`」**：`rintro` 是**一次收一个**，
要拆 `∧` 必须写**模式** `⟨…⟩`（§2.2）。在 `p ∧ q → r` 上写 `rintro hp hq` 会**报错**（实测）：

```text
example (p q r : Prop) : p ∧ q → r := by
  rintro hp hq
```

```text
error: Tactic `introN` failed: There are no additional binders or `let` bindings in the goal to introduce

p q r : Prop
hp : p ∧ q
⊢ r
```

看清那条 **`hp : p ∧ q`**：第一个名字把**整个** `p ∧ q` 收进来了（它是**一条**假设），
于是第二个名字 `hq` **没有东西可收** → 报错。
**同一道题的正确写法是 `rintro ⟨hp, hq⟩`**（§2.2）——`⟨…⟩` 才是「拆」。

### §2.2 收**模式**：用 `⟨…⟩` 把**刚请进来的那块**拆一层

```lean
example (p q r : Prop) (h : p → q → r) : p ∧ q → r := by
  rintro ⟨hp, hq⟩
  exact h hp hq
```

它做完之后的状态（实测）：

```text
example (p q r : Prop) : p ∧ q → r := by
  rintro ⟨hp, hq⟩
```

```text
error: unsolved goals
p q r : Prop
hp : p
hq : q
⊢ r
```

⭐ 和 §1 那段**长写法**做完之后的**效果完全一样**（假设里同样多出 `hp : p`、`hq : q`），
只是少了「先 `intro hpq` 再 `cases`」那两步。⚠️ 但**这个写法 `intro ⟨hp, hq⟩` 也照样能写**（05-4 教过）——`rintro` 在这一小节**没有优势**（见 §2.4）。

### §2.3 收**交替**模式：把**刚请进来的那块**分成两条路

**被拆的那块**类型是 `∨`——它有两种造法，所以模式里可以写**两条路**：

```lean
example (p q r : Prop) (f : p → r) (g : q → r) : p ∨ q → r := by
  rintro (hp | hq)
  exact f hp
  exact g hq
```

⚠️ **注意这两行是怎么接的**：`rintro (hp | hq)` 之后**不是一个目标是两个**（实测）：

```text
example (p q r : Prop) : p ∨ q → r := by
  rintro (hp | hq)
```

```text
error: unsolved goals
case inl
p q r : Prop
hp : p
⊢ r

case inr
p q r : Prop
hq : q
⊢ r
```

所以后面**一行交一个**（就是 05-3 学过的那条：「普通写法一行只处理当前那一个目标」）。
标签还是老名字：`case inl`／`case inr`（05-4 §2.4 那张表）。
（要把两支「打包」起来写——`·`／`case 标签 =>`——那是 **05-7**。）

### §2.4 ⚠️ `rintro` 相对 `intro` 到底多什么（**实测差集**）

**结论先说：`rintro` 与 `intro` 几乎等价，只多「交替模式」这一件（外加一条语法限制）。**

| 形态（同一版 Lean 上逐个跑过） | `intro` | `rintro` |
|---|---|---|
| 收**一个**名字 `hp` | ✅ | ✅ |
| 收**多个**名字 `hp hpq`（**一行**） | ✅ | ✅ |
| 收 `⟨hp, hq⟩`（拆一层） | ✅ | ✅ |
| 收 `_`（通配） | ✅ | ✅ |
| 收 `rfl`（等式模式） | ✅ | ✅ |
| 收**交替** `(hp \| hq)` | ❌ `unexpected token '\|'; expected ')', ',' or ':'` | ✅ **只有 `rintro` 能写** |
| 交替**嵌在** `⟨…⟩` 里：`⟨hp, hq \| hr⟩` | ❌ `unexpected token '\|'; expected '⟩'` | ✅（分成 `case inl`／`case inr` **两个**目标） |
| **不带参数**（光写一个词） | ✅ `intro` 可以 | ❌ `expected checkColGt`（**至少要给一个模式**） |

⚠️ 所以 **§2.1／§2.2 那两个例子用 `intro` 写完全一样**——§2.1 的 `intro hp hpq` 甚至比 `rintro hp hpq` **短 2 个字符**。
`rintro` 真正**无可替代**的只有 §2.3 的**交替模式**。

⚠️ 另外：**「分两条路」也不是 `rintro` 的专利**——`intro` 也能分支，只是要写构造子**全名**
（**原文 5.3 用的就是这个写法**）：

```lean
example (p q : Prop) : p ∨ q → q ∨ p := by
  intro
  | Or.inl hp => exact Or.inr hp
  | Or.inr hq => exact Or.inl hq
```

（⚠️ 这里写**短名** `inl` 会报 `Invalid pattern: Expected a constructor or constant marked with `[match_pattern]``
——和 §4.2 里 `match` 的那条规矩是同一条。）

## §3 `rcases h with …`：拆**假设 `h`** 的省事版

05-4 的 `cases h with | 构造子 名字… => …` 是「把**假设 `h`** 拆开 **＋** 每条分支写一支」；
如果你**只想拆开**（不分支），用 `rcases`：

### §3.1 拆**类型是 `∧` 的假设**（`h : p ∧ q`）

```lean
example (p q : Prop) (h : p ∧ q) : q ∧ p := by
  rcases h with ⟨hp, hq⟩
  exact ⟨hq, hp⟩
```

状态（实测）：一个目标，假设里多出 `hp : p`、`hq : q` ✓——这**假设列表**和 05-4 的 `cases h with | intro hp hq =>` 做完之后是一样的。

### §3.2 拆**类型是 `∨` 的假设**（`h : p ∨ q`）：得到两个目标

```lean
example (p q r : Prop) (f : p → r) (g : q → r) (h : p ∨ q) : r := by
  rcases h with hp | hq
  exact f hp
  exact g hq
```

⚠️ 写法是 **`with hp | hq`**（**没有**括号——和 §2.3 的 `rintro (hp | hq)` 差在括号上）。
做完同样是 `case inl`／`case inr` **两个**目标，逐行交。

### §3.3 ⭐ 拆**类型是 `∃` 的假设**、一个模式拿**好几层**：`⟨w, hp, hq⟩`

这是 `rcases` 最省事的地方。**被拆的那条假设**是「`∃` 里面套 `∧`」时：

```lean
example (α : Type) (P Q : α → Prop) (h : ∃ x, P x ∧ Q x) : ∃ x, Q x := by
  rcases h with ⟨w, hp, hq⟩
  exact ⟨w, hq⟩
```

一个模式里拿到**三样**：`w`（witness）、`hp : P w`、`hq : Q w`。
（对照 05-4 §3.3：`cases h with | intro w hw =>` 只拿到 `w` 和 `hw : P w ∧ Q w`，
`Q w` 还得自己用 `.right` 取出来。）

### §3.4 ⚠️ `rcases` 相对 `cases` 到底多什么（**实测差集**）

**结论先说：两者能力几乎重合，差别在「写法」——`rcases h with ⟨…⟩` 是「一行、只拆开、自选名字、不用写分支体」。**

| 要干的事（同一版 Lean 上逐个跑过） | `cases` | `rcases` |
|---|---|---|
| 拆一层 `∧`、**并自选名字** | `cases h with` ＋ `\| intro hp hq => …`（**必须写分支体**） | `rcases h with ⟨hp, hq⟩`（**一行，没有体**） |
| 只拆开、**不想写分支体** | `cases h`——名字是 `h✝` 这类**不可引用**的，得另用 `rename_i`／`case` | `rcases h with ⟨hp, hq⟩`（名字**你自己起**） |
| 分两支（`∨`） | `cases h with` ＋ `\| inl hp => …` ＋ `\| inr hq => …` | `rcases h with hp \| hq`（⚠️ **不带括号**） |
| 交替**嵌在**模式里 | ❌ `cases h with \| intro hp (hq \| hr) => …` → `unexpected token '('; expected command` | ✅ `rcases h with ⟨hp, hq \| hr⟩` |
| 一次拆**好几层**（`∃` 套 `∧`） | ✅ 但要**嵌套两层**（`\| intro w hw => cases hw with …`） | ✅ **一个模式** `⟨w, hp, hq⟩` |
| 拆一个**项**（不是假设） | ✅ `cases p with \| mk a b => …` | ✅ `rcases p with ⟨a, b⟩` |
| 对 `Nat` 分情况 | ✅ `\| zero => …` ／ `\| succ k => …` | ✅ `rcases m with _ \| k` |
| 带**等式**的形式 | ✅ `cases h : n with …`（分支里拿到 `h : n = 0`） | ✅ `rcases h : n with _ \| m` |

⚠️ 照旧：**`rintro`／`rcases` 都不在原文 5.3 里**（同一次词频实测：`rintro` **0** 次、`rcases` **0** 次）；
原文的「拆」是 `cases h with …` 与无结构 `cases h`。

## §4 tactic 里的 `match`：把**你点名的那几个表达式**按构造子分开

官方文档（`Lean/Parser/Tactic.lean`，**逐字**）：

> `match` performs case analysis on one or more expressions.
> The syntax for the `match` tactic is the same as term-mode `match`, except that
> the match arms are tactics instead of expressions.

翻成中文：**tactic 版 `match` 和项版 `match` 语法一样，只是每条分支换成 tactic。**
（`match` 后面是**你点名的那几个表达式**——§4.1 例子里点的就是假设 `h`。）

### §4.1 把**假设 `h`** 按 `∨` 的两个构造子分开

```lean
example (p q : Prop) (h : p ∨ q) : q ∨ p := by
  match h with
  | Or.inl hp => exact Or.inr hp
  | Or.inr hq => exact Or.inl hq
```

⭐ **模式里的 `hp`／`hq` 是哪儿来的？——是你自己起的名字**（叫 `zzz`／`yyy` 也行，实测通过），
它被绑到**那个构造子的那个参数**上。构造子吃几个参数、每个参数什么类型，`#check` 一下就知道（实测）：

```text
Or.inl {a b : Prop} (h : a) : a ∨ b
Or.inr {a b : Prop} (h : b) : a ∨ b
And.intro {a b : Prop} (left : a) (right : b) : a ∧ b
Exists.intro.{u} {α : Sort u} {p : α → Prop} (w : α) (h : p w) : Exists p
```

由此得两条：

- **名字的个数** = 构造子显式参数的个数：`Or.inl` 吃 **1** 个，所以 `| Or.inl hp` 后面只能跟**一个**名字
  （给两个会报 `Invalid pattern: Too many arguments to \`Or.inl\`; expected 1 explicit argument`）；
  `And.intro`／`Exists.intro` 各吃 **2** 个，所以要写两个名字（`And.intro hp hq`／`Exists.intro w hw`）。
- **名字的类型**由「被拆的那个东西」定下来：上面 `h : p ∨ q`，而 `Or.inl : a → a ∨ b` 要凑出 `p ∨ q`，
  于是 `a := p`、`b := q`，所以 **`hp : p`**（实测：故意写成 `exact Or.inl hp` 会报
  `The argument hp has type p but is expected to have type q`）。

⚠️ 所以 `hp`／`hq` **不是上下文里原有的东西**——它们就是**被拆开的那条假设的两个部分**，名字由你起。

### §4.2 ⚠️⚠️ 模式里必须写**构造子全名**（本课最容易踩的一处）

把上面的 `Or.inl` 写成短名 `inl`（**故意写错**）：

```text
example (p q : Prop) (h : p ∨ q) : q ∨ p := by
  match h with
  | inl hp => exact Or.inr hp
  | inr hq => exact Or.inl hq
```

```text
error: Invalid pattern: Expected a constructor or constant marked with `[match_pattern]`

Hint: Using one of these would be valid:
  [apply] `Or.inl`
  [apply] `PSum.inl`
  [apply] `Sum.inl`
  ...
```

**为什么**：`match` 里的 `| …` 是**项级模式**（和 `fun`／`match` 表达式里的模式**同源**），
它要的是**构造子本身**；而 05-4 的 `cases h with | inl …` 里那个 `inl` 是**标签**
（Lean 允许你写构造子名的**短名**）。**同一个东西，两套写法**：

⭐ **补充（2026-10-12 学习者提醒）**：**匿名构造子记号 `⟨…⟩` 也能写在 `match` 的模式里**——
`| ⟨hp, hq⟩ => …` **实测通过** ✓，而且**原文 5.3 的 `match` 例子用的就是这个写法**（`| ⟨_, Or.inl _⟩ => …`）。
所以 §4.2 说的「必须写全名」，意思是**别写短名**（`inl`），**不是**「只能写 `And.intro` 这种全名」。

| 写法 | `| …` 里写什么 |
|---|---|
| `cases h with \| …` | **短名**：`inl`／`inr`／`intro` |
| `rcases h with ⟨…⟩`／`rintro ⟨…⟩` | **模式**（但不写构造子名，只写 `⟨…⟩`／`(… \| …)`） |
| **tactic 版 `match`** | **构造子全名**：`Or.inl`／`Or.inr`／`And.intro`／`Exists.intro`（**或匿名构造子记号 `⟨…⟩`**，见下方 ⭐） |

⭐ 好消息：**报错自己会给你 Hint**（上面那三行 `[apply] …`）——照抄改就行。

### §4.3 ⭐ 一次把**两个表达式都**分开（`cases` 做不到的）

```lean
example (p q : Prop) (h1 : p ∨ q) (h2 : p ∨ q) : q ∨ p := by
  match h1, h2 with
  | Or.inl hp, _ => exact Or.inr hp
  | Or.inr hq, _ => exact Or.inl hq
```

`match h1, h2 with` 把**两个**表达式一起看；用不到的那个写 **`_`**（通配）。
（`cases` 一次只能拆一个。）

### §4.4 分支里可以写**多行**

因为「分支是 tactic **序列**」，所以每条分支能放好几行——`cases … with` 那边一条分支只放一个 tactic。

### §4.5 ⚠️ 漏了分支会报错（实测）

```text
example (p q : Prop) (h : p ∨ q) : q ∨ p := by
  match h with
  | Or.inl hp => exact Or.inr hp
```

```text
error: Missing cases:
(Or.inr _)
```

（`cases … with` 漏分支的报错长得不一样，是 05-4 见过的 `Alternative \`inr\` has not been provided`。）

## §5 `contradiction`：**假设之间**有矛盾时，一步把**当前目标**交掉

官方文档（`Init/Tactics.lean`）给的三个例子——**都实测通过**：

```lean
-- ① 能「算」出假的等式
example (p : Prop) (h : 2 + 2 = 3) : p := by
  contradiction

-- ② 一条命题和它的否定
example (p q : Prop) (h : p) (h' : ¬ p) : q := by
  contradiction

-- ③ 「自己不等于自己」这类明显假的东西
example (p : Prop) (x : Nat) (h : x ≠ x) : p := by
  contradiction
```

注意**目标**可以是**任何**命题 `p`／`q`——`contradiction` 一旦在你手上的**假设之间**
（或从假设能「算」出来的东西里）找到矛盾，就直接把**当前目标**交掉。

### §5.1 ⚠️ 找不到矛盾时它**不瞎猜**（实测）

```text
example (p q : Prop) (h : p) : q := by
  contradiction
```

```text
error: Tactic `contradiction` failed

p q : Prop
h : p
⊢ q
```

**它失败时会报错、并把状态印出来**——也就是说：`contradiction` 能过，就说明**确实**有矛盾被它找到了；
它过不去，说明你手上的东西里**没有**它能用的矛盾（这时得你自己想办法，比如用 `False.elim`／`absurd`，见 03-10 的工具箱）。

## §6 判据表：四种写法怎么选

| 你要干的事（**对象** → 动作） | 短写法（本课） | 长写法（前两课） |
|---|---|---|
| 把**目标左边那块**请进来、顺手拆**它**一层 | `rintro ⟨hp, hq⟩` | `intro ⟨hp, hq⟩`（**一样短**；`rintro` 在此**无优势**） |
| 把**目标左边那块**请进来**好几条**（不拆） | `rintro hp hq` | `intro hp hq`（**一行就行**） |
| 把**目标左边那块**分成**两条路**请进来 | `rintro (hp \| hq)` | `intro h; cases h with \| inl hp => … \| inr hq => …` |
| 拆**假设 `h`**（不分支） | `rcases h with ⟨hp, hq⟩` | `cases h with \| intro hp hq => …` |
| 拆**假设 `h`**、分两支 | `rcases h with hp \| hq` | `cases h with \| inl hp => … \| inr hq => …` |
| 把**假设 `h`** 拆**好几层**（一次到底） | `rcases h with ⟨w, hp, hq⟩` | 拆两层，第二层再 `cases` |
| **分支里要写多行**、或**一次把好几个表达式都分开** | **tactic 版 `match`** | （做不到） |
| **假设之间**有矛盾 | `contradiction` | `False.elim (hnp hp)`／`absurd h hnp` |

⚠️ 一句话：**短写法不是「另一种数学」，只是同一件事写得更短**——两种写法做完之后的状态是一样的。

## §9 一页速查

| 写法 | **被操作的对象** → 做了什么 |
|---|---|
| `rintro 模式…` | 对象：**目标左边那块**。请进来**并**按模式拆它；⚠️ 与 `intro` 的差别**只有交替模式**——`(hp \| hq)`（含 `⟨hp, hq \| hr⟩`）**只有它**能写；`⟨hp, hq⟩`／多个名字／`intro \| Or.inl hp => …` 分支 **`intro` 都会**（§2.4） |
| `rcases h with 模式` | 对象：**假设 `h`**。一步拆开它：`⟨hp, hq⟩`（`∧`）、`hp \| hq`（`∨`，两个目标，**无括号**）、`⟨w, hp, hq⟩`（**一次拆到底**）；⚠️ 与 `cases` 的差别在**写法**（一行／无分支体／自选名字），见 §3.4 |
| `match e₁, e₂ with \| 构造子全名 … => tactic…` | 对象：**你点名的那几个表达式**（`e₁`／`e₂`）。按构造子把它们分开；分支 = **tactic 序列**（可多行）；⚠️ 模式要**构造子全名**（`Or.inl`），漏分支报 `Missing cases` |
| `contradiction` | 对象：**假设之间**的矛盾。找到就把**当前目标**交掉；**找不到就报错**（不瞎猜） |
| 标签／模式对照 | `cases … with` 写**短名**（`inl`／`intro`）；`match` 写**全名**（`Or.inl`／`And.intro`）；`rintro`／`rcases` 写 `⟨…⟩`／`(… \| …)` |
