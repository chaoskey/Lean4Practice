> **原文链接**（想深挖时再看，**不是**理解本课的前提）：
> <https://lean-lang.org/theorem_proving_in_lean4/Tactics/>
>
> **本课范围**：原文 **5.2 Basic Tactics 的后半**（`revert`／`generalize`／`rename_i`／`unhygienic`／`repeat`）。
>
> **本课一句话**：05-2 的 `intro` 把目标里的东西**请进假设**；本课这五个 tactic 都在**目标与假设之间搬东西**——
> `revert` 搬回去、`generalize` 把一整块换成变量、`rename_i`／`unhygienic` 管名字、`repeat` 把同一件事连着做几遍。
>
> ⚠️ **仍然只引入这 5 个 tactic**；`repeat'`／`all_goals`／`;`／`<;>`／`case`／`·` 等**都不在本课**（§7 有归属表）。

## §1 上一课留下的缺口

05-2 学的是「**把目标拆开**」：目标是 `p → q` 或 `∀ x, …` 时，`intro` 把箭头左边的东西**请进假设**。
可真做起证明来，还会碰到五件「假设和目标之间还得来回搬」的事：

| # | 碰到的情况 | 谁管 |
|---|---|---|
| 1 | 假设已经在手上，却想让它**回到目标里**（好让目标和手上某个函数对上） | `revert` |
| 2 | 目标里有个**大表达式**，想让一整块变成一个变量 | `generalize` |
| 3 | `intros` 自动起的 `✝` 名字**引用不到**，想给它改名 | `rename_i` |
| 4 | 干脆一开始就**别**让名字变成 `✝` | `unhygienic` |
| 5 | 同一件事要**重复很多遍**（比如一次剥三层箭头） | `repeat` |

这五个都不改变「命题在说什么」，只改变**目标与假设的摆放方式**。

## §2 `revert`：`intro` 的逆操作

Lean 自带源码里给它的说明只有一句（逐字翻译）：

> 「`revert x...` 是 `intro x...` 的**逆操作**：它把给定的假设**搬回目标**。」

（原文：`` `revert x...` is the inverse of `intro x...`: it moves the given hypotheses back into the goal ``）

### §2.1 最小例子（看状态）

**故意不写完**的代码是（只有 `revert`，不写收尾）：

```text
example (p q : Prop) (hp : p) (hq : q) : p := by
  revert hp
```

Lean 报「还有目标没证完」，顺手印出当时的状态（**逐字**）：

```text
error: unsolved goals
p q : Prop
hq : q
⊢ p → p
```

`hp : p` **从假设里消失了**，目标变成 `p → p`——一个**函数类型**。
也就是说：`revert` 把 05-2 的 `intro` **反着做了一遍**。

### §2.2 一次搬多个：顺序与 `intro` 相反

```text
example (p q : Prop) (hp : p) (hq : q) : p := by
  revert hp hq
```

```text
error: unsolved goals
p q : Prop
⊢ p → q → p
```

⚠️ 看顺序：`revert hp hq` 之后目标是 **`p → q → p`**——**列在前面的 `hp` 成了最外层的箭头**。
而 `intro a b` 是**从外往里**剥（先 `a` 后 `b`）。所以两者正好把对方撤销：
`intro hp hq` 之后再来一句 `revert hp hq`，目标就回到最初的样子。

### §2.3 完整例子：搬回去之后，Lean 收尾时会**自动应用**

```lean
example (p q : Prop) (hp : p) (hq : q) (h : p → q → p) : p := by
  revert hp hq
  exact h
```

`revert hp hq` 之后目标是 `p → q → p`，而 `h : p → q → p`——**类型正好对上**，于是 `exact h` 一步收工。

⭐ **它交出的证明项是什么？** `#print` 一查便知（实测）：

```text
theorem exB : ∀ (p q : Prop), p → q → (p → q → p) → p :=
fun p q hp hq h => h hp hq
```

看最后一段：**`h hp hq`**——Lean 把刚退回的那两条假设**自动应用**回 `h` 上了。
所以「`revert hp hq` 之后 `exact h`」等价于「一步写 `exact h hp hq`」。

### §2.4 什么时候真用得上它

- **和 `intro` 互为逆操作**：想把剥开的层重新包起来时用它（§2.1／§2.2 的状态）。
- **更大的用处是给后面的东西铺路**：Lean 源码里 `induction` 的说明写着——若某条假设的类型**依赖**于你要归纳的那个变量，Lean 会先把它 `revert` 掉、归纳完再 `intro` 回来。
  ⚠️ 这里只是告诉你「它后面还有大用」，**本课不引入 `induction`**（那是**第 8 章**）。

## §3 `generalize`：把表达式换成一个变量

源码里的说明（逐字翻译）：

> * `generalize ([h :] e = x),+` 把主目标里**所有** `e` 都换成新假设 `x`。若给了 `h`，则额外引入一条 `h : e = x`。
> * `generalize e = x at h₁ ... hₙ` 还会把 `h₁` … `hₙ` 里的 `e` 也换掉。
> * `generalize e = x at *` 会把**所有地方**的 `e` 都换掉。

### §3.1 带 `h :` 的形式（看状态）

```text
example (n m : Nat) (h : n = m) : n + 0 = m := by
  generalize hk : n + 0 = k
```

```text
error: unsolved goals
n m : Nat
h : n = m
k : Nat
hk : n + 0 = k
⊢ k = m
```

一次做了两件事：**多出一个变量 `k : Nat`**、**多出一条假设 `hk : n + 0 = k`**，
而目标里的 `n + 0` **被换成了 `k`**（目标从 `n + 0 = m` 变成 `k = m`）。

### §3.2 完整例子

```lean
example (n : Nat) : n + 0 = n := by
  generalize hk : n + 0 = k
  exact hk.symm
```

`hk.symm : k = n + 0`，而目标是 `k = n`——`n + 0` 与 `n` **定义相等**（04-3 学过），所以对得上。

### §3.3 ⚠️ 不带 `h :` 的形式：**等式丢了**

```text
example (n : Nat) : n + 0 = n := by
  generalize n + 0 = k
```

```text
error: unsolved goals
n k : Nat
⊢ k = n
```

**没有 `hk` 了**——没有任何一条假设告诉你「`k` 原来是什么」。后果是这一步：

```text
example (n : Nat) : n + 0 = n := by
  generalize n + 0 = k
  rfl
```

```text
error: Tactic `rfl` failed: The left-hand side
  k
is not definitionally equal to the right-hand side
  n

n k : Nat
⊢ k = n
```

`k` **不是** `n + 0` 的缩写——它是**不透明**的，`rfl` 对不上。
（**带了 `h :` 也救不了**：`k` 同样是不透明的——实测 `have h' : n + 0 = k := rfl` 会报
`Type mismatch`，所以那条 `hk : n + 0 = k` 是一条**真正的假设**，要显式用它。）
→ **结论：想留后路就写 `h :` 那个形式。**

### §3.4 `at h`：连假设里的 `e` 一起换

```lean
example (a b : Nat) (h : a + 0 = b) : a = b := by
  generalize hk : a + 0 = k at h
  exact Eq.trans hk h
```

`at h` 让 `h : a + 0 = b` 也变成 `h : k = b`，于是 `Eq.trans hk h`（`hk : a + 0 = k`，`h : k = b`）给出 `a = b`。
（`at *` 是同一族写法，意思是「所有地方都换」——本课不展开。）

## §4 `rename_i`：给 `intros` 起的名字改名

源码里的说明（逐字翻译）：

> 「`rename_i x_1 ... x_n` 把**最后** `n` 个不可及的名字改成给定的名字。」

### §4.1 两个名字：谁是谁

```text
example (p q : Prop) : p → q → p := by
  intros
  rename_i hp hq
```

```text
error: unsolved goals
p q : Prop
hp : p
hq : q
⊢ p
```

`hp : p`、`hq : q`——**名字按假设列表的先后顺序一一对上**（不是倒着给）。

### §4.2 只给一个名字：只改**最后**那一个

```lean
example (p q : Prop) : p → q → q := by
  intros
  rename_i hq
  exact hq
```

两条前提里，只有**最后**那条（`q`）被改名成 `hq`，于是 `exact hq` 能用了。

### §4.3 名字给多了（实测报错）

```text
example (p : Prop) : p → p := by
  intros
  rename_i hp hq
```

```text
error: too many variable names provided
error: unsolved goals
p : Prop
hq : p
⊢ p
```

只有**一条**不可及的名字，却给了两个——报 `too many variable names provided`。
⚠️ 注意后半段：那条假设**还是被套上了最后一个名字 `hq`**（报错归报错，名字已经改了）。

### §4.4 ⚠️ 它只管**不可及**的名字

```text
example (p q : Prop) (hp : p) (hq : q) : p := by
  rename_i x y
```

```text
error: too many variable names provided
error: unsolved goals
p q : Prop
hp : p
hq : q
⊢ p
```

`hp`、`hq` 是**声明里写出来的**参数，本来就能引用——`rename_i` **不动它们**，
于是「一个可改的都没有」= 又是那条 `too many variable names provided`。

## §5 `unhygienic`：一开始就别起 `✝` 名字

源码里的说明（逐字翻译）：

> 「`unhygienic tacs` 让 `tacs` 在**关闭名字卫生**（name hygiene）的情况下运行。
> 这意味着：本来会起**不可及**名字的那些 tactic，会改成起**普通变量**。
> **⚠️ 警告**：tactic 随时可能改变它们的取名策略，所以**依赖自动生成的名字是脆的**。
> **能不用 `unhygienic` 就别用。**」

### §5.1 `intros` 默认起的名字长什么样

```text
example : ∀ x : Nat, x = x := by
  intro
```

```text
error: unsolved goals
x✝ : Nat
⊢ x✝ = x✝
```

名字是 **`x✝`**——带 `✝` 的就是**引用不到**的名字（05-2 §3 讲过）。

### §5.2 于是直接写 `x` 会报错（实测）

```text
example : ∀ x : Nat, x = x := by
  intro
  exact Eq.refl x
```

```text
error(lean.unknownIdentifier): Unknown identifier `x`
```

### §5.3 打开 `unhygienic` 就好了

```lean
example : ∀ x : Nat, x = x := by
  unhygienic intro
  exact Eq.refl x
```

（这条写法就是 Lean 源码文档里的原例，改动只有：源码把它分两行写，这里写成一行。）
`unhygienic intro` 里那句 `intro` 起的是**普通名字 `x`**，所以 `exact Eq.refl x` 认得它。

### §5.4 ⚠️ 源码自己劝你别用

记住源码那两句警告：**靠自动生成的名字是脆的**，而且 `unhygienic` 会把这个「脆」显式写进你的证明里。
**本项目的建议**：想用名字，**首选 §4 的 `rename_i`**（它只改那几条不可及的名字，其余一切照旧）；
`unhygienic` 知道有这么个东西、能看懂别人的代码就够了。

## §6 `repeat`：一直做，直到做不动

源码文档里的话（逐字翻译）：

> 「`repeat tac` 反复应用 `tac`，只要它还成功。
> `tac` 可以是一串 tactic；若 `tac` 在某一步失败，`repeat` 会把 `tac` 造成的**部分改动撤销**。
> **`tac` 最终必须失败**，否则 `repeat tac` 会**无限跑下去**。」

### §6.1 最小例子（看状态 + 完整证明）

```text
example (p q r : Prop) : p → q → r → p := by
  repeat intro
```

```text
error: unsolved goals
p q r : Prop
a✝² : p
a✝¹ : q
a✝ : r
⊢ p
```

三层箭头**一次剥光**——`repeat intro` 干的就是「`intro` 一遍不够？那就再来一遍」。

补上收尾就是完整证明：

```lean
example (p q r : Prop) : p → q → r → p := by
  repeat intro
  assumption
```

### §6.2 它到底是「怎么重复」的——**一轮只处理一个目标**

源码的实现（`Lean/Elab/Tactic/Repeat.lean`，逐字）是：

```text
while true do
    try
      evalTactic tac
    catch _ =>
      break
```

也就是「**执行一次 `tac`；失败就停**」，然后**再来一轮**。
而「执行一次 tactic」的规矩你其实**早就用过**了：**普通写法的一行只处理当时目标列表里的第一个**。
实测证据（05-2 题 2 那种情形）：

```text
example (p q : Prop) (hp : p) (hq : q) : p ∧ q := by
  apply And.intro
  exact hp
```

```text
error: unsolved goals
case right
p q : Prop
hp : p
hq : q
⊢ q
```

`apply And.intro` 造出**两个**子目标；`exact hp` 只交掉了**第一个**（`p`），第二个 `q` 原地留着。
（顺带记住：子目标多的时候 Lean 会打上 `case left`／`case right` 这种**标签**；
本课不要求你会用它，聚焦与分派是 **05-9** 的事。）

明白这一点，`repeat` 的两个表现就都通了：

1. **第一个目标做掉之后，下一轮就轮到第二个**——所以它能顺次把能做的目标都做掉：

```lean
example (p q : Prop) (hp : p) (hq : q) : p ∧ q := by
  apply And.intro
  repeat assumption
```

（`assumption` 第一轮交掉 `p`，第二轮交掉 `q`，第三轮没有目标可做了就停。）

2. **但卡在做不动的目标上就停，不会跳过去救后面的**：

```text
example (p q : Prop) (hq : q) : p ∧ q := by
  apply And.intro
  repeat assumption
```

```text
error: unsolved goals
case left
p q : Prop
hq : q
⊢ p

case right
p q : Prop
hq : q
⊢ q
```

`assumption` **第一轮就失败**（假设里没有 `p` 的证明），`repeat` 立刻停手——两个目标都还在。

### §6.3 失败**不报错**（这一点和裸 `intro` 不同）

```lean
example (p : Prop) (hp : p) : p := by
  repeat intro
  exact hp
```

目标 `p` 上根本没有箭头，`intro` 会失败——但 `repeat` **吞掉**这个失败直接收场，
所以这几行照样通过（对照 05-2 §2.4：裸写 `intro` 是要报
`Tactic 'introN' failed` 的）。

### §6.4 ⚠️ 别让它停不下来

回到源码那句：**`tac` 最终必须失败**。
`repeat` 只在「某一轮失败」时停——要是你给的 tactic **一直成功却什么都不改**，
这个 `while true` 就**永远转下去**（Lean 会一直跑）。所以：

- 用 `repeat` 时，心里要清楚「**它靠什么失败停下来**」（像 `intro`：箭头剥光了就失败）。
- 拿不准的东西**不要**直接丢给 `repeat` 试。

## §9 一页速查

| 写法 | 意思 |
|---|---|
| `revert h` | 把假设 `h` **搬回目标**（`intro` 的逆操作）；之后 `exact f` 时 Lean 会把 `h` 自动应用到 `f` 上（＝ `f h`） |
| `revert h₁ h₂` | 一次搬多条；**列在前面的成为最外层箭头**（`revert hp hq` 得到 `p → q → …`） |
| `generalize h : e = x` | 把目标里的 `e` 换成新变量 `x`，并加一条假设 `h : e = x` |
| `generalize e = x` | 也把 `e` 换成 `x`，但**不加那条等式**——`x` 不透明，信息就丢了（§3.3） |
| `generalize h : e = x at h'` | 连假设 `h'` 里的 `e` 一起换 |
| `rename_i 名字…` | 把**最后** n 个不可及的名字改掉；名字按假设列表顺序对上 |
| `unhygienic 一串tactic` | 让这些 tactic 起**普通名字**（源码劝你别依赖它；本项目首选 `rename_i`） |
| `repeat t` | 反复执行 `t`，**一轮一个目标**，直到某一轮失败就停（失败不报错；**别给它停不下来的 `t`**） |
