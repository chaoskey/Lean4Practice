## §1 上一课留下的缺口

05-1 学了两件事：

| tactic | 干什么 |
|---|---|
| `exact e` | 交出一个项 `e`，要求它的类型**就是**目标 |
| `apply e` | 交出一个项 `e`，它**还缺的参数**按顺序变成新目标 |

这两个都是「**我手上有个东西，交出去**」。可要是目标本身就长成

```text
p → q → p
```

（一个**函数类型**）呢？你手上并没有现成的 `p → q → p`。
`exact` 要求你**整条**交出来（比如 `fun hp _ => hp`），`apply` 也对不上（它要找一个「结论是 `p → q → p`」的东西）。

**`intro` 就是干这个的**：目标是函数类型时，它把**箭头左边**的东西**请进假设列表**，叫你先把这一层剥掉。

---

## §2 `intro`：把目标里的东西请进假设

**规则**：当前目标形如 `∀ x : α, β x`（或 `p → q`——见 §2.2，这两者是同一个东西）时，

```text
intro 名字
```

会把 `x`（或 `p` 的证明）**加进假设**，并把目标换成右边那部分。

### §2.1 最小例子

```lean
example (α : Type) : α → α := by
  intro a
  exact a
```

- `intro a` 之后，`a : α` 进入假设，目标从 `α → α` 变成 `α`；
- 于是 `exact a` 就能交差。

> ⚠️ **为什么这里是 `example` 而不是 `theorem`？** 因为 **`theorem` 的语句必须是 `Prop`**，
> 而 `α → α` 是一个 **`Type`**（03-2 见过这条限制：写成 `theorem` 会报
> `type of theorem '…' is not a proposition`）。凡是「语句不是命题」的练习，本课程都用 `example`。

### §2.2 `∀` 和 `→` 是同一个操作

04-1 的第一句话就是：**`p → q` 其实就是 `∀ _ : p, q`**——两者都是函数类型。
所以 `intro` 对它们**没有区别**：

```lean
example (α : Type) : ∀ x : α, x = x := by
  intro x
  exact Eq.refl x
```

`∀ x : α, x = x` 经过 `intro x`，目标变成 `x = x`，假设多了 `x : α`。

### §2.3 一次引入多个（**从外往里**剥）

```lean
theorem exB : ∀ a b c : Nat, a = b → a = c → c = b := by
  intro a b c h₁ h₂
  exact Eq.trans (Eq.symm h₂) h₁
```

`∀ a b c : Nat, a = b → a = c → c = b` 展开成嵌套的函数类型：

```text
(a : Nat) → (b : Nat) → (c : Nat) → a = b → a = c → c = b
```

`intro a b c h₁ h₂` 就是**从左往右**一个接一个剥：先 `a`、再 `b`、再 `c`、再两个等式前提。
所以 **`intro` 里名字的顺序，就是它们在目标里出现的顺序**。

### §2.4 `intro` 只能用在函数类型的目标上

目标不是函数类型（没有箭头、没有 `∀`）时写 `intro`，实测报错（**逐字**）：

```text
error: Tactic `introN` failed: There are no additional binders or `let` bindings in the goal to introduce
```

（这条报错**后面还会附上当前目标**；`introN` 是 Lean 内部对 `intro` 的称呼，看到它别慌。）

## §3 `intros`：不带参数，让 Lean 自己起名

`intros`（**多了个 s**）不写参数：把**能剥的都剥开**，名字由 Lean 自己起。

实测——把目标 `∀ a b c : Nat, a = b → a = c → c = b` 一直剥到底（故意停住），Lean 打出的假设是：

```text
a✝² b✝ c✝ : Nat
a✝¹ : a✝² = b✝
a✝ : a✝² = c✝
⊢ c✝ = b✝
```

**⚠️ 那些带 `✝` 的名字，你引用不到**（这是刻意的设计）。实测——写 `exact a✝¹` 会报：

```text
error(lean.unknownIdentifier): Unknown identifier `a`
error: expected token
```

（第二条 `expected token` 是因为 `✝` 根本不是一个合法的名字字符。）

**那 `intros` 有什么用？** 当你**不需要点名**、只想把前面几层一次剥光的时候。
配合 `assumption` 特别顺手（§4）：`assumption` 是**按类型**去假设列表里找，不需要名字。

---

## §4 `assumption`：在假设里找现成的

**规则**：在当前假设列表里找一条**类型正是当前目标**的，用它交差。找不到就失败。

### §4.1 例子（原文那条传递性链）

```lean
example (x y z w : Nat) (h₁ : x = y) (h₂ : y = z) (h₃ : z = w) : x = w := by
  apply Eq.trans h₁
  apply Eq.trans h₂
  assumption
```

逐步看（都用得上 04-3 学的 `Eq.trans`）：

| 行 | 当前目标 | 说明 |
|---|---|---|
| 起始 | `x = w` | |
| `apply Eq.trans h₁` | `y = w` | `Eq.trans : a = b → b = c → a = c`；喂 `h₁ : x = y` 后，还缺 `y = c`，与 `x = w` 对上 → `c := w` |
| `apply Eq.trans h₂` | `z = w` | 与上一行同一个用法，只是这回喂的是 `h₂ : y = z`：喂进去后还缺 `z = c`，与目标 `y = w` 对上 → `c := w` |
| `assumption` | 无 | 在假设里找到 `h₃ : z = w`——类型**正是**目标 → 收工 |

### §4.2 `intros` + `assumption`：全程不起名字

```lean
theorem exC (p q : Prop) : p → q → p ∧ q → p := by
  intros
  assumption
```

`intros` 把 `p q` 和三个前提全剥进假设（名字全是 `✝` 那种，引用不到），
`assumption` **按类型**找到了 `p` 的那条前提，一步收工。

### §4.3 `assumption` 认「定义相等」（实测）

```lean
example (n : Nat) (h : n + 0 = n) : n = n := by
  assumption
```

`n + 0` 与 `n` **定义相等**（04-3 学过），所以 `h` 的类型虽然字面写的是 `n + 0 = n`，
`assumption` 照样拿它交 `n = n` 这个目标（**反方向也测了，同样通过**）。

### §4.4 找不到时的报错（实测）

```text
error: Tactic `assumption` failed

p q : Prop
hp : p
hq : q
⊢ p ∧ q
```

注意：假设里只有 `hp : p` 和 `hq : q`，**没有**一条的类型是 `p ∧ q`——`assumption` 不会替你
用 `And.intro` 去**造**一个（那是 `apply`／`exact` 的活）。

## §5 `rfl`：两边定义相等时一步收工

**规则**：目标是 `a = b`，且 `a` 与 `b` **定义相等**（算一算能对上，04-3 学过）时，`rfl` 直接收工。

```lean
theorem exE (n : Nat) : n + 0 = n := by
  rfl
```

`rfl` 就是 04-3 那个 **`rfl` 项**（`Eq.refl`）。看它生成的项（实测）：

```text
theorem exE : ∀ (n : Nat), n + 0 = n :=
fun n => Eq.refl (n + 0)
```

注意 Lean 填的是 `Eq.refl (n + 0)`——它的类型是 `n + 0 = n + 0`，而 `n + 0` 与 `n` 定义相等，
所以这就是目标 `n + 0 = n` 的证明。

## §6 再看 `#print`：tactic 证明还是一串 `fun`

本课最该记住的第二件事（05-1 讲过一半）：**`intro` 就是「交互式地写 `fun`」**。
下面两条实测输出**逐字相同**：

```lean
theorem exF_term : ∀ x : Nat, x = x := fun x => Eq.refl x
theorem exF_tactic : ∀ x : Nat, x = x := by
  intro x
  exact Eq.refl x
```

```text
theorem exF_term : ∀ (x : Nat), x = x :=
fun x => Eq.refl x
theorem exF_tactic : ∀ (x : Nat), x = x :=
fun x => Eq.refl x
```

所以：**`intro` = 写一层 `fun`**；`exact` = 写函数体。第 4 章那套「`∀` 的目标就写 `fun`」
在这里有了 tactic 版本。

## §9 一页速查

| 写法 | 意思 |
|---|---|
| `intro x` | 目标形如 `∀ x : α, …` 或 `p → …` 时：把 `x`（或前提）加进假设，剥掉一层 |
| `intro a b c h₁ h₂` | 一次剥多个，**从外往里**（＝名字在目标里出现的顺序） |
| `intros` | 不写名字，自动剥；**名字带 `✝`、引用不到** |
| `assumption` | 在假设里找一条**类型就是目标**的，用它交差（认定义相等；**不会**替你构造） |
| `rfl` | 目标是 `a = b` 且两边**定义相等**时收工（＝ 04-3 的 `rfl` 项） |
| `intro` = 写 `fun` | `#print` 一查便知（§6） |
