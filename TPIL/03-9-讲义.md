## 3. 原文那张清单：命题有效性

原文 3.6 一开头列了一张**命题逻辑恒等式**的表，并说了一句话，大意是：

> **Lean 的标准库里已经有这些命题的证明了，你在自己的证明里可以随便用。**

原文按四组列出（**下面照抄原文的命题，只是排了版**）。

### 3.1 交换律

```
p ∧ q ↔ q ∧ p  -- 交换律（∧）｜and_comm
p ∨ q ↔ q ∨ p  -- 交换律（∨）｜or_comm
```

### 3.2 结合律

```
(p ∧ q) ∧ r ↔ p ∧ (q ∧ r)  -- 结合律（∧）｜and_assoc
(p ∨ q) ∨ r ↔ p ∨ (q ∨ r)  -- 结合律（∨）｜or_assoc
```

### 3.3 分配律

```
p ∧ (q ∨ r) ↔ (p ∧ q) ∨ (p ∧ r)  -- 分配律（∧ 对 ∨）｜and_or_left
p ∨ (q ∧ r) ↔ (p ∨ q) ∧ (p ∨ r)  -- 分配律（∨ 对 ∧）｜or_and_left
```

### 3.4 其它性质

```
(p → (q → r)) ↔ (p ∧ q → r)  -- 输出律（柯里化）｜and_imp.symm
((p ∨ q) → r) ↔ (p → r) ∧ (q → r)  -- 分配律（析取当前提）｜or_imp
¬(p ∨ q) ↔ ¬p ∧ ¬q  -- 德摩根律（∨）｜not_or
¬p ∨ ¬q → ¬(p ∧ q)  -- 德摩根律（∧，一个方向）｜not_and_of_not_or_not
¬(p ∧ ¬p)  -- 不矛盾律｜and_not_self
p ∧ ¬q → ¬(p → q)  -- 否定蕴含律（一个方向）｜not_imp_of_and_not
¬p → (p → q)  -- 虚真（前提为假）｜无现成名字，用 `absurd`
(¬p ∨ q) → (p → q)  -- 实质蕴含（一个方向）｜Decidable.imp_iff_not_or.mpr
p ∨ False ↔ p  -- 单位律（∨）｜or_false（类型是 `=`，用 `Iff.of_eq` 转）
p ∧ False ↔ False  -- 支配律（∧）｜and_false（类型是 `=`，用 `Iff.of_eq` 转）
¬(p ↔ ¬p)  -- ⬜ 无通行名字｜iff_not_self
(p → q) → (¬q → ¬p)  -- 假言易位（逆否，一个方向）｜mt
```

### 3.5 原文说「这些需要经典推理」的一组

⚠️ 这一组的名字都带 `Decidable.` 或 `Classical.` —— **用之前要先 `open Classical`**。

```
(p → r ∨ s) → ((p → r) ∨ (p → s))  -- 分配律（析取当结论）｜Decidable.imp_or.mp
¬(p ∧ q) → ¬p ∨ ¬q  -- 德摩根律（∧，另一个方向）｜Decidable.not_and_iff_not_or_not.mp
¬(p → q) → p ∧ ¬q  -- 否定蕴含律（另一个方向）｜Decidable.not_imp_iff_and_not.mp
(p → q) → (¬p ∨ q)  -- 实质蕴含（另一个方向）｜Decidable.imp_iff_not_or.mp
(¬q → ¬p) → (p → q)  -- 假言易位（另一个方向）｜Decidable.not_imp_not.mp
p ∨ ¬p  -- 排中律｜Classical.em
(((p → q) → p) → p)  -- 皮尔士定律｜Decidable.peirce
```

> ### 📌 这张清单和你的关系
>
> **它是 3-10（下一课）的题库。** 下一课你会从里面挑一批自己动手证。
>
> **本课只用它做两件事**：
> 1. **看清楚「有效命题」长什么样**——你会发现自己已经能读懂全部符号了；
> 2. **明确「哪些需要经典」这件事必须靠 `#print axioms` 查**，**不能靠感觉**（§8 给表）。
>
> ⚠️ **本课绝不对清单里我没实测过的条目下判断。** 哪几条实测过、结论是什么，§8 的表里写得很清楚。

### 3.6 备注：怎么查「库里到底有没有现成的名字」

上面那些名字，是我**猜 + 翻 Lean 源码**找出来的。你以后可以更省事——**让 Lean 自己报**：

```lean
example (p q r : Prop) : p ∨ (q ∧ r) ↔ (p ∨ q) ∧ (p ∨ r) := by
  exact?          -- Lean 会报：Try this:  [apply] exact or_and_left
```

⚠️ **两件必须记住的事**：

1. **`exact?`（还有 `apply?`）是 tactic 写法（`by`），属于第 5 章**——本课**不要求会用**，知道有这件武器就行。
2. **`exact?` 说「关不掉」≠「命题不成立」**——它只说明**库里没有现成的项**。
   实测：一条**真的、但库里没有**的命题，和一条**假的**命题，它给的回答**一模一样**（都是 `could not close the goal`）。
   → **它是一本「目录」，不是「判定器」。**

## 4. 新工具一：`sorry` —— 脚手架，不是答案

### 4.1 它是什么

`sorry` 是 Lean 里的一个特殊记号：**它可以是任何命题的「证明」**，也可以是任何类型的「值」。

```
-- ⚠️ 下面这段**故意**用了 sorry，只为演示。
--    它会编译通过，但 Lean 会报一条警告：declaration uses `sorry`
theorem scaffold (p q : Prop) : p → q :=
  sorry
```

**关键事实（这一点必须记住）**：

| 事实 | 说明 |
|---|---|
| ✅ **`sorry` 让文件能编译** | 所以你可以**先把框架搭起来** |
| ⚠️ **但它不是证明** | 它只是「假装这里有证明」 |
| ⚠️ **Lean 会警告** | `warning: declaration uses 'sorry'` |
| 🔴 **它会让定理依赖一个叫 `sorryAx` 的公理** | 这是**最要紧**的一点 |

### 4.2 `sorryAx`：用 3-8 的工具照出它

3-8 你学过 `#print axioms`——**本课正好用它来「照」`sorry`**：

```lean
theorem scaffold (p q : Prop) : p → q :=
  sorry
#print axioms scaffold
```

```
'scaffold' depends on axioms: [sorryAx]
```

> ## 🔴 对照 3-8 的三个结论一起看
>
> | 定理 | `#print axioms` 说什么 |
> |---|---|
> | 构造性定理（如 `¬(p ∨ q) → ¬p ∧ ¬q`） | `does not depend on any axioms` |
> | 用了经典的定理 | `[propext, choice, Quot.sound]` |
> | **用了 `sorry` 的定理** | **`[sorryAx]`** ← **它根本不是证明** |
>
> `sorryAx` 的意思是「**假设这个命题成立**」。
> 所以一个只靠 `sorry` 撑起来的定理，**等于没有证**。

### 4.3 那它有什么用：**自顶向下写长证明**

`sorry` 的正确用法是**工作方法**，不是**交付内容**：

```
第 1 步：先把整个证明的骨架写出来，每个还没想好的地方填 sorry
        → 让 Lean 检查：**骨架的类型对不对、分支漏没漏**
第 2 步：把最外层的 sorry 换成真正的证明，里面继续留 sorry
        → 每次只攻一个洞
第 3 步：重复，直到 **一处 sorry 都没有**
```

**为什么这样更快**：你不用一次想清楚整条证明链——**先确认「形状对了」，再逐个填洞**。

> ### ⚠️ 本项目的验收规则（务必记住）
>
> **交出来的 `.lean` 文件里，一处 `sorry` 都不能留。**
> 验收脚本会检查，而且 `sorry` 会让 `#print axioms` 显示 `[sorryAx]`。
>
> **一句话：`sorry` 可以随便用，但必须在交之前全部拆掉。**
> 就像脚手架——盖楼时随便搭，**交房时不能留在墙里**。

## 5. 新工具二：`_` —— 让 Lean 告诉你「它要什么」

### 5.1 `_` 是什么

`_` 是**占位符**：你写一个下划线，意思是「**这里有一个洞，内容我不写，你自己找**」。

你在 **2-10** 已经见过它——那时它用在**隐式参数**的位置，Lean 会从上下文里把参数**推**出来。

### 5.2 ⚠️ 但在**证明**里，`_` 几乎总是**失败**

这是**实测**的，不是推测。下面四行都是**真的会报错**的写法：

```
-- ⚠️ 下面四行**故意**写错（都会报 don't know how to synthesize placeholder）
example (p : Prop) (h : p) : p := _
example (p : Prop) (h : p) : p ∧ p := ⟨_, _⟩
example (p : Prop) : p → p := fun h => _
example (p : Prop) : p → p := _
```

报错长这样：

```
error: don't know how to synthesize placeholder
```

### 5.3 那**失败**有什么用？——**报错信息本身就是「当前子目标」**

这才是原文推荐 `_` 的原因。`_` 失败时，Lean 会打印**三样东西**：

1. **它期望的类型**（也就是「这个洞要填什么」）；
2. **当时手上有什么**（上下文里的假设）；
3. 有时还会说**是哪个参数**没填上（比如上面的 `for argument 'right'`）。

> ### 📌 一句话总结
> **`_` 不是「让 Lean 帮你证」，而是「让 Lean 告诉你它在等什么」。**
> 它**经常失败**——而**失败信息就是你上一个 `sorry` 想看的东西**，只是**不用真的写 `sorry`**。

### 5.4 `_` 和 `sorry` 的分工

| | `sorry` | `_` |
|---|---|---|
| 编译能过吗 | ✅ 能（有警告） | ❌ 通常不能（直接报错） |
| 环境干不干净 | 会留下 `sorryAx` | **什么也不留下**（因为它压根没过） |
| 什么时候用 | **搭骨架**、分批推进 | **问 Lean「这里要什么」** |

> 💡 **所以：想「先跑起来」用 `sorry`；想「看清目标」用 `_`。**
> 两者的共同点是——**都不该出现在最终交付物里**。

## 6. 样板一（逐段拆解）：分配律 —— **不需要**经典

原文给的两个样板之一。目标：

```
p ∧ (q ∨ r) ↔ (p ∧ q) ∨ (p ∧ r)  -- 分配律（∧ 对 ∨）｜and_or_left
```

### 6.1 先看**整体形状**（不要急着写细节）

它是 `↔`，所以**整体用 `Iff.intro`**，交**两个方向**：

```
Iff.intro
  (…)   -- 方向一：p ∧ (q ∨ r)  →  (p ∧ q) ∨ (p ∧ r)
  (…)   -- 方向二：(p ∧ q) ∨ (p ∧ r)  →  p ∧ (q ∨ r)
```

### 6.2 方向一：`p ∧ (q ∨ r) → (p ∧ q) ∨ (p ∧ r)`

**逐段读**（这是 §6.40 要求的：不能只给最终结果）：

| 步骤 | 写上什么 | 为什么 |
|---|---|---|
| 1 | `fun h : p ∧ (q ∨ r) =>` | 目标是一个**函数类型**（`→`），所以用 `fun` 把前提拿进来 |
| 2 | `have hp : p := h.left` | 前提是个**合取**：左边是 `p`，**起个名字**免得反复写 |
| 3 | 现在目标变成 `(p ∧ q) ∨ (p ∧ r)`，而 `h.right : q ∨ r` | 手上有**析取** → 要**分情况** |
| 4 | `Or.elim h.right (…) (…)` | 交两个分支：`q` 成立的支、`r` 成立的支 |
| 5 | `fun hq : q => Or.inl ⟨hp, hq⟩` | 有 `q` → 造出 `p ∧ q`（左边）；目标是析取 → 用 `Or.inl` |
| 6 | `fun hr : r => Or.inr ⟨hp, hr⟩` | 有 `r` → 造出 `p ∧ r`（右边）；目标是析取 → 用 `Or.inr` |

⚠️ **第 5、6 步最容易搞反**（§6.36 的老坑）：目标是 `(p ∧ q) ∨ (p ∧ r)`，
所以「用 `q` 的那一支」要交出**左边** `p ∧ q` → 用 **`Or.inl`**；
「用 `r` 的那一支」要交出**右边** `p ∧ r` → 用 **`Or.inr`**。

### 6.3 方向二：`(p ∧ q) ∨ (p ∧ r) → p ∧ (q ∨ r)`

| 步骤 | 写上什么 | 为什么 |
|---|---|---|
| 1 | `fun h : (p ∧ q) ∨ (p ∧ r) =>` | 这一层的目标整体是 `→`，所以要用 `fun` 把前提**拿进手里**（和 §6.2 第 1 步用 `fun` 的理由**是同一条**：目标是个函数类型） |
| 2 | 前提是**析取** → `Or.elim h (…) (…)` | 手上有析取 → 必须**分两支**，每支各写一个函数 |
| 3 | 左支 `fun hpq : p ∧ q =>` | 手上是合取 → 用 `.left` / `.right` 拆成 `hp : p`、`hq : q` |
| 4 | 目标是 `p ∧ (q ∨ r)`，形状是**合取** → `⟨hp, Or.inl hq⟩` | `hp : p` 交给合取的**左边**；`hq : q` 要造出 `q ∨ r`——`q` 是 `q ∨ r` 的**左边**，所以用 **`Or.inl`** |
| 5 | 右支 `fun hpr : p ∧ r => ⟨hp, Or.inr hr⟩` | `hp : p` 交给合取的**左边**；`hr : r` 要造出 `q ∨ r`——`r` 是 `q ∨ r` 的**右边**，所以用 **`Or.inr`** |

### 6.4 完整代码（**已实测通过，零公理**）

```lean
theorem distrib (p q r : Prop) : p ∧ (q ∨ r) ↔ (p ∧ q) ∨ (p ∧ r) :=
  Iff.intro
    (fun h : p ∧ (q ∨ r) =>
      have hp : p := h.left
      Or.elim h.right
        (fun hq : q => show (p ∧ q) ∨ (p ∧ r) from Or.inl ⟨hp, hq⟩)
        (fun hr : r => show (p ∧ q) ∨ (p ∧ r) from Or.inr ⟨hp, hr⟩))
    (fun h : (p ∧ q) ∨ (p ∧ r) =>
      Or.elim h
        (fun hpq : p ∧ q =>
          have hp : p := hpq.left
          have hq : q := hpq.right
          show p ∧ (q ∨ r) from ⟨hp, Or.inl hq⟩)
        (fun hpr : p ∧ r =>
          have hp : p := hpr.left
          have hr : r := hpr.right
          show p ∧ (q ∨ r) from ⟨hp, Or.inr hr⟩))
```

**它用没用经典？** 实测：

```
#print axioms distrib
→ 'distrib' does not depend on any axioms
```

**怎么读这句话**：`does not depend on any axioms` 意思是「**证明里没有用到任何假设性的东西**」——
既没用 `em`，也没用 `sorry`。**这是「构造性证明」的机械判据**（3-8 §6.41 的第②层证据）。

## 7. 样板二（逐段拆解）：实质蕴含 `¬(p ∧ ¬q) → (p → q)` —— **需要**经典

原文给的第二个样板，专门示范**经典推理**。目标：

```
¬(p ∧ ¬q) → (p → q)  -- 实质蕴含｜Decidable.not_and_not_right.mp
```

### 7.1 先看**整体形状**

目标是**两层函数**：`¬(p ∧ ¬q)` 是前提，`p → q` 是结论。所以整体是：

```
fun h : ¬(p ∧ ¬q) =>      -- 第一层：拿假设 h
fun hp : p =>             -- 第二层：拿假设 hp
show q from …             -- 现在目标只剩 q
```

### 7.2 难点在哪：**从这里到 `q`，一步都走不动**

手上有什么？

- `h : ¬(p ∧ ¬q)`——即 `p ∧ ¬q → False`
- `hp : p`

⚠️ **注意 `h` 要的是 `p ∧ ¬q`，而我们只有 `p`**——**缺一个 `¬q`**。
而 `¬q` 是「`q` 不成立」——**我们既证不出 `q`，也证不出 `¬q`**。

> **这就是「需要经典」的地方**：`q` 到底成不成立，手上的材料**一样都不给**。

### 7.3 所以：**先用 `em q` 把 `q` 的真假拿到手**

```
Or.elim (em q) (…) (…)
```

**两支分别是**：

| 支 | 手上得到 | 怎么写 |
|---|---|---|
| 左支 | `hq : q` | **目标就是 `q`** → 直接把 `hq` 交出去 |
| 右支 | `hnq : ¬q` | 现在能凑出 `p ∧ ¬q`（`hp` 配 `hnq`），**喂给 `h`** → 得到 `False` → 从 `False` 得 `q` |

⚠️ **右支用的就是 3-5 学的 `absurd`**：手上同时有 `p ∧ ¬q` 和它的否定 `h` → 直接得到任何东西。

### 7.4 完整代码（**已实测通过，带经典**）

```lean
open Classical

theorem not_and_not (p q : Prop) : ¬(p ∧ ¬q) → (p → q) :=
  fun h : ¬(p ∧ ¬q) =>
  fun hp : p =>
  show q from
  Or.elim (em q)
    (fun hq : q => hq)
    (fun hnq : ¬q => absurd (And.intro hp hnq) h)
```

**它用没用经典？** 实测：

```
#print axioms not_and_not
→ 'not_and_not' depends on axioms: [propext, choice, Quot.sound]
```

⚠️ **注意 `open Classical` 的位置**：上面它写在 `not_and_not` **之前**。
如果把 `open Classical` 写在**文件最顶上**，那么**它前面的定理也会「沾上」它**——
**这也是为什么判断「用没用经典」不能看「能不能编译」，只能看 `#print axioms`**（见 §8）。

## 9. 本课**不**引入的东西（别被下面的名字吓到）

| 名字 | 属于哪 | 本课要不要理解 |
|---|---|---|
| `cases` / `apply` / `exact` / `rw` / `simp` | **第 5 章**（tactic） | ❌ 本课全部用**证明项**，一个 tactic 都不用 |
| `∀` / `∃`（量词） | **第 4 章** | ❌ 本课只讲**命题逻辑**，没有量词 |

| `Decidable` / `by decide` / `if` | 后面的章 | ❌ 不引入 |
| 「命题有效性」的**元理论**（可靠性与完备性） | 不属于本书主线 | ❌ 不引入 |

> **本课的「需要经典」判断，只依赖 §8 那张表的 `#print axioms` 输出**——
