## 1. 先分清两个世界：命题 `Prop` 与数据 `Type`

Lean 里「类型」是个大概念，它下面有**两个不同的世界**。先把这两个世界分清，后面才不会乱：

| 世界 | 里面住什么 | 它的「值」叫什么 | 例子 |
|---|---|---|---|
| **`Prop`** | **命题** | **证明** | `2 = 2`、`True` |
| **`Type`** | **数据类型** | **数据** | `Nat`、`Bool` |

**判据**（初学阶段只抓这一条就够）：

> 看一个类型的**值是证明还是数据**。
> 值是证明 → 它是命题；值是数字、布尔值这类东西 → 它是数据。

用 Lean 实测一下。`#check` 的输出格式**一律**是 **`表达式 : 它的类型`**：

```lean
#check Nat            -- Nat : Type       ← 数据类型【不是命题！】
#check 1 + 1          -- 1 + 1 : Nat      ← 数据：Nat 的一个值
#check 2 = 2          -- 2 = 2 : Prop     ← 命题
#check (rfl : 2 = 2)  -- rfl : 2 = 2      ← 证明：命题的一个值
```

**重点看后两行**——这才是本课要讲的东西：

- `2 = 2` 是一个**类型**（准确说，是命题）
- `rfl` 是它的**值**（准确说，是证明）

**前两行只是拿来对照的**：`Nat` 虽然也是「类型」，但它属于**另一个世界**，它的值是数字，不是证明。

> ⚠️ **一个非常常见的误解**：「类型 = 命题」是**错的**。
> 正确的是：**命题都是类型，但不是所有类型都是命题**。命题只是类型里特殊的一小类。
> 所以看到 `Nat : Type` 时，不能推「那 Nat 是个命题」。

> 💡 `#check` **只报类型、不做计算**，所以 `#check 1 + 1` 原样显示 `1 + 1`，不会化成 `2`。
> 想看计算结果要用 `#eval`：
> ```lean
> #eval 1 + 1      -- 2
> ```
> `1 + 1` 和 `2` 是**同一个值的两种写法**。

### 命题这一侧，就是 Curry–Howard 对应

| 逻辑 | 类型（命题世界 `Prop`） |
|---|---|
| 命题 | 类型 |
| 证明 | 项（值） |
| 蕴含 `p → q` | 函数类型 `p → q` |
| 肯定前件（由 `p→q` 与 `p` 得 `q`） | 函数应用 |

记住最后两行，本课的全部内容都是它的推论。

在证明里，`#check` 是你最好的朋友——不确定某个假设的类型时，直接查：

```lean
#check hp        -- hp 到底是什么类型？
```

## 2. 蕴含 `p → q` 的证明，就是写一个函数

`p → q` 读作「如果 p 成立，那么 q 成立」。

**要证明 `p → q`，就是要构造一个函数**：喂给它一个 `p` 的证明，它吐出一个 `q` 的证明。

### 先读懂这一行的结构

```lean
example (p : Prop) : p → p := fun hp => hp
```

从左到右分四段，**每一段都有明确的意思**：

| 段 | 内容 | 意思 |
|---|---|---|
| ① | `example` | 「这里有一个待证的命题」。只是拿来做示范，**不起名字** |
| ② | `(p : Prop)` | 引入一个叫 `p` 的东西，**它的类型是 `Prop`**——也就是：`p` 是一个命题 |
| ③ | `: p → p` | 冒号后面是**要证什么**（目标） |
| ④ | `:= fun hp => hp` | `:=` 后面是**怎么证**（给出一个值） |

第 ② 段的 `Prop` 不是装饰——**它正是把 `p` 声明进「命题世界」的那句话**（见 §1）。少了它，`p` 会被当成某个未知的数据类型。

第 ④ 段里 `fun hp => hp` 的写法也要认识一下：

- `fun 参数 => 结果` 是 Lean 里**写匿名函数**的写法（别的语言里常叫 `lambda` 或箭头函数）。
- 所以 `fun hp => hp` 就是「一个函数：参数叫 `hp`，返回值就是 `hp` 本身」。
- 这正是「证明 `p → p`」该有的样子——**给我一个 `p` 的证明，我原样还给你**。

`theorem` 和 `example` 的区别只有一个：**`theorem` 要起名字**，以后可以引用它。

```lean
theorem my_first (p : Prop) : p → p := fun hp => hp
```

### 项模式（term mode）

```lean
example (p : Prop) : p → p := fun hp => hp
```

上面这一整行**就是完整的证明**，不需要再写别的。它能证明 `p → p`，是因为它正好是一个
「`p` 的证明 ⇒ `p` 的证明」的函数——**证明和函数，在这里是同一件事**。

### 策略模式（tactic mode）

```lean
example (p : Prop) : p → p := by
  intro hp
  exact hp
```

- `intro hp`：把目标的左边（`p`）**搬进假设**并命名为 `hp`，目标随之变成 `q`。
  这正对应「写函数的参数」。
- `exact hp`：宣称「假设里的 `hp` 恰好就是要证的东西」。

> 两种模式**完全等价**。`by ...` 不过是项模式的另一种写法。
> 建议：初学阶段两种都练，看到 `by` 就知道它在构造项。

### 右边的箭头要先处理

注意 `p → q → p` 是 `p → (q → p)`（箭头**右结合**）。
所以 `intro hp` 之后目标变成 `q → p`，还需要再 `intro` 一次：

```lean
example (p q : Prop) : p → q → p := by
  intro hp hq
  exact hp
```

`intro hp hq` 是连续 `intro` 的简写。`hq` 在证明里没被用到——可以用 `_` 表示「我故意不用它」：

```lean
example (p q : Prop) : p → q → p := fun hp _ => hp
```

## 3. 使用一个蕴含：函数应用

反过来，如果手里有 `h : p → q` 和 `hp : p`，那就**调用这个函数**得到 `q`：

```lean
example (p q : Prop) (hp : p) (h : p → q) : q := h hp
```

项模式里它就是普通的函数应用 `h hp`。

策略模式里用 `exact`：

```lean
example (p q : Prop) (hp : p) (h : p → q) : q := by
  exact h hp
```

---

## 4. `apply`：从目标往回推

`exact` 要求你一次给出**完整**的证明项。而 `apply` 允许你**分步**推进：

```lean
example (p q r : Prop) (h1 : p → q) (h2 : q → r) : p → r := by
  intro hp
  apply h2
  apply h1
  exact hp
```

逐步看目标怎么变：

| 步骤 | 目标 | 说明 |
|---|---|---|
| 开始 | `⊢ p → r` | |
| `intro hp` | `⊢ r`，假设含 `hp : p` | 引入前提 |
| `apply h2` | `⊢ q` | `h2 : q → r`，所以「只要证出 `q` 就够了」 |
| `apply h1` | `⊢ p` | `h1 : p → q`，同理退到 `p` |
| `exact hp` | 完成 | `hp` 正是 `p` 的证明 |

**`apply` 的心智模型**：`apply h` 是在说「我的目标可以由 `h` 的结论给出，所以现在只需证 `h` 的前提」。

> 口诀：**`intro` 往目标里拆，`apply` 从目标往回退，`exact` 一击命中。**

## 5. 怎么读 Lean 的报错

Lean 的报错几乎总是「三段式」。看这个错误：

```lean
-- 故意写错：想用 p 的证明去证 q
example (p q : Prop) (hp : p) : q := hp
```

报错是：

```
error: Type mismatch
  hp
has type
  p
but is expected to have type
  q
```

**该看的是后两段**：`has type p` / `is expected to have type q`——
「你给的 `hp` 类型是 `p`，但这里需要 `q`」。

初学阶段 90% 的报错都是这个形状：**类型对不上**。
遇到它，先问自己：我期望这个位置是什么类型？我给的又是什么类型？

另一个高频报错是 `unknown identifier`（名字打错）和
`function expected at ...`（把不是函数的东西当函数用了）。

## 6. 小结

| 想做什么 | 项模式 | 策略模式 |
|---|---|---|
| 证明 `p → q` | `fun hp => ...` | `intro hp` |
| 用 `h : p → q` 和 `hp : p` 得 `q` | `h hp` | `exact h hp` 或 `apply h` |
| 目标与某个假设完全一致 | 直接用那个名字 | `exact 那个名字` |

本课只需要三个策略：**`intro`、`exact`、`apply`**。
