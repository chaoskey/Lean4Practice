## 1. 从 3-3 走到 3-4

- **3-1** 命题即类型；**3-2** 用 `fun` 证 `→`；**3-3** 用「对」证 `∧`。
- **本课**换成**析取 `∨`**（读作「或」）。

**最要紧的一步**：3-3 学的 `⟨,⟩`（匿名构造子）**在这里用不了**——原因 §5 讲，而且**报错信息会亲口告诉你**。

---

## 2. 先看全景：两个连接词放在一起对照

| | **合取 `∧`（3-3）** | **析取 `∨`（本课）** |
|---|---|---|
| 读作 | 「并且」（两个都成立） | 「或」（**至少一个**成立） |
| 证明长什么样 | 一个**「对」** | 一个**「二选一」的事实** |
| 引入（造） | `And.intro hp hq` / `⟨hp, hq⟩` | **`Or.inl hp`**（用 `hp`） / **`Or.inr hq`**（用 `hq`） |
| 消去（拆） | `.left` / `.right`（各取一半） | **`Or.elim h`（分别讨论两种情况）** |
| 有几个构造子 | **1 个**（`And.intro`） | **2 个**（`Or.inl`、`Or.inr`） |
| 能用 `⟨,⟩` 吗 | ✅ 能（因为只有 1 个构造子） | ❌ **不能**（因为有 2 个，不知道该用哪个） |

**记忆抓手**：`∧` 的证明**必须两样都给**（所以打包成一「对」）；`∨` 的证明**只要给一样**（所以是「用哪一边」的选择）。

---

## 3. 引入规则：`Or.inl` / `Or.inr`（任选一边）

原文（我译）：

> `Or.intro_left q hp` 从证明 `hp : p` 造出 `p ∨ q` 的证明；类似地，`Or.intro_right p hq` 从 `hq : q` 造出 `p ∨ q` 的证明。这就是**左／右析取引入规则**。

实测（四种写法全通过）：

```lean
variable (p q : Prop)

example (hp : p) : p ∨ q := Or.intro_left q hp
example (hp : p) : p ∨ q := Or.inl hp
example (hq : q) : p ∨ q := Or.intro_right p hq
example (hq : q) : p ∨ q := Or.inr hq
```

**短写与全名的关系**（原文也这么说）：

- `Or.inl` 是 `Or.intro_left _` 的简写——**少掉的那个参数（另一半是什么）由 Lean 从「你要造的类型」推出来**；
- `Or.inr` 是 `Or.intro_right _` 的简写。

四个函数的类型（实测）：

```lean
#check Or.inl
-- Or.inl {a b : Prop} (h : a) : a ∨ b
#check Or.inr
-- Or.inr {a b : Prop} (h : b) : a ∨ b
#check Or.intro_left
-- Or.intro_left {a : Prop} (b : Prop) (h : a) : a ∨ b
#check Or.intro_right
-- Or.intro_right {b : Prop} (a : Prop) (h : b) : a ∨ b
```

⚠️ 注意 `{a b : Prop}` 是**隐式参数**（02-10 学的花括号），你不用写；`Or.intro_left` 的 `(b : Prop)` 则是**要你写的那个另一半**（所以全名比短写多一个参数）。

## 4. `Or` 到底是个什么东西（`#print` 实测）

```lean
#print Or
```

实测输出：

```
inductive Or : Prop → Prop → Prop
number of parameters: 2
constructors:
Or.inl : ∀ {a b : Prop}, a → a ∨ b
Or.inr : ∀ {a b : Prop}, b → a ∨ b
```

**和 3-3 的 `#print And` 对读**：

| | `#print And`（3-3） | `#print Or`（本课） |
|---|---|---|
| 头一行 | `structure And (a b : Prop) : Prop` | `inductive Or : Prop → Prop → Prop` |
| 构造子 | `constructor:` —— **只有 1 个** `And.intro` | `constructors:` —— **有 2 个** `Or.inl`、`Or.inr` |

⚠️ `inductive`（归纳类型）这个词属**第 7 章**，本课不必理解；你只要抓住**「构造子的个数」**这一件事——它决定了下一节能不能用 `⟨,⟩`。

---

## 5. ⚠️ 为什么 `⟨hp, hq⟩` 在 `∨` 上用不了

回到 3-3 §8 的规则：**`⟨,⟩` 只能用于「**只有一个构造子**」的类型**。

- `p ∧ q` **只有 1 个**构造子 `And.intro` → Lean 知道该用哪个 → `⟨hp, hq⟩` 合法；
- `p ∨ q` **有 2 个**构造子 `Or.inl` / `Or.inr` → Lean **不知道你想走哪一边** → 报错。

实测的报错原文（如果你对 `p ∨ q` 写了 `⟨…, …⟩`）：

```
error: Invalid `⟨...⟩` notation: The expected type `p ∨ q` has more than one constructor

Note: This notation can only be used when the expected type is an
      inductive type with a single constructor
```

**这两行报错就是本课最该记住的东西**——它把你「为什么不能用 `⟨,⟩」的理由**直接说出来了**。要造 `p ∨ q`，你**必须自己说清楚走哪一边**（`Or.inl` 还是 `Or.inr`）。

## 6. 消去规则：`Or.elim`（**分情况讨论**）

原文（我译）：

> 析取消去规则稍微复杂一点。思路是：你可以从 `p ∨ q` 证出 `r`，办法是**展示 `r` 能从 `p` 推出来、也能从 `q` 推出来**。换句话说，这是一个**分情况（by cases）证明**。在 `Or.elim hpq hpr hqr` 里，`Or.elim` 吃三个参数：`hpq : p ∨ q`、`hpr : p → r`、`hqr : q → r`，产出 `r` 的证明。

`Or.elim` 的类型（实测）：

```lean
#check Or.elim
-- Or.elim {a b c : Prop} (h : a ∨ b) (left : a → c) (right : b → c) : c
```

**三个参数，逐个读**：

| 参数 | 类型 | 它是干什么的 |
|---|---|---|
| `h` | `a ∨ b` | 「**其中一边成立**」这个事实 |
| `left` | `a → c` | 左边（`a`）成立时的**做法** |
| `right` | `b → c` | 右边（`b`）成立时的**做法** |

⚠️ **两个分支函数必须返回同一个类型**（都是 `c`）——因为 `Or.elim` 最终只能交出**一个** `c` 的证明。这也正是「分情况讨论」的准确含义：**两种情况，各给一条通往同一个结论的路**。

---

## 7. 完整例子：`p ∨ q → q ∨ p`（把「或」交换过来）

原文的例子。给定「`p` 或 `q` 成立」，要证「`q` 或 `p` 成立」——**分两种情况讨论**：

- 若 `h` 是 `inl`（左边成立，即 `hp : p`）→ 用 `Or.inr hp` 造出 `q ∨ p`；
- 若 `h` 是 `inr`（右边成立，即 `hq : q`）→ 用 `Or.inl hq` 造出 `q ∨ p`。

原文的写法（全名）：

```lean
variable (p q : Prop)

example (h : p ∨ q) : q ∨ p :=
  Or.elim h
    (fun hp : p => show q ∨ p from Or.intro_right q hp)
    (fun hq : q => show q ∨ p from Or.intro_left p hq)
```

**同一条证明，两个更短的写法**（都实测通过）：

```lean
variable (p q : Prop)

example (h : p ∨ q) : q ∨ p :=
  Or.elim h (fun hp => Or.inr hp) (fun hq => Or.inl hq)

example (h : p ∨ q) : q ∨ p :=
  h.elim (fun hp => Or.inr hp) (fun hq => Or.inl hq)
```

后一行里的 `h.elim` 就是 §3-3 讲过的**点记号**（通用规则 `e.bar` = `Foo.bar e`）：`h.elim` = `Or.elim h`。

---

## 8. `Or.elim` 里面到底做了什么（看一眼就行）

```lean
#print Or.elim
```

实测输出：

```
theorem Or.elim : ∀ {a b c : Prop}, a ∨ b → (a → c) → (b → c) → c :=
fun {a b c} h left right =>
  match h with
  | Or.inl h => left h
  | Or.inr h => right h
```

⚠️ `match`（模式匹配）属**第 7 章**，**本课不必理解语法**。你只要看懂它的**意思**：

> 「看 `h` 到底是 `inl` 还是 `inr`——是 `inl` 就调 `left`，是 `inr` 就调 `right`。」

**这正是「分情况讨论」这四个字在 Lean 里的全部内容。**

## 10. 小结

1. **`∨` 的证明 = 「走左边」或「走右边」**：造它用 `Or.inl` / `Or.inr`（全名 `Or.intro_left` / `Or.intro_right`）。
2. **`Or.elim h 左做法 右做法` = 分情况讨论**：两边的做法必须**返回同一个类型**。
3. **`∧` 有 1 个构造子、`∨` 有 2 个** → `⟨,⟩` 只能用于 `∧`，**不能**用于 `∨`（报错信息会告诉你原因）。
4. `h.elim` 与 03-3 的 `h.left` 是**同一种点记号**（`e.bar` = `Foo.bar e`）。
