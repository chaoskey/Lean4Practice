## 1. 本课要做什么

上一课（04-1）你学到的是一句话：

```
∀ x : α, p x   就是   (x : α) → p x         —— 一个函数类型
```

由此得到两个动作：**证 `∀` 就写 `fun`**（引入）、**用 `∀` 就应用**（消去）。

本课把这个「应用」**练细**，并补上三个点：

| 序 | 内容 | 一句话 |
|---|---|---|
| 1 | **`#check` 阶梯** | 一张有几个前提的定理，可以**一次喂一个参数**；每喂一次，Lean 打出来的类型就短一截 |
| 2 | **隐式参数 `∀ {x y z}, …`** | 把值参数藏起来，写作时省事；`#check` 的输出里会出现 `?m.N` |
| 3 | **`∀` 与 `→` 的关系** | `p → q` 就是「不依赖变量的 `∀`」——第 3 章的 `→` 是第 4 章 `∀` 的特例 |

> ⚠️ **本课仍然只写证明项**，不用 tactic（tactic 是**第 5 章**）。
> 这一条不是我的估计：核对原文 4.1 全节，**tactic 关键词 0 处**。

## 2. `#check` 阶梯：把定理当机器

### 2.1 先复习 `#check`

`#check` 是**命令**（2-1 学过）：它**不证明任何东西**，只是把「这个表达式的类型」打印出来。

```lean
#check Nat
```

### 2.2 一张有三个值参数的定理

先声明一张定理：`trans_r` 表示关系 `r` 的**传递性**。

```lean
section ladder
variable (α : Type) (r : α → α → Prop)
variable (trans_r : ∀ x y z, r x y → r y z → r x z)
variable (a b c : α)
variable (hab : r a b) (hbc : r b c)

#check trans_r
#check trans_r a b c
#check trans_r a b c hab
#check trans_r a b c hab hbc
end ladder
```

**实测输出**（四行，一行一条命令）：

```
trans_r : ∀ (x y z : α), r x y → r y z → r x z
trans_r a b c : r a b → r b c → r a c
trans_r a b c hab : r b c → r a c
trans_r a b c hab hbc : r a c
```

### 2.3 逐行读

先把第一行拆开看：

```
trans_r : ∀ (x y z : α), r x y → r y z → r x z
          └── 三个值 ──┘  └─ 前提一 ─┘ └─ 前提二 ─┘ └ 结论 ┘
```

`trans_r` 这台机器要**三样东西**才能开动：两个值（`x y z` 里的任意两个位置）和两个前提。现在看阶梯：

| 行 | 喂进去了什么 | Lean 打印的类型 | 这一行相比上一行 |
|---|---|---|---|
| 1 | 什么都没喂 | `∀ (x y z : α), r x y → r y z → r x z` | — |
| 2 | 三个值 `a b c` | `r a b → r b c → r a c` | 三个 `∀` 没了；`x y z` 换成了 `a b c` |
| 3 | 再加一个前提 `hab` | `r b c → r a c` | 少了一个 `→`（第一个前提被吃掉了） |
| 4 | 再加一个前提 `hbc` | `r a c` | 少了第二个 `→`；**左边已经不是函数了** |

> ## ⭐ 一句话
> **每应用一次，类型里就少一个 `→`；前提喂完，剩下的就是结论本身。**
>
> 第 4 行的 `trans_r a b c hab hbc` **不是「关于 `r a c` 的东西」，它就是要证的 `r a c` 的证明**。
> 这正是 04-1 学的**消去**——只是这次我们把它一层层看清楚了。

### 2.4 这张阶梯有什么用

两点：

1. **写证明时它就是「还差什么」的清单**。证到一半卡住，把手上那个定理 `#check` 一下（或喂掉已有参数再 `#check`），打印出来的类型就是**你还缺的东西**。
2. **它解释了「定理就是函数」**。`trans_r` 本身是个函数；喂参数的过程就是函数应用——和 2-4 学的一模一样，只是类型里有 `Prop`。

## 3. 隐式参数：`∀ {x y z}, …`

### 3.1 写法

2-10 讲过：**花括号 `{}` 包起来的参数是隐式参数**——通常不用你给，Lean 自己推。

本课把它用到 `∀` 上：把 `∀ x y z, …` 写成 `∀ {x y z}, …`，那三个值就变成隐式。

```lean
section ladder_implicit
variable (α : Type) (r : α → α → Prop)
variable (trans_i : ∀ {x y z}, r x y → r y z → r x z)
variable (a b c : α)
variable (hab : r a b) (hbc : r b c)

#check trans_i
#check trans_i hab
#check trans_i hab hbc
end ladder_implicit
```

**实测输出**：

```
trans_i : r ?m.4 ?m.5 → r ?m.5 ?m.6 → r ?m.4 ?m.6
trans_i hab : r b ?m.6 → r a ?m.6
trans_i hab hbc : r a c
```

### 3.2 `?m.N` 是什么

`?m.4` 这类记号叫**元变量**（metavariable）——02-4 讲过它的来历。在这里它的意思很具体：

> **`?m.4` = 「这个位置的参数，Lean 到这儿还不知道该填什么」。**

⚠️ **`?m` 后面的数字只是 Lean 的内部编号**，不要用它做任何判断。一个实测：

- 原文 4.1 的**正文**里写的是 `r ?m.1 ?m.2 → …`；
- 而**同一个代码块**实际打印出来是 `r ?m.4 ?m.5 → …`。

两处**指同一件事**，只是编号不同。

**你自己跑的时候编号也会和这里不一样**（它取决于文件里前面出现过多少需要推断的东西）——
我做习题参考解时实测到过 `?m.4 …` 和 `?m.9 …` 两种。

> **要紧的是「有没有 `?m`」，不是「`?m` 后面是几」。**
>
> 📌 **做题时的判准（题 4 用）**：**预测只要求「形状」对**——有没有 `?m`、有几个 `→`、`r` 的两个位置分别是哪个变量。
> **编号对不上是正常的、不用改**（内部编号本来就预测不出来）。
> 而文件末尾「验证区」那份**实跑记录**要**逐字照抄**实际输出（那是记录，不是预测）。

### 3.3 三条输出逐行读

| 行 | 喂进去了什么 | 打印的类型 | 定下来了哪些值 |
|---|---|---|---|
| 1 | 什么都没喂 | `r ?m.4 ?m.5 → r ?m.5 ?m.6 → r ?m.4 ?m.6` | **一个都没定** |
| 2 | `hab : r a b` | `r b ?m.6 → r a ?m.6` | `x := a`、`y := b`（看 `r a b` 的形状） |
| 3 | 再加 `hbc : r b c` | `r a c` | `z := c`；**`?m` 全没了** |

> **信息是从哪里来的？** 从**喂进去的参数的类型**来。
> `hab : r a b` 的形状逼着第一个参数是 `a`、第二个是 `b`；`hbc : r b c` 逼着第三个是 `c`。
> 三个都钉住了，Lean 就不用再猜了。

### 3.4 好处与代价

| | |
|---|---|
| **好处** | 写起来短。证 `r a c` 时可以直接写 `trans_i hab hbc`，**不用**写 `a b c` |
| **代价** | 单独看 `trans_i`、`trans_i hab` 时，Lean 的信息**不够**（所以打出 `?m`）——想看清楚就得补参数 |

这段话不是我编的取舍：原文 4.1 讲隐式参数时说的正是这两条。

### 3.5 想显式给出来：`@`

隐式参数不是「不能写」，只是「默认不用写」。**`@` 把它变回必须写的显式参数**（2-10 学过）：

```lean
section at_sign
variable (α : Type) (r : α → α → Prop)
variable (trans_i : ∀ {x y z}, r x y → r y z → r x z)
variable (a b c : α) (hab : r a b) (hbc : r b c)

#check @trans_i
#check @trans_i a b c
end at_sign
```

**实测输出**：

```
trans_i : ∀ {x y z : α}, r x y → r y z → r x z
trans_i : r a b → r b c → r a c
```

读法：

- 第 1 行：`@trans_i` 打出来的类型里，`{x y z}` **还带着花括号**——这是「它本来是隐式的」这个事实。
- 第 2 行：一旦用 `@` 把 `a b c` 写上，它就和 2.2 那张**显式**阶梯的第 2 行**是同一个类型**了。

> ⚠️ **`@` 后面必须把隐式参数一个不落地写出来**。`@trans_i a` 只写一个，是**不合法**的。
> 另一种给法 2-10 也讲过：具名写法 `trans_i (x := a) (y := b) (z := c)`。

## 4. 用起来：等价关系的初等推理

原文 4.1 给了一个把两个引理接起来的例子。写成 Lean：

```lean
theorem ex_rel (α : Type) (r : α → α → Prop)
    (symm_r : ∀ {x y}, r x y → r y x) (trans_r : ∀ {x y z}, r x y → r y z → r x z)
    (a b c d : α) (hab : r a b) (hcb : r c b) (hcd : r c d) : r a d :=
  trans_r (trans_r hab (symm_r hcb)) hcd
```

**逐步看类型**（每一步都是消去）：

| 表达式 | 类型 | 做了什么事 |
|---|---|---|
| `hab` | `r a b` | 手上的材料 |
| `hcb` | `r c b` | 手上的材料 |
| `symm_r hcb` | `r b c` | 把 `hcb` **掉个头**（`symm_r` 是隐式参数，`b c` 由 `hcb` 推出来） |
| `trans_r hab (symm_r hcb)` | `r a c` | 从 `a` 接到 `c` |
| `hcd` | `r c d` | 手上的材料 |
| `trans_r (trans_r hab (symm_r hcb)) hcd` | `r a d` | 从 `a` 接到 `d` |

> **注意 `symm_r` 和 `trans_r` 是写在 `theorem` 的括号参数表里的**（叫**显式参数**），
> 不是靠 `variable` 自动加的。为什么必须这样写？见下面这个 ⚠️。

### ⚠️ 一个真会咬人的细节：`variable` 只加「出现在命题里」的变量

假设你把上面那段改写成先 `variable` 再写 `theorem`：

```
variable (α : Type) (r : α → α → Prop)
variable (symm_r : ∀ {x y}, r x y → r y x)
variable (trans_r : ∀ {x y z}, r x y → r y z → r x z)
variable (a b c d : α) (hab : r a b) (hcb : r c b) (hcd : r c d)

theorem t : r a d := trans_r (trans_r hab (symm_r hcb)) hcd
```

**上面这段是故意写错的**（所以它没有用 ```lean 标记）。实测报错是：

```
error: Unknown identifier `trans_r`
```

**为什么？** 因为 Lean 给声明加参数时，**只加那些出现在「声明类型」里的 `variable`**。这张定理的类型是 `r a d`，
里面只出现了 `α`、`r`、`a`、`d`——`trans_r`、`symm_r`、`hab`、`hcb`、`hcd`、`b`、`c` **一个都没出现**，
所以它们**根本没被加进这张定理**，证明体里自然就找不到。

**实测证据**：把上面那段改成能编译的样子再看 `#print`，Lean 打出的参数表就是

```
theorem t : ∀ (α : Type) (r : α → α → Prop) (a d : α), r a d := …
```

——只有 `α r a d` 四个，**没有** `trans_r`。

**正确做法**（也就是本节 `ex_rel` 的写法）：把引理写进**括号参数表**里

```lean
section explicit_params
variable (α : Type) (r : α → α → Prop)

example (trans_r : ∀ {x y z}, r x y → r y z → r x z)
    (a b c : α) (hab : r a b) (hbc : r b c) : r a c :=
  trans_r hab hbc
end explicit_params
```

> **一句话结论**：**凡是你打算在证明体里用、但命题本身又没提到的东西，都要写成显式参数。**
>
> 📌 顺带一个实测事实（本课**不要求理解**，只是别被它误导）：**上面那个 `theorem t : r a d := …` 的写法**，
> 如果改成不带名字的 `example`，却**能编译**。原因是 `example` 没有名字，它直接在完整上下文里处理证明体，
> 不经过「先算参数表」这一步。本课不展开这条区别——**记住上面那句话结论就够了**。

## 5. `p → q` 就是 `∀ _ : p, q`

原文 4.1 里有一句很值得单独拿出来讲的话：

> 正如 `α → β` 是 `(x : α) → β` 中 `β` 不依赖 `x` 的特例，
> **`p → q` 也是 `∀ x : p, q` 中 `q` 不依赖 `x` 的特例。**

也就是说：**第 3 章你天天在写的 `→`，其实就是第 4 章这个 `∀` 的一种（变量用不上的）情形。**

用 Lean 直接验：

```lean
example (p q : Prop) (h : p → q) : ∀ _ : p, q := h
example (p q : Prop) (h : ∀ _ : p, q) : p → q := h
```

两个方向都是**一次直接赋值**（`:= h`）——不需要 `fun`，不需要任何转换命令。

> **这说明什么？** 说明两个类型**按定义就是同一个**，不是「碰巧等价」。
> （对照 3-6 那道题：`p ↔ q` 与 `(p → q) ∧ (q → p)` 就**不是**同一个类型，那时是要写两个方向的。）
>
> 📌 写法上的两点：
> - `∀ _ : p, q` 里的 `_` 表示「**这个变量我不打算给它起名字**」——因为 `q` 里根本不用它。
> - 你也可以写 `(x : p) → q`；既然 `x` 用不上，写 `_` 最不容易引起误会。

## 6. ⚠️ 了解即可：`Prop` 为什么叫「非直谓」

**本节的结论只要记住一句，不需要理解原理。**

原文 4.1 末尾那段讲的是：`(x : α) → β` 属于哪个「宇宙」，取决于 `β` 属于哪个宇宙；
**而当 `β` 是命题（属于 `Prop`）时，整个 `(x : α) → β` 也属于 `Prop`——不管 `α` 有多大。**

拿 Lean 看一眼（`#check` 会把「属于哪个宇宙」也打出来）：

```lean
#check (∀ (α : Type) (p : α → Prop) (x : α), p x → p x)
#check (∀ (α : Type), α → α)
```

**实测输出**：

```
∀ (α : Type) (p : α → Prop) (x : α), p x → p x : Prop
(α : Type) → α → α : Type 1
```

| 行 | 里面量化到了什么 | 「体」是什么 | 整体属于 |
|---|---|---|---|
| 1 | `Type`、`α → Prop`（**很大的东西**） | 命题（`p x → p x`） | **`Prop`** |
| 2 | `Type` | 类型（`α → α`，是数据不是命题） | `Type 1`（**不是 `Prop`**） |

第 1 行就是所谓**非直谓性**（impredicativity）：我们**对「所有谓词」量化**，得到的仍然是**一个命题**。
原文说，一百年前这被认为是「恶性循环」式的定义方式；而在 Lean 的 `Prop` 里它是合法的。

**反过来的对照**——如果「体」不是命题，整体就不是 `Prop`：

```
example : Prop := ∀ (α : Type), α → α
```

**上面这段是故意写错的**（也没有用 ```lean 标记）。实测报错：

```
error: Type mismatch
  (α : Type) → α → α
has type
  Type 1
of sort `Type 2` but is expected to have type
  Prop
of sort `Type`
```

> ⚠️ **本课不要求理解的部分**：`Sort`、`Sort 1`、`Type 1`、`imax`、以及报错里的 `of sort …`。
> 这些属于**后面的章节**（宇宙与多态）。本课只需要带走这一条：
> **「体是命题 ⟹ 整体还是命题」；「体是类型 ⟹ 整体不是命题」。**
