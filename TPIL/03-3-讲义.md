> 📄 **示例**：`03-3-示例.lean`（我写的，已通过编译、零 warning）

> **本课的一句话**：**`p ∧ q` 的证明，就是「`p` 的证明」和「`q` 的证明」打包成的一个「对」**——用 `And.intro`（或 `⟨,⟩`）打包，用 `.left` / `.right` 拆包。

## 2. 先认全连接词的脸（本课只学 `∧`）

原文 3.3 开头给了这张表：

| 纯 ASCII | 符号 | 编辑器缩写（VS Code） | 本名 | 本课地位 |
|---|---|---|---|---|
| `True` | `True` | —— | `True` | 3-5 再讲 |
| `False` | `False` | —— | `False` | 3-5 再讲 |
| `Not` | `¬` | `\not`、`\neg` | `Not` | 3-5 再讲 |
| `/\` | `∧` | `\and` | `And` | ✅ **本课主角** |
| `\/` | `∨` | `\or` | `Or` | 3-4 再讲 |
| `->` | `→` | `\to`、`\r`、`\imp` | （蕴含／函数类型） | 3-2 已学 |
| `<->` | `↔` | `\iff`、`\lr` | `Iff` | 3-6 再讲 |

三点说明：

1. 除了 `→`，其余六个（`True` `False` `Not` `And` `Or` `Iff`）**都是 Lean 库里的定义**，自动导入，不用你写。
2. 原文一句话要记住：**它们的结果都是 `Prop`**——`p ∧ q : Prop`、`p ∨ q : Prop`……（`→` 也一样：`p → q : Prop`，这是 03-1 学过的「`Prop` 对箭头封闭」。）
3. **优先级**（原文）：`¬` 最强，其次 `∧`，其次 `∨`，其次 `→`，最后 `↔`；**二元连接词一律右结合**。
   所以 `a ∧ b → c ∨ d ∧ e` 读作 `(a ∧ b) → (c ∨ (d ∧ e))`。
   本课只需要用到其中**一条**：**`∧` 比 `→` 结合得紧**——`p ∧ q → r` 是 `(p ∧ q) → r`。

实测（`∧` 与 `→` 的相对强弱、以及右结合的打印效果）：

```lean
variable (p q r : Prop)

#check (p ∧ q → q)      -- p ∧ q → q : Prop
#check ((p ∧ q) ∧ r)    -- (p ∧ q) ∧ r : Prop
#check (p ∧ (q ∧ r))    -- p ∧ q ∧ r : Prop
```

**怎么读上面第 2、3 行**：这两行的**类型不一样**——第 2 行是「先合取左边两个」，第 3 行是「先合取右边两个」。但 Lean 打印时**只给「不按右结合」的那种加括号**：所以 `(p ∧ q) ∧ r` 带着括号，而 `p ∧ (q ∧ r)` 打成 `p ∧ q ∧ r`（右结合是默认读法，不用括号）。这也说明：**你写 `p ∧ q ∧ r` 时，Lean 读作 `p ∧ (q ∧ r)`**。

## 3. 打包：`And.intro`（合取的「引入规则」）

原文（我译）：

> `And.intro h1 h2` 用两个证明 `h1 : p`、`h2 : q` 造出 `p ∧ q` 的证明。它常被称作**合取引入规则**（and-introduction rule）。

实测：

```lean
variable (p q : Prop)

example (hp : p) (hq : q) : p ∧ q := And.intro hp hq
```

逐段读：

| 这一段 | 它在说 |
|---|---|
| `example` | 「检查下面这个项有指示的类型」——**本课新语法，§7 专门讲** |
| `(hp : p) (hq : q)` | 两个假设（写法和 `theorem` 的参数一样） |
| `: p ∧ q` | 要造出的类型（也就是要证的命题） |
| `:= And.intro hp hq` | 交出的项：**把两个证明打包** |

`And.intro` 自己的类型（实测）：

```lean
#check And.intro
-- And.intro {a b : Prop} (left : a) (right : b) : a ∧ b
```

两点：

1. `{a b : Prop}` 是**隐式参数**（02-10 学的花括号）——它俩由上下文推出来，你不用写。
2. 它两个参数的**名字**就叫 `left`、`right`（不是我随便起的）。

## 4. `And` 到底是个什么东西（`#print` 实测）

```lean
#print And
```

实测输出：

```
structure And (a b : Prop) : Prop
number of parameters: 2
fields:
  And.left : a
  And.right : b
constructor:
  And.intro {a b : Prop} (left : a) (right : b) : a ∧ b
```

读法：

- 第 1 行：`And` 有**两个参数**（`a b : Prop`），**结果是一个 `Prop`**；
- `fields:` 下面两行：它有两个**字段**（field）——`left : a` 与 `right : b`；
- `constructor:` 一行：它有**一个**构造子 `And.intro`。

⚠️ `structure`（结构体）这个词属**第 7 章**，本课**不必理解**。你只要记住上面三件事：**两个参数、两个字段（`left` / `right`）、一个构造子（`intro`）**——§5 和 §8 的写法全从这里来。

## 5. 拆包：`And.left` / `And.right`（合取的「消去规则」）

原文（我译）：

> `And.left h` 从 `h : p ∧ q` 造出 `p` 的证明；`And.right h` 造出 `q` 的证明。它们常被称作**左合取消去规则**和**右合取消去规则**。

实测：

```lean
variable (p q : Prop)

example (h : p ∧ q) : p := And.left h
example (h : p ∧ q) : q := And.right h
```

这两个函数的类型（实测）：

```lean
#check And.left
-- And.left {a b : Prop} (self : a ∧ b) : a
#check And.right
-- And.right {a b : Prop} (self : a ∧ b) : b
```

**和 02-2 的对照**：02-2 学的「对」`Nat × Bool` 用 `.1` / `.2`（本名 `.fst` / `.snd`）取两个分量；这里 `p ∧ q` 的两个分量用 `And.left` / `And.right` 取。**形状一样，含义不同**——§10 讲这个「不同」到底在哪。

**改用点记号也完全一样**（§6 讲点记号）：

```lean
variable (p q : Prop)

example (h : p ∧ q) : p := h.left
example (h : p ∧ q) : q := h.right
```

**`.1` / `.2` 也可以**（02-2 学过这两个）：

```lean
variable (p q : Prop)

example (h : p ∧ q) : p := h.1
example (h : p ∧ q) : q := h.2
```

四种写法各自造出的函数的类型（实测）：

```lean
variable (p q : Prop)

#check (fun (h : p ∧ q) => h.left)     -- fun h => h.left : p ∧ q → p
#check (fun (h : p ∧ q) => h.right)    -- fun h => h.right : p ∧ q → q
```

注意打印出来的是 **`h.left`**，不是你写的 `And.left h`——**Lean 偏爱短的写法**（这和 03-1「有记号时就用记号打印」是同一类现象）。

## 6. 点记号 `e.bar` 是什么

原文（我译）：

> 给定一个表达 `e`，其类型是某个**归纳类型** `Foo`，那么写法 `e.bar` 是 `Foo.bar e` 的简写。这样不用 `open` 命名空间也能调用函数。

⚠️ 「归纳类型」属**第 7 章**，本课不必理解；你只要知道 `p ∧ q`、`Nat × Bool` 这类东西都适用。

原文举的例子用的是 `List`（⚠️ **`List` 是 Lean 内置的列表类型，它的定义属第 7 章，本课不必理解**——这里只把它当成「有一个 `length` 函数的类型」）：

```lean
variable (xs : List Nat)

#check List.length xs   -- xs.length : Nat
#check xs.length        -- xs.length : Nat
```

**一个不依赖 `List` 的同类例子**（用你已经很熟的 `Nat`）：

```lean
#check (3 : Nat).succ   -- Nat.succ 3 : Nat
```

规律一句话：**`e.bar` 就是把 `e` 塞进 `Foo.bar` 的第一个参数**——`xs.length` = `List.length xs`，`h.left` = `And.left h`，`3.succ` = `Nat.succ 3`。

## 7. `example` 命令（本课新语法）

原文（我译）：

> `example` 命令**声明一个定理，但既不给它起名字、也不把它存进上下文**。本质上，它只是**检查给定的项有指示的类型**。它方便举例，我们会经常用它。

**和 `theorem` 的区别**（实测）：

```lean
variable (p : Prop)

example : p → p := fun hp => hp        -- 通过；但没有名字，之后无从引用
theorem named : p → p := fun hp => hp  -- 通过；有名字
#check named                           -- named (p : Prop) : p → p
```

- `example` 之后你**没法再引用它**（它没有名字）；
- `theorem named` 之后可以 `#check named`、`#print named`，也能把 `named` 当函数用。

**本课为什么开始用它**：这一课的例子大多是「随手验证某个类型能不能造出来」，**不需要**给每个都起名字——起名字反而要占名字、还要小心重名。

## 8. 匿名构造子 `⟨hp, hq⟩`（打包的短写法）

原文（我译）：

> 对 `p ∧ q` 这类「**只有一个构造子**」的类型，Lean 允许**匿名构造子写法** `⟨arg1, arg2, ...⟩`——前提是**相关类型能从上下文推出来**。于是常常可以写 `⟨hp, hq⟩` 代替 `And.intro hp hq`。

`⟨` `⟩` 的输入：**`\<` + 空格**、**`\>` + 空格**（见 [`Unicode速查.md`](./Unicode速查.md)）。

实测（结果类型已知，可以直接用）：

```lean
variable (p q : Prop)

example (hp : p) (hq : q) : p ∧ q := ⟨hp, hq⟩
```

**⚠️ 一个必踩的坑**（实测）。下面这段是**故意写错的**：

```
#check (fun (hp : p) (hq : q) => ⟨hp, hq⟩)

error: Invalid `⟨...⟩` notation: The expected type of this term could not be determined
```

**原因**：`⟨,⟩` 本身**不带**「这是 `And` 还是 `Prod`」的信息，它**只能靠上下文推**。上面那种写法里，Lean 不知道你要造的是 `p ∧ q` 还是别的什么，于是直接报错。

**修法**：**给它一个类型标注**（实测通过）：

```lean
variable (p q : Prop)
variable (hp : p) (hq : q)

#check (⟨hp, hq⟩ : p ∧ q)   -- ⟨hp, hq⟩ : p ∧ q
```

**顺带一条实测**：`#check (And.intro hp hq)` 打印出来是 **`⟨hp, hq⟩ : p ∧ q`**——**Lean 自己偏爱用匿名构造子打印**（和 §5 那个 `h.left` 是同一类现象）。

## 9. 嵌套与「扁平化」

原文（我译）：

> 「`And`」这类构造常常会**叠起来**。Lean 允许把**右结合**的嵌套构造子**摊平**来写，所以下面两个证明是等价的。

实测：

```lean
variable (p q : Prop)

example (h : p ∧ q) : q ∧ p ∧ q := ⟨h.right, ⟨h.left, h.right⟩⟩
example (h : p ∧ q) : q ∧ p ∧ q := ⟨h.right, h.left, h.right⟩
```

**为什么能省**：`q ∧ p ∧ q` 按右结合就是 `q ∧ (p ∧ q)`（§2 讲过）。要造它，得交出「`q` 的证明」+「`p ∧ q` 的证明」——而后者本身又是一对。**扁平的 `⟨a, b, c⟩` 恰好对应「最外层那一对 + 里面那一对」**，所以两种写法说的是同一件事。

**⚠️ 只有「右嵌套」能这样省。** 实测（下面这段是**故意写错的**）：

```
variable (p q r : Prop)
example (a : p) (b : q) (c : r) : (p ∧ q) ∧ r := ⟨a, b, c⟩

error: Application type mismatch: The argument
  a
has type
  p
but is expected to have type
  p ∧ q
in the application
  And.intro a
```

`(p ∧ q) ∧ r` 是**左嵌套**，正确的写法要**显式嵌一层**（实测通过）：

```lean
variable (p q r : Prop)

example (a : p) (b : q) (c : r) : (p ∧ q) ∧ r := ⟨⟨a, b⟩, c⟩
```

## 10. `∧` 与 `×`：像，但**不是**同一个东西

**像在哪**：`And.intro` ↔ `Prod.mk`（打包），`And.left` / `And.right` ↔ `.1` / `.2`（拆包）——形状一模一样。

**不同在哪**（原文原话，我译）：

> 给定 `hp : p` 和 `hq : q`，`And.intro hp hq` 的类型是 `p ∧ q : Prop`；而给定 `a : α` 和 `b : β`，`Prod.mk a b` 的类型是 `α × β : Type`。**`Prod` 不能用在 `Prop` 上，`And` 不能用在 `Type` 上。**

实测这两句话。下面这段是**故意写错的**：

```
-- ① And 吃 Type（Nat）会报错：
#check And Nat Nat

error: Application type mismatch: The argument
  Nat
has type
  Type
of sort `Type 1` but is expected to have type
  Prop
of sort `Type` in the application
  And Nat
```

```
-- ② Prod 吃 Prop 会报错（p q 是 Prop）：
variable (p q : Prop)
#check Prod p q

error: Application type mismatch: The argument
  p
has type
  Prop
of sort `Type` but is expected to have type
  Type ?u.4
of sort `Type (?u.4 + 1)` in the application
  Prod p
```

**一句话**：`And` 只在**命题的世界**（`Prop`）里工作，`Prod` 只在**类型的世界**（`Type`）里工作。它俩虽然「长得像」，在 Lean 里却是**分开定义的两个东西**。原文：

> `∧` 与 `×` 的相似是 Curry–Howard 同构的**又一例**；但与「蕴含 ↔ 函数类型」不同，**`∧` 和 `×` 在 Lean 里是分开处理的**。

对照实测（这两个是**对的**写法）：

```lean
variable (p q : Prop)

#check (Prod.mk 1 true)   -- (1, true) : Nat × Bool
#check (And p q)          -- p ∧ q : Prop
```

## 12. 小结

1. **合取 `p ∧ q` 的证明是一个「对」**：打包用 `And.intro hp hq`（或 `⟨hp, hq⟩`），拆包用 `And.left` / `And.right`（或 `h.left` / `h.right` / `h.1` / `h.2`）。
2. **`→` 的引入/消去是 `fun` / 应用；`∧` 的引入/消去是打包 / 拆包**——这就是「每个连接词都带一套引入规则和消去规则」。
3. **`⟨,⟩` 靠上下文推类型**；推不出来时要加 `: p ∧ q` 这样的标注（否则报 `Invalid ⟨...⟩ notation`）。
4. **`p ∧ q` 与 `p × q` 长得像，但一个住 `Prop`、一个住 `Type`**，不能混用。
5. 新语法：**`example`**——检查类型、不命名、不入库。
