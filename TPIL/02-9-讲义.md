## 1. 本课的一句话

**一个类型的定义里，可以出现「值」。** 于是「同一个名字 + 不同的值」就是**不同的类型**。

本课有两个主角：

| 名字 | 长什么样 | 依赖体现在哪 |
|---|---|---|
| **依赖函数类型** | `(a : α) → β a` | **返回值的类型依赖输入** |
| **依赖对类型**（sigma） | `(a : α) × β a` | **第二个分量的类型依赖第一个分量** |

---

## 2. 其实你早就见过「依赖类型」的一半

**02-3** 里你见过 `List : Type → Type`——`List α` **依赖** `α`。但那依赖的是**类型**。
本课的新东西是：类型可以依赖**值**（比如一个 `Nat`）。实测：

```lean
#check List
#check Fin
#check Fin 3
#check Vector
```

实测输出（4 行）：

```
List.{u} (α : Type u) : Type u
Fin (n : Nat) : Type
Fin 3 : Type
Vector.{u} (α : Type u) (n : Nat) : Type u
```

**看第 3 行**：`Fin 3 : Type`——`Fin` **吃了一个值** `3`，吐出一个**类型**。
这就是「依赖类型」：`Fin` 的类型是 `(n : Nat) → Type`——**返回的类型依赖 `n` 这个值**。

所以：

- **`Fin 3` 与 `Fin 5` 是「两个不同的类型」**（不是「同一个类型的两个值」）。
  `Fin 3` 的元素是 `0`、`1`、`2`；`Fin 5` 的元素是 `0`…`4`——**元素个数由 `n` 决定**。
- `Vector Nat 2` 与 `Vector Nat 3` 同理（`Vector` 同时依赖**一个类型** `α` 和**一个值** `n`）。

```lean
#check (2 : Fin 3)
#eval (2 : Fin 3)
```

实测：

```
2 : Fin 3
2
```

> ⚠️ **本课不引入的两样东西**，看输出时会碰到，**别在这里卡住**：
> 1. `. {u}` 与 `Type u` 里的 **`u`** 是**宇宙多态**——**还没有归属的课**（见 `学习计划.md` §三 的注）。
> 2. `Fin` / `Vector` 的**定义**用了 `inductive`，属**第 7 章**——**本课不引入**。
>    本课你只需要知道：`Fin n` 是「**小于 `n` 的自然数**」这个类型，**元素个数由 `n` 决定**。

## 3. 问题：`cons` 的类型该写什么？

（下面这段推理来自原文，我翻译并拆细。）

`cons` 是「把一个元素放到列表最前面」的函数。显然 `cons α a as` 应该返回 `List α`。
那么 **`cons` 自己**是什么类型？

**第一反应**：`Type → α → List α → List α`。
**可是这说不通**：那个 `α` **无所指**——它**应该**是「**第一个参数的值**」，
但写成 `Type → α → …` 之后，`α` 只像是「第 2 个参数恰好也叫 `α`」，**和第一个参数没有任何关系**。

**正确写法：给参数起名字**（这就是 `(名字 : 类型) →` 这个写法的用处）：

```lean
def cons (α : Type) (a : α) (as : List α) : List α :=
  List.cons a as

#check cons
#check cons Nat
#check cons Bool
#eval cons Nat 1 (cons Nat 2 List.nil)
```

实测输出（4 行）：

```
cons (α : Type) (a : α) (as : List α) : List α
cons Nat : Nat → List Nat → List Nat
cons Bool : Bool → List Bool → List Bool
[1, 2]
```

**关键在中间两行**：`cons Nat` 的类型是 `Nat → List Nat → List Nat`，
`cons Bool` 是 `Bool → List Bool → List Bool`——**「后面参数的类型」和「返回类型」都跟着第一个参数变了**。
这就是「依赖」：`α` 是一个**参数名**，后面的 `α` 都指向它。

> ⚠️ **`List.cons a as` 里的 `{}` 隐式参数**：本课**不引入**——**下一课 2-10 专讲**（原文 2.9 就是它）。
> 本课你只要照抄 `List.cons a as` 就行（那个类型参数 Lean 自己会推出来）。

## 4. 依赖函数类型：`(a : α) → β a`

原文的定义（我翻译）：

> 给定 `α : Type` 和 `β : α → Type`，把 `β` 看成**一族类型（a family of types）**——
> 也就是：**对每个 `a : α` 都有一个类型 `β a`**。
> 那么 `(a : α) → β a` 表示这样一些函数 `f` 的类型：
> **对每个 `a : α`，`f a` 都是 `β a` 的元素**。
> 换句话说，**`f` 返回值的类型依赖它的输入**。

**原文还有一句极重要的话**（我翻译）：

> 当 `β` **不依赖** `a` 的时候，`(a : α) → β` 与 `α → β` **没有区别**。
> 实际上，在依赖类型论里（也就在 Lean 里），**`α → β` 就是 `(a : α) → β` 在 `β` 不依赖 `a` 时的记号**。

实测——**两行输出一模一样**：

```lean
#check ((a : Nat) → Nat)
#check (Nat → Nat)
```

实测输出（2 行）：

```
Nat → Nat : Type
Nat → Nat : Type
```

**所以你不是在学一个新符号，而是在学一个新「自由度」**：`β` 现在**可以**跟着 `a` 走；
它不跟着走的时候，Lean 打出来还是老样子 `α → β`。

**一个真的依赖的例子**（返回类型里**有 `n`**）：

```lean
def depZero (n : Nat) : Fin (n + 1) :=
  0

#check depZero
#check depZero 3
#eval depZero 3
#check ((n : Nat) → Fin (n + 1))
```

实测输出（4 行）：

```
depZero (n : Nat) : Fin (n + 1)
depZero 3 : Fin (3 + 1)
0
(n : Nat) → Fin (n + 1) : Type
```

⚠️ **注意第 2 行打的是 `Fin (3 + 1)`，不是 `Fin 4`**——Lean **不会替你算**（除非有理由必须算）。

`depZero` 的意思是：「给我任何一个 `n`，我还你一个 `Fin (n + 1)` 里的元素」。
它必须返回 `0`——因为 `Fin (n + 1)` 里一定有 `0`（而 `Fin n` **不一定**有，`n = 0` 时它是空的）。

> 📌 这里有一个**很容易卡住**的地方：**这个值其实完全不依赖 `n`**——变的是**类型**。
> 详见 **§5 末尾**的 💡（那里有 `#print depZero` 的实测）。

### ⚠️ 但那个 `0` 背后有一条**本课不解释**的规则

**分两层看，别混在一起：**

- **「为什么答案是 `0`」——这一层不需要新知识。**
  `Fin (n + 1)` 的元素就是 `0`、`1`、…、`n`，所以最小的那个一定是 `0`。
  这是从本课说的「`Fin k` 是**小于 `k` 的自然数**」直接推出来的。
- **「Lean 凭什么接受你把字面量 `0` 当成 `Fin (n + 1)` 的元素」——这一层需要一条没讲的规则。**
  `0` 本身**不属于任何特定类型**：它的类型由**预期类型**决定。机制叫**类型类实例**，属 **第 10 章**。

实测（**同一个 `0`，能待在好几种类里**）：

```lean
#check (0 : Nat)          -- 0 : Nat
#check (0 : Fin 3)        -- 0 : Fin 3
#check (0 : Int)          -- 0 : Int
#check (0 : Fin (2 + 1))  -- 0 : Fin (2 + 1)
#check (0)                -- 0 : Nat    ← 没有预期类型时，默认是 Nat
```

**本课你怎么对待它**：把它当成一条「**可以用、暂时别问为什么**」的规则——
跟你一直在写 `def five : Nat := 5` 里的 `5`、`#eval` 里的数字是同一回事。
**第 10 章**（Type Classes）会正面讲清它。

而这个机制**正好解释了为什么上面的例子写的是 `Fin (n + 1)` 而不是 `Fin n`**：
一般的 `Fin n` **没有**这条规则——因为 `n = 0` 时 `Fin 0` 是**空类型**，压根没有元素可写。
实测报错原文：

```
error: failed to synthesize instance of type class  OfNat (Fin n) 0
numerals are polymorphic in Lean, but the numeral `0` cannot be used in a context
where the expected type is  Fin n   due to the absence of the instance above
```

（看 Lean 自己那句话：**「numerals are polymorphic in Lean」**。）

## 5. 依赖对类型（sigma）：`(a : α) × β a`

原文（我翻译）：

> 正如依赖函数类型用「让 `β` 依赖 `a`」**推广**了函数类型 `α → β`，
> **依赖笛卡尔积类型** `(a : α) × β a` 用同样的方式**推广**了笛卡尔积 `α × β`。
> 依赖积也叫 **sigma 类型**，也可以写成 **`Σ a : α, β a`**。
> 可以用 **`⟨a, b⟩`** 或 **`Sigma.mk a b`** 造一个依赖对。

实测（**造**一个依赖对）：

```lean
def mkPair (α : Type) (β : α → Type) (a : α) (b : β a) : (a : α) × β a :=
  ⟨a, b⟩

#check mkPair
```

实测：

```
mkPair (α : Type) (β : α → Type) (a : α) (b : β a) : (a : α) × β a
```

**看第二个参数的类型 `β a` 和返回类型 `(a : α) × β a`**：
「第二个分量」的类型是 `β a`——**它依赖第一个分量 `a`**。这在 02-2 学的普通 `×` 里是做不到的。

`Σ` 写法与 `Sigma.mk`（**和上面是同一个东西**）：

```lean
def mkSigma (α : Type) (β : α → Type) (a : α) (b : β a) : Σ a : α, β a :=
  Sigma.mk a b

#check mkSigma
```

实测：

```
mkSigma (α : Type) (β : α → Type) (a : α) (b : β a) : (a : α) × β a
```

⚠️ **打印出来是 `×` 那一版**——`Σ a : α, β a` 与 `(a : α) × β a` **是同一个类型的两种写法**
（原文说 `f` 与 `g`「表示同一个函数」，指的就是这种关系：**写法不同，东西相同**）。

### 最漂亮的例子：取第二个分量

```lean
def secondOf (α : Type) (β : α → Type) (p : (a : α) × β a) : β p.1 :=
  p.2

#check secondOf
```

实测：

```
secondOf (α : Type) (β : α → Type) (p : (a : α) × β a) : β p.fst
```

**盯着返回类型 `β p.1` 看**：`β` 吃的不是某个固定的类型，而是 **`p` 的第一个分量**——
也就是说，**你得先知道 `p.1` 是什么，才知道 `p.2` 是什么类型**。

> 💡 `p.1` 在这里打印成 **`p.fst`**——**02-2 讲过 `.1` 与 `.fst` 是同一个东西**（`(5, 9).1` 与 `(5, 9).fst` 都是 `5`）。
> 所以 `β p.1` 和 `β p.fst` 是**同一个类型**，只是 Lean 选了后一种写法打印。

> ⚠️ **原文那版用了 `universe u v`**，把类型写成 `Type u` / `Type v`——那是**宇宙多态**（还没有归属的课），
> **本课不引入**。上面这些例子里我都用了**不带 universe** 的 `Type`：**效果一样，只是适用范围窄一点**。
> 等学到那节课，你就明白原文为什么多写那么一笔。

### 💡 一个很容易卡住的地方：值可以**不**依赖参数

`depZero` 的**类型**依赖 `n`（返回 `Fin (n + 1)`）——那它的**值**呢？实测：

```lean
#print depZero
#check (depZero 3)
#check (depZero 7)
#eval (depZero 3)
#eval (depZero 7)
#print secondOf
```

实测输出（6 段）：

```
def depZero : (n : Nat) → Fin (n + 1) :=
fun n => 0                                  ← 定义体里**根本没有用到 n**！

depZero 3 : Fin (3 + 1)                     ← 类型跟着 n 变
depZero 7 : Fin (7 + 1)
0                                           ← 值不变
0

def secondOf : (α : Type) → (β : α → Type) → (p : (a : α) × β a) → β p.fst :=
fun α β p => p.snd                          ← 这里**用到了** p
```

（上面两个定义：`depZero` 是 **§4** 里定义的那个，`secondOf` 是**本节上面**定义的那个。）

**所以两件事要分开看：**

- **「依赖」不一定体现在值上。** `depZero` 的返回值**永远是同一个 `0`**——
  变的是**它的类型**：`Fin (3+1)`、`Fin (7+1)`……
- **你可能会想**：「那我岂不是需要一个『**取 `Fin (n+1)` 最小元**』的**通用办法**？」
  ——**这个直觉是对的**，只不过：**那个通用办法由 Lean 提供，不用你写**。
  你写下的 `0`，Lean 会**对每一个 `n`** 检查 `0 : Fin (n + 1)`（靠 §4 里说的那条规则）。
- **对照 `secondOf`**：那里的返回值 **`p.2` 确实用到了参数 `p`**——因为「第二分量」必须从 `p` 里取出来。
  所以 `secondOf` 是「**类型和值都依赖**」，而 `depZero` 是「**只有类型依赖**」。

> 📌 **一句话记住**：**类型可以依赖参数；值可以依赖，也可以不依赖。**
> 看到「返回类型里有参数」时，**不要**自动假设「返回值里也得写那个参数」。

## 6. 为什么叫「依赖」类型论？

**因为类型里可以出现值。**

- `Fin n` 里的 `n` 是**值**；
- `β a` 里的 `a` 是**值**；
- 于是 `Fin 3` / `Fin 5` **是不同的类型**，`β p.1` **要看 `p` 才能确定**。

对比一下你前八课学的（「**简单**类型论」）：

| | 简单类型论（2-1 ~ 2-8） | 依赖类型论（本课起） |
|---|---|---|
| `→` 右边 | 一个**固定**的类型（`Nat`、`Bool`、`List α`…） | **可以跟着左边的参数走**：`(n : Nat) → Fin (n + 1)` |
| `×` 右边 | 一个**固定**的类型 | **可以跟着第一个分量走**：`(a : α) × β a` |
| 类型能吃什么 | 类型（`List : Type → Type`） | **也能吃值**（`Fin : Nat → Type`） |

> 📌 **提前看一眼第 3 章**（**本课不引入**，只是让你知道它要来干什么）：
> 第 3 章会讲 `∀ x, P x`——那**就是**依赖函数类型 `(x : α) → P x`。
> 也就是说：**你这一课学的 `(a : α) → β a`，是第 3 章所有「全称量词」背后的东西。**

## 8. 小结

本课记住四件事：

1. **类型可以吃一个值**：`Fin : Nat → Type`，所以 `Fin 3` 与 `Fin 5` 是**两个不同的类型**。
2. **依赖函数类型 `(a : α) → β a`**：**返回值的类型依赖输入**；
   而 **`α → β` 就是 `β` 不依赖 `a` 时的这个写法**（实测两行输出一模一样）。
3. **依赖对类型（sigma）`(a : α) × β a`**：**第二个分量的类型依赖第一个分量**；
   `Σ a : α, β a` 是它的另一种写法，`⟨a, b⟩` / `Sigma.mk a b` 都能造。
4. **为什么重要**：第 3 章的 `∀`、`Fin n`、`Vector α n`——全都建立在「类型能吃值」之上。
