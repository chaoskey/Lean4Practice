> 本课只讲一件事：**`def` 到底是什么、它的句型有哪些门道。**（你从第 1 课起就一直在用它，这一课把它讲全。）

## 1. 本课的一句话

`def` 的作用是**给一个东西起名字**。它可以给一个**函数**起名字：

```lean
def double (x : Nat) : Nat := x + x
```

也可以给一个**值**起名字（下一节会看到）。

原文有一句话点得很准：**可以把 `def` 理解成「有名字的 `fun`」**（a kind of named `fun`）。这一课就是把这句听上去简单的话展开讲清楚。

---

## 2. 三种写法，同一个函数

同一个「把自然数翻倍」的函数，有三种写法（实测，`#eval` 全都得 `6`）：

```lean
def doubleA (x : Nat) : Nat := x + x      -- 参数写在 def 上
def doubleB : Nat → Nat := fun x => x + x -- 类型写全，右边是 fun
def doubleC := fun (x : Nat) => x + x     -- 类型全省，让 Lean 推
```

它们**是同一个函数**——这一点由 `#eval` 证明（下面三行是实测输出，都打印 `6`）。
但 `#check` 的**显示形状**有两种（也是实测输出）：

```lean
#check doubleA        -- doubleA (x : Nat) : Nat     ← 望远镜式
#check doubleB        -- doubleB : Nat → Nat         ← 箭头式
#check doubleC        -- doubleC (x : Nat) : Nat     ← 望远镜式

#eval doubleA 3       -- 6
#eval doubleB 3       -- 6
#eval doubleC 3       -- 6
```

⚠️ **注意这里「哪一点相同、哪一点不同」**：

- **相同的一点**：三个都是「吃一个 `Nat`、吐一个 `Nat`」的函数（类型都是 `Nat → Nat`）。
- **不同的一点**：`#check` 的**显示形状**不同——`doubleA` 与 `doubleC` 是望远镜式，`doubleB` 是箭头式。

为什么？**这正是 02-2 第 8 节讲过的那条规律**：显示形状取决于**类型里的 binder 有没有名字**。

- `doubleB` 的类型是我们**手写**的 `Nat → Nat`——里面没有名字，所以显示箭头式；
- `doubleA`（参数写在 `def` 上）与 `doubleC`（类型是 Lean 从 `fun (x : Nat) => ...` **推出来**的）的类型里**带着名字 `x`**，所以显示望远镜式。

> 💡 这条规律你已经在 02-2 见过一次；这里是它第二次出现。**它只影响显示，不影响含义。**

---

## 3. 一般句型：`def 名字 : 类型 := 表达式`

原文给的一般形式是：

```
def foo : α := bar
```

读作：**`α` 是右边那个表达式 `bar` 的类型**。逐段看：

| 片段 | 意思 |
|---|---|
| `def` | 「我要起个名字」 |
| `foo` | 起的名字 |
| `: α` | 这个名字的**类型** |
| `:=` | 「它的值就是……」 |
| `bar` | 一个**表达式** |

### 类型标注可以省，但**建议写**

原文说得很实在（我翻译）：

> Lean 通常能推出类型 `α`，但**把它明确写出来往往是个好主意**：
> 一是**表明你的意图**，二是**当右边的类型对不上时，Lean 会报错**。

第二点是实际好处——**写出来相当于给自己上了一个保险**。实测：如果你把类型写成 `Nat`，右边却给一个 `Bool`——**下面这段是故意写错的**（它会报错）：

```
def bad : Nat := true
```

Lean 会直接报错（实测原文，前面还有「文件:行:列:」的位置信息，我略掉了）：

```
error: Type mismatch
  true
has type
  Bool
but is expected to have type
  Nat
```

**不写类型就没有这个保险**：Lean 会照着你右边的东西推一个类型出来（比如推成 `Bool`），于是你的笔误就悄悄通过了。

> 💡 所以本课程建议：**类型标注尽量写**。省下来的几个字符，不值得换掉这个检查。

---

## 4. 等号右边可以是**任何表达式**，不只是 `fun`

原文强调：右边的 `bar` 可以是**任何表达式**，所以 `def` 也能用来**给一个值起名字**。

```lean
def pi := 3.141592654        -- 右边是一个小数

#check pi             -- pi : Float
#eval pi              -- 3.141593
```

- `Float` 是 Lean 内置的**小数类型**（就像 `Nat` 是自然数类型）。右边那个 `3.141592654` 就是它的值。
- `#eval pi` 打印 `3.141593`——小数显示时会截断位数，这里不重要，知道它是「那个数」就行。

右边当然也可以是**算式**：

```lean
def square (x : Nat) : Nat := x * x

#check square         -- square (x : Nat) : Nat
#eval square 4        -- 16
```

## 5. 多个参数：两种标注写法

```lean
def addA (x y : Nat) := x + y            -- 两个名字共用一个标注
def addB (x : Nat) (y : Nat) := x + y    -- 各自写自己的标注

#check addA           -- addA (x y : Nat) : Nat
#check addB           -- addB (x y : Nat) : Nat   ← 与上一行输出相同
```

**哪一点一样**：两个的**类型完全相同**（都是 `Nat → Nat → Nat`），因此 `#check` 打印出的形状也**完全相同**。

调用的时候，参数位置上**可以放表达式**（不必只是变量或数字）：

```lean
#eval addA 3 2        -- 5
#eval addB (doubleA 3) (7 + 9)   -- 22
```

第二行怎么读：先算 `doubleA 3`（得 `6`），再算 `7 + 9`（得 `16`），最后 `addB 6 16`（得 `22`）。

---

## 6. 参数也可以是**函数**

这和第 02-4 课第 8 节讲的是同一个东西，只是这次用 `def` 的句型写出来：

```lean
def doTwice (f : Nat → Nat) (x : Nat) : Nat := f (f x)

#check doTwice        -- doTwice (f : Nat → Nat) (x : Nat) : Nat
#eval doTwice doubleA 2   -- 8
```

`#eval` 那行怎么读：`doubleA` 是「翻倍」，`x = 2` → 先 `2 + 2 = 4`，再 `4 + 4 = 8`。

## 7. 本课最抽象的一节：`def` 起的名字与它的**定义**是什么关系

> 这一节是原文 2.4 的收尾，也是本课唯一需要慢慢读的地方。**看不懂可以只记住结论**（我会把结论单独框出来）。

先做一个实验：给 `Nat` 起个新名字。

```lean
def Natural := Nat

#check Natural        -- Natural : Type
```

注意 `#check` 的结果：`Natural : Type`。**Lean 没有把它显示成 `Nat`**——它保留了 `Natural` 这个名字。

再看一个更有意思的（实测）：

```lean
def idNat : Natural → Natural := fun n => n
#check idNat          -- idNat : Natural → Natural
```

`idNat` 的类型是「吃 `Natural`、吐 `Natural`」。**显示里保留的还是 `Natural`，不是 `Nat`。**

### 可是——把 `Nat` 的东西塞进去**却能通过**（实测）

```lean
def three : Nat := 3
#eval idNat three     -- 3
```

`three` 的类型是 `Nat`，而 `idNat` 要的是 `Natural`。**为什么可以？**

因为 Lean 在**必须判断「两个东西是否按定义相等」**时，会**展开** `Natural`——展开后它就是 `Nat`，于是对上了。

### 反过来，有些写法**会失败**（实测）

**下面这段是故意写错的**（它会报错）：

```
def five : Natural := 5
```

这一行**不通过**。Lean 的报错大意是：

```
failed to synthesize instance of type class
  OfNat Natural 5
numerals are polymorphic in Lean, but the numeral `5` cannot be used
in a context where the expected type is Natural
```

> ⚠️ **这条报错里的东西（「类型类」「数字是多态的」）本课不引入**——那是后面章节的内容。
> **你不需要看懂它。** 你需要的只是下面这个结论。

### 结论（本课要记住的一句话）

原文给这种性质起了个名字：`def` 起的名字是 **semireducible**（我译作「**半可归约**」）：

> **大多数场合 Lean 不展开它；只有在「必须判断两个东西是否按定义相等」时，才会展开。**

这解释了上面两个实验为什么结果不同：

| 实验 | Lean 需要做什么 | 结果 |
|---|---|---|
| `#eval idNat three` | 判断 `three` 的类型 `Nat` 与 `idNat` 要的 `Natural` **是否按定义相等** → **必须展开** | ✅ 通过 |
| `def five : Natural := 5` | 数字 `5` 要经过**类型类**机制去找「`Natural` 上的数字」→ **这条路径不展开** `Natural` | ❌ 失败 |

**为什么「数字」这条路径不展开，而「判断相等」会展开**——这属于类型类的机制，**本课不引入**，知道有这回事即可。

> 💡 这条「半可归约」的性质，第 3 章讲**证明相等**（`=` 与 `rfl`）时会**直接用到**：
> `rfl` 能证明的东西，正是「展开后两边是同一个东西」的那些。所以今天先把它记个脸熟。

## 8. 本课**不**引入的东西（明确标出来，别在这里卡住）

原文 2.4 里有两个例子**本课不引入**：

1. **`if ... then ... else ...`（条件判断）**：原文用 `def greater (x y : Nat) := if x > y then x else y` 演示「右边可以是更复杂的表达式」。
   **本课不引入 `if`**——它背后是 Lean 的**类型类**机制（后面章节才讲）。想看「右边可以放复杂表达式」，用第 4 节的 `square`（`x * x`）就够了。
2. **把「类型」当参数**：原文有 `def compose (α β γ : Type) (g : β → γ) (f : α → β) (x : α) : γ := g (f x)`。
   它要理解 `(α β γ : Type) → ...` 这种**依赖积**类型，属于本项目 **2-9（依赖类型）** 一带——**02-4 那一课我就把它推迟了，本课继续推迟。**

> 这两样都会在它们自己的课里从头讲。**现在跳过它们，不影响本课的任何内容。**

## 9. 小结

本课记住四件事：

1. **`def` 就是「有名字的 `fun`」**：`def doubleA (x : Nat) : Nat := x + x` 与 `def doubleB : Nat → Nat := fun x => x + x` **是同一个函数**（`#eval` 都是 `6`）。
2. **句型是 `def 名字 : 类型 := 表达式`**，`α` 就是右边表达式的类型；**类型可以省，但建议写**——写清楚意图，而且**右边类型对不上时 Lean 会报错**（不写就没这个保险）。
3. **右边可以是任何表达式**，不只是 `fun`：所以 `def` 也能给**值**起名字（`def pi := 3.141592654`）。
4. **`def` 起的名字是「半可归约」**：大多数场合**不展开**，只有**必须判断两个东西是否按定义相等**时才展开。这条第 3 章会用到。
