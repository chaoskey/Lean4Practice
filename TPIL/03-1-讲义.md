> **本课的一句话**：**命题就是类型，证明就是项。**

## 1. 本课的一句话

前 10 课你学的都是「**写定义**」。从这一课起你要**写证明**——但在那之前，
本课先回答一个更基础的问题：**在 Lean 里，「一个命题」和「一个证明」到底是什么东西？**

答案（本课的核心）：

| | 是什么 |
|---|---|
| **命题** | **一个类型**（`p : Prop`——`Prop` 也是类型，只是「装着命题」的那一层） |
| **证明** | **这个类型的一个项**（`t : p`——读作「`t` **是** `p` 的一个证明」） |

⚠️ 本课**不写证明**（那是下一课 3-2 的事）。本课是**把地基铺好**：
搞清这一点，下一课的第一个证明你才看得懂。

---

## 2. 我们**本可以**另造一套「断言语言」

原文开头先讲了一个**反面方案**（我翻译并拆细）：

> 想证明「关于对象的一些断言」，有一种策略是：**在「定义语言」之上，再叠一层「断言语言」和「证明语言」**。
> 但**没有理由让语言翻倍**：依赖类型论足够灵活、足够有表达力，**完全可以把「断言」和「证明」都放进同一个框架里**。

那个反面方案长这样（**下面前两段是原文的示意图，本课不引入 `structure` / `axiom`**，
你**只要看懂意思**，不必会写）：

```lean
def Implies (p q : Prop) : Prop := p → q
```

（`Prop` 是 Lean 里「装着命题」的那个类型——**02-3** 学过 `Prop` 与 `Type` 的区别。）

那个方案会接着说：「再为每个命题 `p` 配一个类型 `Proof p`，放它的证明」，
然后**用公理（`axiom`）**把推理规则塞进去，比如：

- **肯定前件（modus ponens）**：有 `Implies p q` 的证明、又有 `p` 的证明 → 得到 `q` 的证明；
- **蕴含引入**：假设 `p` 成立时能推出 `q` → 就得到 `Implies p q` 的证明。

> ⚠️ **本课不引入**：`structure`（**第 7 章**）、`axiom`（Lean 里能用，但**很危险**，
> 原文自己也说它「可能破坏一致性」）。上面这段**只是让你知道「本来可以那样做」**。

---

## 3. 省掉一半：把「命题 `p`」**直接当成类型**

原文接着做了两步简化（我翻译）：

> 1. 我们可以**不再反复写 `Proof`**——干脆把 **`Proof p` 和 `p` 本身合并**。
>    换句话说：**每当有 `p : Prop`，就把 `p` 当成一个类型**——**它的证明们的类型**。
>    于是 **`t : p`** 就可以读作「**`t` 是 `p` 的一个证明**」。
> 2. 而且做了这个合并之后，蕴含的规则正好说明：**`Implies p q` 和 `p → q` 可以来回换**。

**第 2 点就是本课最漂亮的一步**：

> **蕴含「`p` 推出 `q`」，就是「有一个函数，把 `p` 的任意元素变成 `q` 的元素」。**
> 所以 `Implies` 这个构造子**完全是多余的**——**直接用函数类型 `p → q` 当蕴含就行**。

实测（**`→` 两边都是命题，结果还是命题**）：

```lean
variable (p q r : Prop)

#check (p → q)
```

实测：

```
p → q : Prop
```

也就是说：**`→` 这个记号你早就用熟了**（02-2 学的「函数类型」），
从本课起它**多了一个身份**——**它同时就是逻辑里的「蕴含」**。

---

## 4. 这个对应关系有个名字：**Curry–Howard 同构**

原文（我翻译）：

> 自然推理系统里「蕴含」的规则，**恰好**对应函数里「抽象（`fun`）」和「应用（把函数作用到参数上）」的规则——
> 这个事实是 **Curry–Howard 同构**的一个实例，也叫「**命题即类型**（propositions-as-types）」范式。

**用一句话说清这个「恰好对应」**（本课的核心对照表）：

| 逻辑 | 类型论 |
|---|---|
| 命题 `p` | 类型 `p` |
| `p` 的证明 | 类型 `p` 的一个**项**（元素） |
| 「`p` 推出 `q`」（蕴含 `p → q`） | **函数类型** `p → q` |
| 「假设 `p` 成立」（引入前提） | **`fun` 抽象**一个 `p` 的参数 |
| 「用上一条已知的 `p`」（使用前提） | 把函数**应用**到那个项上 |

实测**同一个 `fun`，两种身份**：

（`p` 就是 **§3** 用 `variable` 声明的那个命题。）

```lean
#check (fun (x : Nat) => x)
#check (fun (hp : p) => hp)
```

实测（2 行）：

```
fun x => x : Nat → Nat
fun hp => hp : p → p
```

**两行的形状一模一样**——区别只在 `Nat` 是**数据类型**、`p` 是**命题**。
第一行是「恒等函数」，第二行是「**`p` 蕴含 `p` 的一个证明**」（下一课 3-2 就拿它当第一个证明）。

## 5. `Prop` 与 `Sort 0`（**标注：本课不引入**）

原文提到（我翻译）：

> 实际上，类型 **`Prop` 是 `Sort 0` 的语法糖**——也就是上一章讲的类型层级里**最底的那一层**；
> 而 **`Type u` 也只是 `Sort (u+1)` 的语法糖**。`Prop` 有一些特殊性质，但**和其他类型层级一样，它对箭头构造子是封闭的**：
> 如果有 `p q : Prop`，那么 **`p → q : Prop`**。

- **`p → q : Prop` 这一点**：上面 §3 已经实测过了 ✓（**这是本课真正要记的**）；
- ⚠️ **`Sort` / `universe` / `Type u` 属宇宙多态 —— 还没有归属的课，本课不引入**。
  你只要知道 **`Prop` 是「命题所在的那一层」**就够了。

## 6. 两种理解方式（挑一个你喜欢的）

原文说，「命题即类型」至少有**两种**看法——**哪一种都行**，但要知道有两种（我翻译）：

**① 构造主义（constructive）的看法**：

> 对某些人（持构造主义逻辑观的人）来说，这**忠实地刻画了「什么是一个命题」**：
> 命题 `p` 表示**一种数据类型**，即「**构成 `p` 的一个证明的数据**长什么样」的规格说明。
> 于是 `p` 的一个证明，就**只是一个类型正确的对象** `t : p`。

**② 「编码技巧」的看法**：

> 不认同这套哲学的人，可以把它看成**一个简单的编码技巧**：
> 给每个命题 `p` 配一个类型——**`p` 假的时候这个类型是空的**；
> **`p` 真的时候它恰好有一个元素**（就叫它 `*`）。
> 后一种情况下，我们说（与 `p` 对应的）这个类型是「**有居民的**（inhabited）」。

**两者共同的操作要点**（这才是你写证明时真正用到的）：

- **造出一个 `t : p`**，就等于**证明了 `p` 为真**；
- 你可以把 `p` 的那个「居民」想成「**`p` 为真这个事实**」；
- 而 `p → q` 的一个证明，就是**用「`p` 为真这个事实」得到「`q` 为真这个事实」**。

## 7. 证明无关（proof irrelevance）

原文（我翻译）：

> 如果 `p : Prop` 是任意命题，Lean 的内核把**任意两个元素 `t1 t2 : p` 当作「按定义相等」**——
> 就像它把 `(fun x => t) s` 和 `t[s/x]`（代入）当作按定义相等一样。这叫做 **proof irrelevance（证明无关）**。
> 它意味着：**即使我们可以把证明 `t : p` 当成语言里的普通对象，它也不携带「`p` 为真」以外的任何信息。**

**直白地说**：

- 同一个命题 `p`，**不管你怎么证出来的**，Lean 认为那些证明**是相等的**（证明之间没有「不一样」可言）；
- 所以证明**只是「一个记号」**，告诉我们「**这个命题成立**」——它没有别的用处。

**这条对你写证明的实际影响**（很重要）：

| 影响 | 说明 |
|---|---|
| 证明不必「抄」下来 | 用到某个定理时，知道**它成立**就够了（不必关心它是怎么证的） |
| `theorem` 与 `def` 有一点不同 | 原文：Lean 把证明**标成「不可展开」（irreducible）**，因为**没人需要展开一个证明** |
| 也是「并行检查证明」的前提 | 原文：检查一个证明，**不需要知道另一个证明的细节** |

> 📌 这解释了原文的一句：`theorem` **本质上就是 `def`**（下一课 3-2 会实测 `#print t1` 看到证明长什么样）——
> 对内核来说两者没区别，**实用差别**在于上面这些。

## 8. 本课你要动手的：用 `#check`「看穿」命题

本课的习题里，你会自己跑这些命令。先在这里把**要看的东西**说清（**输出留给你自己核对**）：

```lean
#check And
#check Or
#check Not
#check True
#check False
```

**你要从输出里看出两件事**：

1. **`And` / `Or` / `Not` 都是「吃 `Prop`、吐 `Prop`」的东西**——它们**是函数**（类型层级的函数）；
2. **`∧` / `∨` / `¬` 只是「函数形式」的记号**——就像 02-2 里 `×` 是 `Prod` 的记号那样。

**这一条是重点**：`p ∧ q` 和 `And p q` **是同一个东西**，只是**写法不同**（Lean 打印时用记号）。
下一课 3-2 起你会看到：**证明里常常要在「记号形式」和「函数形式」之间来回换**。

## 10. 小结

本课记住四件事：

1. **命题 = 类型**：`p : Prop` 就**当类型**读；**证明 = 项**：`t : p` 读作「`t` 是 `p` 的一个证明」。
2. **蕴含 = 函数**：`p → q` **就是**「把 `p` 的元素变成 `q` 的元素的函数」——
   **`→` 从本课起有两个身份**（函数类型 / 蕴含），它们是**同一件事**（**Curry–Howard 同构**）。
3. **`Prop` 对箭头封闭**：`p q : Prop` ⟹ **`p → q : Prop`**（实测：`p → q : Prop`）。
4. **证明无关**：同一个命题的任意两个证明，Lean 认为**按定义相等**——证明**不携带「命题为真」以外的信息**。
