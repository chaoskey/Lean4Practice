## 1. 本课的一句话

`let` 的作用是：**在一个表达式内部，给某个东西起一个临时的名字。**

最基本的例子（下面两行是实测输出）：

```lean
#check let y := 2 + 2; y * y
-- 打印（两行）：
--   let y := 2 + 2;
--   y * y : Nat

#eval let y := 2 + 2; y * y       -- 16
```

先别管那些符号，把它读成一句话：

> 「先让 `y` 代表 `2 + 2`；然后计算 `y * y`。」

原文把 `let` 的含义说得非常干脆（我翻译）：

> `let a := t1; t2` 这个表达式，**按定义等于**「把 `t2` 里出现的每个 `a` 都换成 `t1`」之后的结果。

拿上面的例子对照：把 `y * y` 里的 `y` 都换成 `2 + 2`，得到 `(2 + 2) * (2 + 2)`，算出来是 `16`
—— 这正是 `#eval` 打印的东西。

> 💡 「按定义等于」这个说法你在 **02-5 第 7 节**已经见过一次（当时讲的是 `def` 的半可归约）。
> 那里我们说 `three : Nat` 能塞进要 `Natural` 的地方，靠的就是「按定义相等」。本课会看到
> `let` 在这一点上和 `def` **不一样**——见第 3 节。

## 2. 基本句型

```
let 名字 := 表达式1; 表达式2
```

逐段读：

| 片段 | 意思 |
|---|---|
| `let` | 「我要在这里临时起个名字」 |
| `名字` | 起的名字（这里叫 `y`；你想叫什么叫什么） |
| `:=` | 「它代表……」 |
| `表达式1` | 这个名字代表的东西 |
| `;` | 「名字起完了，下面是正文」 |
| `表达式2` | **整个表达式的值，就在这一段里** |

⚠️ **最容易看错的地方**：**`;` 后面那一段才是「整个表达式的值」。**

`let y := 2 + 2; y * y` 从头到尾是**一个表达式**（不是两条命令），它的值就是 `16`。
`y` 只在**这个表达式内部**（也就是 `;` 后面那段）有效——出了这个表达式就没了。
这就是「**局部**定义」这个名字的来历。

## 3. `let` 的名字与 `def` 的名字，差在哪

这是本课最该分清的一件事。两者都叫「起名字」，但差别有两处：

| | `def` 起的名字（02-5） | `let` 起的名字（本课） |
|---|---|---|
| **活在哪里** | **整个文件**：写在它后面的地方都能用 | **只在这一个表达式里**：`;` 后面那段 |
| **和右边的表达式是什么关系** | **半可归约**：大多数场合**不展开**，只在**必须判断「两个东西是否按定义相等」**时才展开 | **就是替换**：把名字**换掉**即可，不需要「展开」这一步 |

第二条是原文的原话（「每个 `a` 都是一个**语法缩写**」）。用数字直观地看（实测，两个都是 `16`）：

```lean
#eval let y := 2 + 2; y * y       -- 16
#eval (2 + 2) * (2 + 2)           -- 16   ← 把 y 替换掉，得到的就是它
```

**哪一点一样**：两行的**值**一样（都是 `16`）。
**哪一点不一样**：左边你起了个名字，右边没有名字——但**名字只是缩写**，替换完就是右边。

> 💡 对照 02-5 第 7 节的 `def Natural := Nat`：那里的名字**不会**被随手替换成 `Nat`
> （`#check idNat` 显示的还是 `Natural`）；而 `let` 的名字，按定义就等于它右边那串。
> **记住这一点，本课第 7 节要靠它。**

## 4. 在 `def` 里用 `let`（本课最常用的场合）

`let` 真正的用武之地是**在函数体里**给中间结果起名字，免得同一串东西写两遍：

```lean
def twice_double (x : Nat) : Nat :=
  let y := x + x; y * y

#check twice_double     -- twice_double (x : Nat) : Nat
#eval twice_double 2    -- 16
```

读法：`x = 2` → `y` 代表 `2 + 2`（也就是 `4`）→ 算 `4 * 4` → `16`。

原文还给了一句结论（我翻译）：

> 这里的 `twice_double x`，**按定义等于** `(x + x) * (x + x)`。

—— 也就是第 1 节那条「替换」的规律：把 `y` 换成 `x + x`，就是右边这串。**这就是 `let` 的全部含义。**

### 分号可以换成换行

原文说：**用了换行的时候，`;` 可以省掉。** 下面这个定义与上面的 `twice_double` 是同一个东西：

```lean
def t (x : Nat) : Nat :=
  let y := x + x
  y * y

#eval t 2               -- 16
```

**哪一点一样**：两个函数的**值**一样（`#eval` 都得 `16`）。
**哪一点不一样**：只是排版——`twice_double` 用 `;` 把 `let` 和正文写在同一行；`t` 用换行分开。

> 💡 写长的函数体时用换行更清楚。**本课习题会两种都让你写一遍。**

## 5. 一次起好几个名字；名字撞车了怎么办

`let` 可以**串联**：前面起好的名字，后面的 `let` 可以直接用（实测）：

```lean
#eval let y := 2 + 2; let z := y + y; z * z    -- 64
```

读法：`y` 代表 `4` → `z` 代表 `4 + 4`（也就是 `8`）→ `8 * 8 = 64`。

**再看一个例子：如果第二次起的名字与第一次相同呢？**（实测）

```lean
#eval let y := 1; let y := y + 10; y           -- 11
```

结果是 `11` 而不是 `1`，也不是 `21`。为什么？规则是：

> **第二个 `let` 右边那个 `y`，指的是「前一个 `y`」；从这个 `let` 往后，`y` 才指新的那个。**

所以 `let y := y + 10` 里的 `y` 是 `1`，算出 `11`；最后那个 `y` 指的是新的 `y`（`11`）。

> 💡 名字撞车（术语叫 shadowing，遮蔽）在 Lean 里**是允许的**，规则就是上面这一条：
> **右边看旧的，往后看新的。** 但为了别人（和将来的你）好读，**能不撞就不撞**。

## 6. `#check` 看到 `let` 时会显示成什么（速查）

这一节专门治「猜错显示形状」这个老毛病——**照下面查，不用猜**。

```lean
#check let y := 2 + 2; y * y
-- 打印（两行）：
--   let y := 2 + 2;
--   y * y : Nat
```

三条规律（都是实测）：

1. **`let` 会被原样显示**：名字 `y`、右边的写法 `2 + 2` 都保留。
   ⚠️ **右边的 `2 + 2` 不会被算成 `4`**——`#check` 只问类型，不做计算。
2. **类型写在最后**：这里是最末尾那个 `: Nat` 里的 `Nat`（意思是「整个表达式的类型是 `Nat`」）。
3. **你手写的类型标注不显示**。看下面这个（实测）：

```lean
#check let n : Nat := 5; n + 1
-- 打印（两行）：
--   let n := 5;
--   n + 1 : Nat
```

我写的是 `let n : Nat := 5`，但打印出来是 **`let n := 5;`（那个 `: Nat` 不见了）**。

**速查表**：

| 你写的 | `#check` 打印成（两行） |
|---|---|
| `let y := 2 + 2; y * y` | `let y := 2 + 2;` ⏎ `y * y : Nat` |
| `let n : Nat := 5; n + 1` | `let n := 5;` ⏎ `n + 1 : Nat`（**手写的 `: Nat` 不显示**） |

> 💡 顺带一个好习惯：**要猜输出，就先把「名字」和「右边的写法」分开想**
> ——「名字保留、右边不计算」这两条能解决本课的绝大多数显示问题。

## 7. 本课最抽象的一节：`let` 与 `fun` **不是**一回事

> 这一节对应原文 2.5 的收尾。**看不懂可以先只记结论**（我会把结论单独框出来）。

原文说：`let a := t1; t2` 的含义，和 `(fun a => t2) t1` **很像，但两者不是同一样东西**。
并且留了一道思考题：**为什么下面 `foo` 能通过，而 `bar` 不能？**

能通过的那个（实测）：

```lean
def foo := let a := Nat; fun x : a => x + 2

#check foo        -- foo (x : Nat) : Nat
#eval foo 3       -- 5
```

不能通过的那个——**下面这段是故意写错的**：

```
def bar := (fun a => fun x : a => x + 2) Nat
```

Lean 报的错（实测原文，前面还有「文件:行:列:」的位置信息，我略掉了）：

```
error(lean.synthInstanceFailed): failed to synthesize instance of type class
  HAdd a Nat (?m.17 a x)
```

> ⚠️ **这条报错里的东西（「类型类」`type class`、`HAdd`、`?m.17`）本课不引入**——
> 那是后面章节的内容。**你不需要看懂它。**

### 为什么一个通过、一个不通过

关键只有一句话：**`foo` 里的 `a` 是「缩写」，`bar` 里的 `a` 是「变量」。**

- **`foo` 能通过**：`let a := Nat` 的意思是「**`a` 就是 `Nat` 的缩写**」。
  Lean 检查 `fun x : a => x + 2` 时，把 `a` **换掉**成 `Nat`，于是它检查的其实就是
  `fun x : Nat => x + 2`（02-4 学过的东西）—— **说得通**。所以 `#check foo` 打印的是 `foo (x : Nat) : Nat`。

- **`bar` 不通过**：这里的 `a` 是 `fun` 的**参数**，也就是一个**变量**。
  Lean 检查 `fun a => ...` 这个函数体的时候，**不能**拿外面的 `Nat` 去替换 `a`
  —— 因为 `fun a => ...` 必须**对任何 `a` 都说得通**（你根本不知道调用者会塞什么类型进来）。
  而 `x + 2` 对**任意**的 `a` 说不通：**Lean 不知道 `a` 这个类型上有没有加法。**
  于是它报错。

### 结论（本课要记住的一句话）

> **`let` 起名字是「替换」（语法缩写）：名字按定义就等于右边那串。
> `fun` 的参数是「变量」：函数体必须对参数的任意取值都说得通。
> 所以 `let a := t1; t2` 与 `(fun a => t2) t1` 看着像，却**不是**同一样东西。**
> ——当 `t2` 的合理性**依赖于 `a` 具体是哪个东西**时（像 `foo` 这样），两者就分道扬镳了。

> 💡 这也解释了原文那句「有些 `let a := t1; t2` 写不成 `(fun a => t2) t1`」：
> `foo` 就是这样一个例子——它能写成 `let`，却写不成 `fun`。

## 9. 小结

本课记住四件事：

1. **`let` 是「表达式内部」的临时命名**：句型 `let 名字 := 表达式1; 表达式2`，
   其中 **`;` 后面那段才是整个表达式的值**；**换行可以代替 `;`**。
2. **`let` 的名字按定义就等于右边那串**（把名字**替换**掉即可）——这是它与 `def` 的
   「半可归约」（02-5 第 7 节）最本质的差别；另外 `def` 的名字活在**整个文件**里，`let` 只活在**这一个表达式**里。
3. **`#check` 把 `let` 原样显示**：名字保留、**右边不计算**、**手写的类型标注不显示**。
4. **`let` 与 `(fun a => t2) t1` 不是一回事**：`let` 是**替换**，`fun` 的参数是**变量**
   —— 这就是为什么原文的 `foo` 能通过、`bar` 不能。
