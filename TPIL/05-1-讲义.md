>
> **本课一句话**：**写证明换一种方式**——不再一口气交出「那一整项」，而是给一串「做什么」的**指令**；

>

> 但**证明项不白学**：§6 会实测给你看——tactic 证明最后生成的**就是证明项**。

## §1 一件大事：换一种写证明的方式

**前 4 章的写法**：证明就是**一个项**。比如 04-1 那种：

```lean
theorem and_swap (p q : Prop) (hp : p) (hq : q) : q ∧ p :=
  ⟨hq, hp⟩
```

`⟨hq, hp⟩` 是一个**项**——它的类型是 `q ∧ p`，所以它能当这一格的答案。
这种写法叫**项模式**（term mode）：**你一次性把答案写出来**。

**它的毛病**：写的时候你看不见「**目标是什么**」「**手头有哪些假设**」。
短证明无所谓；一长，就容易写出一个类型对不上的项，然后对着一大串报错猜是哪一步错了。

**Lean 给的第二种写法**：在**任何需要一个项的地方**，都可以改写

```text
by
  <一串 tactic>
```

这叫**tactic 模式**：你不再直接给答案，而是给一串**指令**；
Lean 每执行一条指令，就把「现在的目标」更新一次，**你可以随时看它变成什么样**。

> ⚠️ **两条必须一开始就分清的事**（本课后面都会实测）：
>
> 1. **tactic 证明最后生成的还是项。** 不是换了一套逻辑，只是换了「写的方式」——§6 用 `#print` 证明给你看。
> 2. **第 2～4 章学的东西照样要用。** `And.intro`、`h.left`、`fun x => …` 这些**项**，
>    正是你交给 `apply` / `exact` 的**材料**。tactic 不替你思考，它只是帮你**一步步装配**。

## §2 目标（goal）：tactic 每一步都在对付的东西

**目标**由两部分组成：

- **假设**：**手头有的**东西（变量、前提）；
- **要证的**：写作 **`⊢ `** 后面那个类型。

**实测**：把证明写成 `_`（第 04-8 课讲过，`_` 是「洞」——让 Lean 自己填），Lean 会告诉你它填不出来，**顺便把目标原样打给你**：

下面这段**故意不完整**（所以不能放在 ```lean 块里跑，会报错）：

```text
theorem goal_demo (p q : Prop) (hp : p) (hq : q) : p ∧ q ∧ p := _
```

实测输出（**逐字**）：

```text
don't know how to synthesize placeholder
context:
p q : Prop
hp : p
hq : q
⊢ p ∧ q ∧ p
```

**怎么读**：

- `p q : Prop` —— 「`p`、`q` 是**命题**」（`Prop` 是 2-3 课学的「命题的类型」）；
- `hp : p` —— 「手上有一样东西叫 `hp`，它的类型是 `p`」（也就是**一个 `p` 的证明**）；
  `hq : q` 就是「一个 `q` 的证明」；
- `⊢ p ∧ q ∧ p` —— **要证的是** `p ∧ q ∧ p`。

> ⚠️ **`⊢` 不是你要往文件里写的东西。** 它只是 Lean **显示目标**时的记号（读作「要证」）。
> 文件里永远不会出现 `⊢`。

**tactic 必须缩进**（实测，别踩）：`by` 后面的 tactic 要**比所在声明的开头更深**，
否则 Lean 认为 `by` 已经结束，后面的东西被当成新命令：

```text
theorem bad (p q : Prop) (hp : p) (hq : q) : p ∧ q := by
apply And.intro
exact hp
exact hq
```

实测报错（**逐字**，「expected command」这个说法很难看出真因，记住它对应的就是缩进）：

```text
error: unsolved goals
p q : Prop
hp : p
hq : q
⊢ p ∧ q
error: unexpected identifier; expected command
```

**怎么看目标**：在 VS Code 里，把光标放在 `by` 块中间，右侧 **Infoview** 就会显示**当前**目标
（用 `Ctrl+Shift+Enter` 可以把消息窗口打开）。本项目的检查命令 `lake env lean` 则**只在报错时**才把目标印出来。

> 📌 所以「看目标」有两条路：**编辑器里随时看**，或者**故意写不完整，让报错告诉你**。
> 后者本课会一直用（因为它能逐字抄进材料，方便你对照）。

## §3 第一个 tactic：`exact`

**`exact 项`** 的意思是：**「就用这个项来交差」**。
要求：这个项的**类型就是目标**（允许「定义相等」，即算一算能对上）。

```lean
theorem s3_exact (p q : Prop) (hp : p) (hq : q) : q ∧ p := by
  exact And.intro hq hp
```

扎实起见，看它生成的项（`#print`，实测）：

```text
theorem s3_exact : ∀ (p q : Prop), p → q → q ∧ p :=
fun p q hp hq => ⟨hq, hp⟩
```

（`#print` 的印法：定理的**参数被 Lean 打包进类型**，`p q : Prop` 与 `hp hq` 都变成了 `→`；
这正是 04-1 学的「`∀` 就是函数类型」。**第 05-2 课**会讲 `intro`，到时候这个形状就是你自己拼出来的。）

**给错了会怎样**（实测）：假设 `h : p → q`，目标是 `q`，你写 `exact h`：

```text
error: Type mismatch
  h
has type
  p → q
but is expected to have type
  q
```

读法：`has type` 后面是**你给的项**的类型，`expected` 后面是**目标**。
两者对不上——因为你交的是一把「还没上膛的枪」（`p → q`），而不是一颗「子弹」（`q`）。

> 💡 原文强调：**收尾时偏爱 `exact`**。因为它失败时**明明白白**（类型对不上就说对不上），
> 不会像 `apply` 那样偷偷替你留下一些你没想要的目标。

## §4 第二个 tactic：`apply`

**`apply 项`** 的意思是：**「用这个项来交差，但它还缺的参数，先欠着、变成新目标」**。

换个说法（本课最有用的一句）：**把项看成函数**——`apply` 拿它的**最终返回类型**去和**目标**对上；
对得上就把它**还缺的参数**，按顺序变成**新的目标**。

### §4.1 最小的例子

`h : p → q` 可以看成一个函数：**喂它一个 `p`，它吐一个 `q`**。
目标就是 `q`，于是「用 `h` 交差，还缺一个 `p`」：

```lean
theorem s4_apply (p q : Prop) (hp : p) (h : p → q) : q := by
  apply h
  exact hp
```

实测：`apply h` 之后的**当前目标**变成

```text
p q : Prop
hp : p
h : p → q
⊢ p
```

（注意 `h` **还在**上下文里——`apply` 只是「预约」用它，并不会把它消耗掉。）

### §4.2 `apply And.intro`：一次留下两个目标

```lean
theorem s4_two (p q : Prop) (hp : p) (hq : q) : p ∧ q ∧ p := by
  apply And.intro
  exact hp
  apply And.intro
  exact hq
  exact hp
```

`And.intro` 要两个参数（左、右），所以 `apply And.intro` 一次欠**两个**。
实测（写到这里故意停住）报出的目标（**逐字**）：

```text
case left
p q : Prop
hp : p
hq : q
⊢ p

case right
p q : Prop
hp : p
hq : q
⊢ q ∧ p
```

**三个要点**：

1. **顺序**：`And.intro` 的参数是「先左后右」，所以留下的目标也是**先 `p`、后 `q ∧ p`**。
2. 第二个目标是 `q ∧ p`、**不是**「`q` 和 `p` 两个」——这是因为 **`∧` 是右结合的**（04-6 学过：
   `p ∧ q ∧ p` 其实是 `p ∧ (q ∧ p)`），所以右边那一整块是**一个**目标，将来还要再 `apply And.intro` 一次。
3. `case left` / `case right` 这两行是**目标的名字**——**第 05-7 课**才讲怎么用它们；
   现在只要知道「那是 Lean 给每个目标起的标签」，**本课不看它**。

### §4.3 `apply` 后面可以给复合表达式

不必只给一个名字，给**任何项**都行：

```lean
theorem s4_compound (p q : Prop) (hp : p) (hq : q) : p ∧ q := by
  apply And.intro hp
  exact hq
```

`And.intro hp` 的类型是 `q → p ∧ q`——**还缺一个 `q`**，所以还有一个子目标。

### §4.4 `apply` 和 `exact` 什么时候一样？

- `exact e` 要求 **`e` 的类型就是目标**。
- `apply e` 允许 **`e` 的类型是「目标」或者「… → … → 目标」**（缺的参数变子目标）。

所以：**当 `e` 的类型恰好就是目标时，两者都能一步收工**。实测——下面两段都能通过：

```lean
theorem s4_eq_apply (p q : Prop) : p → q → p ∧ q := by
  apply And.intro

theorem s4_eq_exact (p q : Prop) : p → q → p ∧ q := by
  exact And.intro
```

（原因见**题 6**：`And.intro` 的完整类型是 `∀ {a b : Prop}, a → b → a ∧ b`，
取 `a := p`、`b := q`，它**恰好就是**目标 `p → q → p ∧ q`。）

### §4.5 `apply` 对不上时说什么

实测（`hq : q`，目标 `p ∧ q`，写 `apply hq`）：

```text
error: Tactic `apply` failed: could not unify the type of `hq`
  q
with the goal
  p ∧ q
```

`could not unify` =「**对不上**」。`apply` 的报错通常比 `exact` 冗长——上面这段后面还会**再附一遍当前目标**
（实测里是 `p q : Prop` / `hp : p` / `hq : q` / `⊢ p ∧ q`），这里从略；
所以**收尾还是 `exact` 干净**。

## §5 目标不止一个时：tactic 按顺序，一个一个解

- 每条 tactic 只作用于 **当前目标**——也就是目标列表里**第一个**那个；
- 解掉一个，**第二个自动变成当前目标**；解完所有目标，`by` 块才算完成。
- 还剩目标就报 `unsolved goals`（§2 的 `_`、§4.2 的「故意停住」都是这一种）。

所以你写 tactic 的顺序，就是**目标被解决的顺序**。§4.2 那段能通过，正是因为：
`apply And.intro` 留下「先 `p` 后 `q ∧ p`」→ `exact hp` 解掉第一个 →
现在当前目标是 `q ∧ p` → `apply And.intro` 再拆成「先 `q` 后 `p`」→ 两个 `exact` 收尾。

## §6 `#print`：tactic 证明 ⇄ 证明项

这是本课最该记住的一件实测。下面两段，一个是**项模式**，一个是**tactic 模式**，
证明的都是 `q ∧ p`：

```lean
theorem s6_term (p q : Prop) (hp : p) (hq : q) : q ∧ p :=
  ⟨hq, hp⟩

theorem s6_tactic (p q : Prop) (hp : p) (hq : q) : q ∧ p := by
  apply And.intro
  exact hq
  exact hp

#print s6_term
#print s6_tactic
```

实测输出（两条 `#print` 的输出**逐字相同**）：

```text
theorem s6_term : ∀ (p q : Prop), p → q → q ∧ p :=
fun p q hp hq => ⟨hq, hp⟩
theorem s6_tactic : ∀ (p q : Prop), p → q → q ∧ p :=
fun p q hp hq => ⟨hq, hp⟩
```

**结论**：**tactic 只是「写证明项」的另一种语法**。碰到看不懂的 tactic 证明，
`#print 名字` 就能把它打回成你第 2～4 章熟悉的形状。
（`#print axioms 名字` 也照样能用——本课示例文件里六条全是 `does not depend on any axioms`。）

## §7 `sorry`：先欠着的 tactic

`by` 里面也可以写 `sorry`——意思和项模式的 `sorry` 一样：**「这一格我先欠着」**。
它的作用是**先搭骨架、看目标**。编译时**只报 warning，不报错**：

```text
warning: declaration uses `sorry`
```

⚠️ 两条相关的项目约定（`AGENTS.md` §6.15）：

- `sorry` 只是 **warning**，**退出码仍是 0**——所以「能过编译」**不等于**「题做完了」；
- 本课程的习题文件用 `sorry` 占位，验收脚本靠「**整行就是 `sorry`**」来数还有几题没做。
  所以**`sorry` 必须单独占一行**。

## §10 一页速查

| 写法 | 意思 |
|---|---|
| `:= by` ＋ 缩进的若干行 | 进入 tactic 模式（tactic 必须**缩进**） |
| 目标 `⊢ X` | 「要证 `X`」；上面是假设，下面是目标（`⊢` 只是显示记号，不写进文件） |
| `exact e` | 用 `e` 交差；要求 `e` 的类型**就是**目标 |
| `apply e` | 用 `e` 交差；`e` **还缺的参数**按顺序变成新目标 |
| `sorry` | 先欠着（warning，不是 error；必须单独占一行） |
| `#print 名字` | 把 tactic 证明打回成**证明项** |
