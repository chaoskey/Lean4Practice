# 第 2 章 · 第 7 课：变量与区段（`variable` / `section`）

> 📄 **示例**：`02-7-示例.lean`（我写的，已通过编译、零 warning）
> ✍️ **习题**：`02-7-习题.lean`（**你写**）
> 📖 **原文**：<https://lean-lang.org/theorem_proving_in_lean4/Dependent-Type-Theory/#variables-and-sections> 的 **2.6** 小节（想深挖时再看；**读不懂不影响本课**）
> 本课只讲一件事：**同一个参数在好几个定义里反复出现，怎样只写一次。**

---

## 1. 本课的一句话

- **`variable`**：把「反复出现的参数」**声明一次**，之后定义里**直接用这个名字**——Lean 会**自动把它变成参数**。
- **`section`**：用来**限定 `variable` 的作用范围**（到 `end` 为止）。

一句话对照：

| 工具 | 干什么 |
|---|---|
| `variable` | 「我后面要用这个名字当参数」→ Lean **自动补参数** |
| `section` | 「这些 `variable` 只在这个范围内有效」 |

---

## 2. 先看问题：参数要重复写

02-5 见过 `doTwice`（把函数用两次）。这里再配一个「用三次」的版本（实测）：

```lean
def doTwiceA (f : Nat → Nat) (x : Nat) : Nat := f (f x)
def doThriceA (f : Nat → Nat) (x : Nat) : Nat := f (f (f x))

#check doTwiceA     -- doTwiceA (f : Nat → Nat) (x : Nat) : Nat
#check doThriceA    -- doThriceA (f : Nat → Nat) (x : Nat) : Nat
```

两个定义里的 `(f : Nat → Nat) (x : Nat)` **一模一样**，写了两遍。后面再有十个这样的函数，就要写十遍。

**`variable` 就是为这个准备的。**

---

## 3. 本课要用的一个新工具：`#print`

`#check` 你早就会了——它给你**类型**。本课还需要一个会给**定义**的工具：**`#print 名字`**。

实测：

```lean
def five : Nat := 5

#check five     -- five : Nat
#print five
-- 打印（两行）：
--   def five : Nat :=
--   5
```

一句话区分：

| 命令 | 给你什么 |
|---|---|
| `#check 名字` | 它的**类型** |
| `#print 名字` | 它的**类型 + 定义**（右边那串也给你） |

> ⚠️ **本课为什么非要 `#print`**：`variable` 的效果是「Lean **悄悄**补上了参数」——
> 光看 `#check` 只能看到「它确实是个函数」，**看不出那些参数是自动补的**。`#print` 才把定义摊开给你看。

## 4. `variable` 登场

实测：

```lean
variable (f : Nat → Nat) (x : Nat)

def doTwiceB := f (f x)
def doThriceB := f (f (f x))

#check doTwiceB     -- doTwiceB (f : Nat → Nat) (x : Nat) : Nat
#print doTwiceB
-- 打印（两行）：
--   def doTwiceB : (Nat → Nat) → Nat → Nat :=
--   fun f x => f (f x)
#print doThriceB
-- 打印（两行）：
--   def doThriceB : (Nat → Nat) → Nat → Nat :=
--   fun f x => f (f (f x))
```

**注意「我写的」和「Lean 打印的」差在哪**：

- 我写的是 `def doTwiceB := f (f x)` —— **一个参数都没写**；
- Lean 打印的是 `def doTwiceB : (Nat → Nat) → Nat → Nat := fun f x => f (f x)` —— **参数 `f`、`x` 被自动补上了**。

原文的说法（我翻译）：

> **`variable` 命令让 Lean 把这些变量作为「绑定变量」插进那些**按名字引用到它们**的定义里。**
> Lean 足够聪明，能看出一个定义里**显式或隐式**用到了哪些变量。
> 所以你写定义时可以**假装 `f`、`x` 是固定的东西**，让 Lean 替你抽象。

### ⚠️ 为什么打印出来会**多出一个 `fun`**？

（这一小节专门回答一个很容易卡住的问题。**如果你刚才已经想问「这个 `fun` 是哪来的」，答案在这里。**）

我写的是 `def doTwiceB := f (f x)`，**一个参数都没写**；打印出来却是

```
def doTwiceB : (Nat → Nat) → Nat → Nat :=
fun f x => f (f x)
```

**那个 `fun f x =>` 是从哪来的？**

**一句话**：**「把变量补成参数」就等于「把这个定义变成一个函数」；而写函数的语法就是 `fun`。**

拆成三步看：

1. `variable (f : Nat → Nat) (x : Nat)` 的意思是：**`f`、`x` 是变量**，不是固定的东西（本节开头讲的）。
2. 本课的规则：Lean 把定义里**用到的**变量**补成参数**。
3. 「**有一个参数的定义，就是函数**」；而**造函数的语法是 `fun`**（**02-4** 学过）。所以补上参数之后，这个定义用 `fun` 写出来就是 `fun f x => f (f x)`。

**`#print` 做的事，就是把「补好参数之后」的定义摊开给你看**——所以你会看到那个 `fun`。
（`#check` 只看**类型**，所以看不到它。两种显示形状的差别，本节末尾还有一个例子。）

所以下面两个定义**是同一个东西**（实测，两行 `#print` 完全一样）：

```lean
variable (f : Nat → Nat) (x : Nat)

def doTwiceC : (Nat → Nat) → Nat → Nat := fun f x => f (f x)   -- 等价的「手写 fun」版本

#print doTwiceB     -- 本节上面刚定义的那个（「不写参数」的版本）
-- 打印（两行）：
--   def doTwiceB : (Nat → Nat) → Nat → Nat :=
--   fun f x => f (f x)
#print doTwiceC     -- 这个「手写 fun」的版本
-- 打印（两行）：
--   def doTwiceC : (Nat → Nat) → Nat → Nat :=
--   fun f x => f (f x)
```

> ⚠️ **注意 `doTwiceC` 里的 `fun f x =>`**：这里的 `f`、`x` 是 `fun` **自己绑定的参数**，
> 所以**文件级的变量** `f`、`x` 并没有被用到 → Lean **不会**再多补一层参数（这一点下一节还会用到）。
>
> 💡 **顺带一个显示形状的例子**（就是 **02-2 第 8 节**那条规律的又一次出现）：
> 同一个 `doTwiceB`，两条命令打出来的形状不同——
>
> | 命令 | 实测输出 | 形状 |
> |---|---|---|
> | `#check doTwiceB` | `doTwiceB (f : Nat → Nat) (x : Nat) : Nat` | **望远镜式** |
> | `#print doTwiceB` | `def doTwiceB : (Nat → Nat) → Nat → Nat := fun f x => f (f x)` | **箭头式** |
>
> **显示形状不同，含义相同**——这条你在 02-2 §8 已经见过一次。

### 那和手写参数的效果一样吗？一样

⚠️ **先提醒一句、免得误会**：上面出现的 `fun` **不是 `variable` 造出来的**。
下一节（§5）会用**三个对照**把这件事验清楚——包括一个**完全没用 `variable`、但照样打印出 `fun`** 的定义。

（下面这段里，`doTwiceA` 是**第 2 节**定义的那个，`doTwiceB` 是**本节上面**定义的那个。）

```lean
#eval doTwiceA (fun k => k + 1) 5     -- 7
#eval doTwiceB (fun k => k + 1) 5     -- 7
```

**哪一点一样**：两个定义**类型完全相同**（都是 `(Nat → Nat) → Nat → Nat`），`#eval` 结果也相同（都是 `7`）。
**哪一点不一样**：`doTwiceA` 的参数是我们**手写**的；`doTwiceB` 的参数是 Lean **自动补**的。

> 💡 原文用**三个**定义（`compose` / `doTwice` / `doThrice`）演示了同一件事：
> 「参数写三遍」的版本、「`variable`」的版本、以及 `#print` 出来的版本，**效果完全相同**。

### ⚠️ 一个容易踩的坑（实测）

`variable` 有个反直觉之处，第一次写几乎必踩：

```lean
variable (n2 : Nat)

def goodB : Nat := n2 + n2

#print goodB
-- 打印（两行）：
--   def goodB : Nat → Nat :=
--   fun n2 => n2 + n2
```

**而这个就通不过**（**下面这段是故意写错的**）：

```
def badB : Nat → Nat := n2 + n2
```

报错原文：

```
error: Type mismatch
  n2 + n2
has type
  Nat
but is expected to have type
  Nat → Nat
```

**为什么**：回到 **02-5** 学过的那条规则——`def 名字 : 类型 := 表达式` 里，
**`类型` 永远是「右边那个表达式」的类型**。右边的 `n2 + n2` 类型是 `Nat`，**不是** `Nat → Nat`。
而 `variable` 补的参数是 Lean **另外加上去的**（加在**最前面**），**不归你手写的那串类型管**。

所以记住：

> **用了 `variable`，`def` 的类型标注就写「右边表达式的类型」**（本课这些例子里通常就是 `Nat`）；
> **不要**把整个函数的类型（`Nat → Nat`）写上去。当然，**不写类型**（`def goodB := n2 + n2`）也可以。

## 5. Lean 很聪明：只把**用到**的变量变成参数

⚠️ **先交代一句：本节用到的 `x` 是哪来的。**
它是**第 4 节**里 `variable (f : Nat → Nat) (x : Nat)` 声明的那一个 `x`
（**`variable` 一旦声明，一直到文件结尾都有效**——这正是下一节 `section` 要解决的问题）。
为了让你能**单独读懂本节**，下面把那一行**再写一次**：

```lean
variable (x : Nat)     -- 就是第 4 节声明的那个 x
variable (b : Bool)    -- 本节的例子用不到它

def incX := x + 1

#print incX
-- 打印（两行）：
--   def incX : Nat → Nat :=
--   fun x => x + 1
```

⚠️ **注意 `b` 不见了**：上面明明声明了 `variable (b : Bool)`，但 `incX` 里**没有用到 `b`**，
所以 Lean **不会**把它变成参数——定义里只有一个 `fun x => …`。

> 💡 规则：**用到的才补，没用到的不管。**
> 所以你可以放心在文件里声明一批变量，不必担心它们「污染」不相干的定义。

### ⚠️ 再澄清一步：那个 `fun` **不是** `variable` 带来的

`variable (x : Nat)` 那一行**本身什么都没做**——光盯着它看，**确实看不出它和 `fun` 有什么关系**。
这个疑问很自然，因为**答案是：`fun` 不是 `variable` 造出来的**。

> **真相**：`#print` 打印**任何一个「带参数的定义」**时，**一律把它写成 `fun`**。
> `variable` 做的事只有一件：**替你自动补上参数**——补完之后这个定义就成了「带参数的定义」，
> 于是 `#print` 也就写成 `fun` 了。

三个对照（实测；**注意中间那个完全没用 `variable`**）：

```lean
def incZ (x : Nat) : Nat := x + 1     -- 手写参数（这个 x 是 incZ 自己的，不是上面那个变量）

#print five    -- 第 3 节定义的那个：它没有参数
-- 打印（两行）：
--   def five : Nat :=
--   5                                ← 没有 fun
#print incZ
-- 打印（两行）：
--   def incZ : Nat → Nat :=
--   fun x => x + 1                   ← 有 fun
#print incX    -- 就是上面那个「让 variable 补参数」的版本
-- 打印（两行）：
--   def incX : Nat → Nat :=
--   fun x => x + 1                   ← 与 incZ 一模一样
```

| 定义 | 有参数吗？ | `#print` 里出现 `fun` 吗？ |
|---|---|---|
| `def five : Nat := 5`（第 3 节那个） | **没有** | **没有** |
| `def incZ (x : Nat) : Nat := x + 1` | 有（**手写**的） | **有** |
| `def incX := x + 1`（配 `variable (x : Nat)`） | 有（**Lean 补**的） | **有** |

**结论**（这三行就是答案）：

- **`fun` 来自「这个定义有参数」，不来自 `variable`。**
- `variable` 只是**替你补参数**；补完的 `incX` 与手写参数的 `incZ`，`#print` 出来**一模一样**。
- 所以 `variable (x : Nat)` 那一行**单独看「看不出和 `fun` 的关系」是正常的**——
  关系不在那一行里，而在**「这个定义有没有参数」**这件事上。

### ✅ 一句话把 `variable` 说准：它声明的**就是参数**

你完全可以说：**`variable` 声明的东西，本来就不是「一般意义上的变量」，而是「参数」。**
Lean 自己就是这么说的——原文 2.6 用的词是 **bound variables（绑定变量）**，而「绑定变量」就是**参数**。

三种写法，**三行 `#print` 一字不差**（实测）：

```lean
variable (x : Nat)

def incVar := x + 1                            -- ① 参数一个不写（variable 替你补）
def incParam (x : Nat) : Nat := x + 1          -- ② 参数手写
def incFun : Nat → Nat := fun x => x + 1       -- ③ 连 fun 也手写

#print incVar
#print incParam
#print incFun
-- 三行打印完全一样：
--   def incVar   : Nat → Nat := fun x => x + 1
--   def incParam : Nat → Nat := fun x => x + 1
--   def incFun   : Nat → Nat := fun x => x + 1
```

**① ② ③ 里的 `x` 是同一种东西**（都是**参数**）。`variable` 做的事，就是**把 ② 里手写的 `(x : Nat)` 自动化**。

再看两个「它**不是**一般意义的变量」的证据（实测）：

```lean
-- 用的还是上面那个 `variable (x : Nat)` 声明的 `x`
def plus1 := x + 1
def plus2 := x + 2

#print plus1
-- 打印（两行）：
--   def plus1 : Nat → Nat :=
--   fun x => x + 1
#print plus2
-- 打印（两行）：
--   def plus2 : Nat → Nat :=
--   fun x => x + 2
```

- 如果 `x` 是「一般意义的变量」（一个**共享的值**），那么 `plus1` 与 `plus2` 就该用同一个 `x`；
  但实测**每个定义各得一份自己的 `x`**——它们是**两个独立的函数**。
- 换句话说：`x` **没有值**，它只是「**占着参数的位置**」。

### ⚠️ 这个理解里有两句话要改一改

1. **「它必然跟函数有关」→ 应改成「用到它的定义，必然变成函数」。**
   `variable` 那一行**单独不产生任何东西**（不写定义，就没有 `fun`）；
   而且定义**没用到它**时，它**也不进参数**——本节上面那个 `b` 就是例子（`incX` 的参数里没有 `b`）。
2. **「把右边理解成是定义了一个函数」→ 右边本身不是函数。**
   右边的 `x + 1` 类型是 `Nat`（一个值），**不是**函数。
   是 Lean 在右边**外面套了一层 `fun x =>`**，于是**整个 `def`** 成了函数。
   > 准确的说法：**右边是「函数体」；`fun x => 右边` 才是函数。**

**修正后的一句话总结**：

> `variable (x : Nat)` 声明的是一个**参数名**（不是值）。
> **哪个定义用到了它，Lean 就把这个参数加到哪个定义前面**——
> 于是那个定义成了函数，`#print` 也就写成 `fun x => 右边`。

## 6. `section`：限定变量的作用范围

`variable` 一旦声明，**一直到文件结尾都有效**。有时我们只想让它在一小段里有效——这就是 `section`：

```lean
section mysection
  variable (m : Nat)
  def squareM := m * m
end mysection

#check squareM     -- squareM (m : Nat) : Nat
#print squareM
-- 打印（两行）：
--   def squareM : Nat → Nat :=
--   fun m => m * m
```

这里要看清**两件不同的事**：

| 问题 | 答案 |
|---|---|
| `squareM` 这个 **`def`** 还在吗？ | **在**——`#check squareM` 正常；而且参数 `m` 已经**固化在它里面**了 |
| `m` 这个**变量**还能用吗？ | **不能**——它出了 `section` 就失效 |

实测「失效」这件事（**下面这段是故意写错的**）：

```
#check m
```

Lean 报错原文：

```
error(lean.unknownIdentifier): Unknown identifier `m`
```

### 匿名 section、命名 section、嵌套 section

原文说：**section 里的行不必缩进**；**section 也不必起名字**（`section` … `end` 就是**匿名** section）；
**起了名字就必须用同一个名字结束**；**section 可以嵌套**（这样可以一层层地声明变量）。

```lean
section
  variable (k : Nat)
  def cubeK := k * k * k
end

#print cubeK
-- 打印（两行）：
--   def cubeK : Nat → Nat :=
--   fun k => k * k * k

section outer
  variable (p : Nat)
  def addP := p + 1
  section inner
    variable (q : Nat)
    def addPQ := p + q
  end inner
  def addP2 := p + 2
end outer

#print addPQ
-- 打印（两行）：
--   def addPQ : Nat → Nat → Nat :=
--   fun p q => p + q
#print addP2
-- 打印（两行）：
--   def addP2 : Nat → Nat :=
--   fun p => p + 2
```

**从上面这段能看出**：`addPQ` 在 `inner` 里、同时用到了 `inner` 与 `outer` 的变量 → 参数是 `p q` 两个；
`addP2` 只用到 `outer` 的 `p` → 参数只有 `p` 一个。

⚠️ **命名 section 用别的名字结束会报错**（**下面这段是故意写错的**）：

```
section foo
  variable (z : Nat)
  def dz := z + 1
end bar
```

报错原文：

```
error: Invalid name after `end`: Expected `foo`, but found `bar`
```

（Lean 还会在下面贴心地把正确写法提示出来。）

> 💡 **两条容易混的规则，放一起记**：
> 1. `section` 结束后，**变量**失效，但**里面定义的 `def` 不会消失**；
> 2. 命名 section **必须同名结束**；匿名 section 就写一个光秃秃的 `end`。

## 7. 原书 2.6 的写法：变量也可以是「类型」

到上一节为止，我们的变量都是「值」（`Nat`、`Nat → Nat`、`Bool`）。原文的例子更进一步：**把「类型」本身也变成变量**。

```lean
variable (α β γ : Type)
variable (g : β → γ) (h : α → β) (z : α)

def composeB := g (h z)

#print composeB
-- 打印（两行）：
--   def composeB : (α β γ : Type) → (β → γ) → (α → β) → α → γ :=
--   fun α β γ g h z => g (h z)
```

**怎么读**：`α`、`β`、`γ` 是**三个参数**，只不过它们的值是**类型**
（`α : Type` 就是「`α` 是一个类型」——这话你在 **02-3** 学过）。`variable` 的机制**一点没变**：
Lean 照样把用到的名字变成参数。

> 📌 **一处范围修正（请读一下）**：我在 **02-5 讲义**里说过「把类型当参数」要推到 2-9，**现在修正**：
> **本课正式演示这种写法，要求你能读懂、也能照着写**；
> 但「**为什么后面的参数可以依赖前面的参数**」（比如 `g : β → γ` 里的 `β`、`γ` 本身就是参数）
> 属于**依赖函数类型**，**原理归 2-9**。本课**只要求照用，不要求解释原理**。
> 习题也**不出**需要你自己设计类型参数的题（仍以已学内容为主）。

## 9. 小结

本课记住四件事：

1. **`variable (名字 : 类型) …`**：把反复出现的参数声明一次；之后定义里**直接用这个名字**，Lean **自动把它变成参数**——用 `#print` 能看得一清二楚。
2. **只补用到的**：定义里没引用的变量**不会**变成参数。
3. **`section` / `end`**：限定变量的作用范围。**变量出了 section 就失效，但 section 里定义的 `def` 照旧存在**（参数已经固化在它里面）。匿名 section 可以；命名 section **必须同名结束**；可以嵌套。
4. **变量也可以是类型**（`variable (α : Type)`）：机制一样，**照用即可**；依赖函数类型的原理**归 2-9**。
