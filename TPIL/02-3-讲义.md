# 第 2 章 · 第 3 课：`Prop` 与 `Type`（类型本身也是对象）

> 📄 **示例**：`02-3-示例.lean`（我写的，已通过编译、零 warning）
> ✍️ **习题**：`02-3-习题.lean`（**你写**）
> 📖 **原文**：<https://lean-lang.org/theorem_proving_in_lean4/Dependent-Type-Theory/#types-as-objects> 的 **2.2** 小节（想深挖时再看；**读不懂不影响本课**）
> 本课只讲一件事：**「类型」自己也是一个对象——它也有类型。而 Lean 里有两个「大类型」：`Type`（数据）与 `Prop`（命题）。**

---

## 1. 本课的一句话

上一课我们知道：**每个值都有类型**——`1 : Nat`、`true : Bool`、`(1, true) : Nat × Bool`。

这一课往前再走一步：**「类型」自己也有类型。**

```lean
#check Nat
```

Lean 回答：

```
Nat : Type
```

读作：「`Nat` 这个东西的**类型**是 `Type`。」

这句话初看很怪（`Nat` 不是类型吗？怎么还有类型？），但它是 Lean 的地基。本课就把这件事讲清楚。

---

## 2. 类型也有类型（实测）

一个一个问下去（下面每一行的右边注释，都是我实跑 Lean 得到的输出）：

```lean
#check Nat                   -- Nat : Type
#check Bool                  -- Bool : Type
#check Nat → Bool            -- Nat → Bool : Type
#check Nat × Bool            -- Nat × Bool : Type
#check Nat → Nat             -- Nat → Nat : Type
#check Nat × Nat → Nat       -- Nat × Nat → Nat : Type
#check Nat → Nat → Nat       -- Nat → Nat → Nat : Type
#check (Nat → Nat) → Nat     -- (Nat → Nat) → Nat : Type
```

**规律**：上一课我们造出来的那些类型（`→` 造的、`×` 造的），它们的类型统统是 `Type`。

**为什么这件事重要？**（原文的说法是「类型是**一等公民**」）

因为这说明：**「类型」不是纸上谈兵的标签，它和 `1`、`true` 一样，本身就是一个「对象」**。既然如此，它就应该能享受对象的一切待遇：

- 可以被 `#check` 问类型（上面就在做这件事）
- 可以被 `def` 起名字（下一节）
- 可以被当参数传给别的东西（下一节）

---

## 3. 给「类型」和「吃类型的东西」起名字（实测）

`def` 这个句型你已经会了（`def m : Nat := 1`）。**它照样可以用来给「类型」起名字**——只要把类型位置写成 `Type`，值位置放一个类型：

```lean
def α : Type := Nat          -- 给类型 Nat 起个名字叫 α
def β : Type := Bool         -- 给类型 Bool 起个名字叫 β

#check α                     -- α : Type
#check β                     -- β : Type
#check α × α                 -- α × α : Type
```

注意最后一行：`α` 是我们自己起的名字，**它可以直接放在类型的位置上用**（`α × α`）。这正是「类型本身也是对象」的最直接体现。

更进一步的例子——给「**吃一个类型、吐一个类型**」的东西起名字：

```lean
def F : Type → Type := List          -- List：吃一个类型，吐它的列表类型
def G : Type → Type → Type := Prod   -- Prod：吃两个类型，吐它们的积

#check F                     -- F : Type → Type
#check F Nat                 -- F Nat : Type       ← 「Nat 的列表」那个类型
#check G Nat Nat             -- G Nat Nat : Type   ← 「Nat × Nat」那个类型
```

这里 `List` 和 `Prod` 都是**标准库里现成的**东西，我们没有自己造——和你上一课用现成的 `Nat.succ`、`Nat.add` 是同一个做法。

> ⚠️ **一个你会撞上的东西，先说清楚**：如果你在某处（比如 `#check List`）看到
>
> ```
> List.{u} (α : Type u) : Type u
> ```
>
> 那一堆 `{u}`、`Type u` 叫**宇宙多态**，**本课不引入**（原因见第 10 节）。
> 你只要知道：`u` 表示「它活在某一层宇宙里」，**本课只用不带 `u` 的写法就够**。

---

## 4. `Type` 自己的类型：一层层往上（实测）

既然每个类型都有类型，那 `Type` 自己的类型是什么？

```lean
#check Type                  -- Type : Type 1
#check Type 0                -- Type : Type 1   ← 和上一行输出一样
#check Type 1                -- Type 1 : Type 2
#check Type 2                -- Type 2 : Type 3
```

第 2 行说明了一件有用的事：**`Type` 就是 `Type 0` 的简写**——它俩是同一个东西（输出完全相同）。

那 `Type 1` 又是什么？是**更大的一层**。Lean 有一层无穷无尽的「宇宙」：

```
Type  : Type 1
Type 1 : Type 2
Type 2 : Type 3
...
```

**为什么不能只有一个 `Type`？** 因为「包含一切类型的那个类型」会自己包含自己，从而自相矛盾（跟「所有集合的集合」是同一类麻烦）。所以 Lean 干脆分层。

> 💡 **本课只需要知道这个现象**：「看到 `Type 1` 不要慌，它只是更大一层」。
> **不需要理解为什么必须分层**——那属于逻辑基础，不是本课程的内容。
> 平时你几乎只会写 `Type`，`Type 1` 极少出现。

---

## 5. 第二个宇宙：`Prop`（命题的世界）

到目前为止，`Type` 里装的是「**数据**」那一类的类型：`Nat`、`Bool`、`Nat × Bool`、`Nat → Nat`……

Lean 还有**另一个宇宙**：`Prop`——**命题**的世界。

```lean
#check Prop                  -- Prop : Type
#check True                  -- True : Prop
#check False                 -- False : Prop
```

逐行读：

- **`Prop` 是「命题的类型」**——就像 `Nat` 是「自然数的类型」。
  注意它的输出是 `Prop : Type`：**`Prop` 自己是一个类型**（住在 `Type` 里）。这一点下面第 7 节还会再说一次，因为它最容易绕晕。
- **`True` 和 `False` 是两个最基本的命题**：`True` 是**永远成立**的命题，`False` 是**永远不成立**的命题。

那命题的「值」是什么？看这一行：

```lean
#check True.intro            -- True.intro : True
```

**命题也有「值」，而命题的「值」叫「证明」。** `True.intro` 就是 `True` 的一份证明。

> ⚠️ **怎么自己造证明，是第 3 章《命题与证明》的内容，本课不引入。**
> 本课只需要认得这个**位置关系**：命题（如 `True`）站在**类型**的位置上，证明（如 `True.intro`）站在**值**的位置上。第 3 章会从这里接着往下讲。
>
> 顺带一提：`False : Prop` 是「假命题」，它**一份证明都没有**——这正是「假」的意思。第 3 章会用到这一点。
>
> 顺带第二件：如果你用 `def` 去声明一个「类型是命题」的东西（例如 `def h : True := True.intro`），Lean 会**警告**你：
> `Definition 'h' is a proposition; use 'theorem' instead of 'def'`。
> `theorem` 是第 3 章的关键字，**本课不用**；现在只要知道「Lean 能区分『这是数据』还是『这是命题』」就够了。

## 6. 番外（可选读）：`Sort`——`Prop` 与 `Type` 的统一叫法

Lean 内部把上面这些宇宙统称为 `Sort`：

```lean
#check Sort 0                -- Prop : Type
#check Sort 1                -- Type : Type 1
#check Sort 2                -- Type 1 : Type 2
```

也就是：

| 写法 | 等于 |
|---|---|
| `Sort 0` | `Prop` |
| `Sort 1` | `Type`（= `Type 0`） |
| `Sort 2` | `Type 1` |
| `Sort 3` | `Type 2` |

**为什么要知道这个**：你以后在 Lean 的输出里可能看到 `Sort u` 这种字样（例如 `False.elim` 的输出里有 `{C : Sort u}`）。那时按上表翻译一下就行——它只是在说「某个宇宙里的某个类型」。

> **本课不要求会用 `Sort`**，认得即可。这一节看不懂可以整节跳过，不影响后面的课。

## 7. 判据（接上一课）：一眼分清「类型 / 命题 / 值」

上一课（2-2 第 9 节）我们立过一条判据：**用 `#check X`，看输出里冒号右边那一串**。现在把它补全：

| 冒号右边是 | `X` 是 |
|---|---|
| `Type` | **类型** |
| `Prop` | **命题** |
| 别的（`Nat`、`Nat × Nat`、`Nat → Nat`、`True`…） | **值**（右边那串就是它的类型） |

四个实测例子：

| 实测输出 | 冒号右边 | 判定 |
|---|---|---|
| `Nat × Bool : Type` | `Type` | 类型 |
| `Prop : Type` | `Type` | **类型**（注意！`Prop` 自己是类型里的一员） |
| `True : Prop` | `Prop` | 命题 |
| `True.intro : True` | `True` | 值（一份证明） |

> ⚠️ **最容易绕晕的是第 2 行 `Prop : Type`**：`Prop` **是**一个类型（所以冒号右边是 `Type`），
> 但它**装的东西**是命题。这两件事不矛盾——`Prop` 是「专门用来装命题的那种类型」。

## 8. 两个世界的对照表

| | `Type` 的世界（数据） | `Prop` 的世界（命题） |
|---|---|---|
| 里面住着 | `Nat`、`Bool`、`Nat × Bool`、`Nat → Nat`… | `True`、`False`… |
| 里面东西的**值** | 数据：`1`、`true`、`(1, true)` | **证明**：`True.intro` |
| 平时拿它干什么 | 计算（`#eval`） | 证明（第 3 章） |
| 判据 | `#check` 右边是 `Type` | `#check` 右边是 `Prop` |

## 10. 小结

本课记住四件事：

1. **类型也是对象**：类型自己也有类型（`Nat : Type`）；可以给它起名字（`def α : Type := Nat`），也可以当参数传（`F : Type → Type := List`）。
2. **`Type` 有无限多层**：`Type : Type 1`、`Type 1 : Type 2`……；`Type` 就是 `Type 0` 的简写。**平时只写 `Type`**，看到 `Type 1` 不用慌。
3. **`Prop` 是第二个宇宙**：`Prop : Type`（`Prop` 自己是类型），`True : Prop`、`False : Prop`，而命题的「值」是**证明**（`True.intro : True`）。
4. **判据**：`#check X` 冒号右边是 `Type` → **类型**；是 `Prop` → **命题**；别的 → **值**。
