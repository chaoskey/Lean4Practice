## 1. 本课的一句话

前面三课，函数一直是「**别人写好的东西**」：`Nat.succ`、`Nat.add`、`List`——我们只是把它们拿来用。

这一课开始，你要**自己造函数**了。工具是一个关键字：

```lean
fun (x : Nat) => x + 5
```

上面这串东西**本身就是一个函数**：吃一个自然数，吐回它加 5。

> ⚠️ 这是本课程的一个分水岭：**在 Lean 里，连「证明」都是用 `fun` 造出来的**。
> 所以这一课不好好过，第 3 章会寸步难行。我会讲得比前面几课更慢。

## 2. `fun` 的基本写法

```lean
fun (x : Nat) => x + 5
```

逐段读：

| 片段 | 读作 | 说明 |
|---|---|---|
| `fun` | 「造一个函数」 | 关键字。Lean 只认这个拼写 |
| `(x : Nat)` | 「参数叫 `x`，类型是 `Nat`」 | 括号里是**参数**，写法和你已经熟悉的 `def a (n : Nat)` 一样 |
| `=>` | 「吐回……」 | 读作「箭头」；直接打 `=>` 就行（也可以打 `\=>`） |
| `x + 5` | 函数体 | 用参数算出的结果 |

**`λ` 与 `fun` 完全同义**（`λ` 打 `\lambda` 或 `\la`）。下面两行是实测输出，**逐字相同**：

```lean
#check fun (x : Nat) => x + 5      -- fun x => x + 5 : Nat → Nat
#check λ (x : Nat) => x + 5        -- fun x => x + 5 : Nat → Nat   ← 与上一行输出完全相同
```

> ⚠️ 注意 Lean 的**显示习惯**：你写的是 `(x : Nat) => `（带括号带类型），
> 它回给你的是 `fun x => `（不带括号不带类型）。**这不是两回事**——显示时省掉了它认为多余的部分。

## 3. 类型：从 α 到 β

原文这段说法值得一字一句读懂（我翻译成中文）：

> 假设你有一个变量 `x : α`，并且你能从它构造出一个表达式 `t : β`；
> 那么 `fun (x : α) => t` 就是**类型 `α → β`** 的一个对象。
> 把它想成「把任意一个 `x` 映射到 `t`」的那个函数。

这个过程有个名字，叫 **lambda 抽象**（lambda abstraction）——**从一个表达式造出一个函数**。

翻译成你能直接用的判据（实测）：

```lean
#check fun (x : Nat) => x + 5      -- fun x => x + 5 : Nat → Nat
```

冒号右边是 `Nat → Nat`，正好对应「参数类型 `α` 是 `Nat`、结果类型 `β` 是 `Nat`」。

---

## 4. 类型标注可以省 —— 但有边界

大多数时候，`(x : Nat)` 里的 `: Nat` 可以**省略**，让 Lean 自己推：

```lean
#check fun x => x + 5              -- fun x => x + 5 : Nat → Nat   ← 没写 : Nat 也能推出来
```

为什么能推出来？因为函数体里有个 `5`，而 `5 : Nat`——**线索够了**。

### ⚠️ 但线索不够时，Lean 推不出来

下面这一行**没有**任何类型线索（既没标注，函数体里的 `+` 也没告诉我们 `x`、`y` 是什么类型）：

```lean
#check fun x y => x + y
```

它**不会**给你一个干净的类型，而是打印出一串带 `?m.…` 的「**待定**」东西，大意是：

```
fun x y => x + y : (x : ?m.…) → (y : ?m.…) → ?m.…
```

（`?m` 是 Lean 的「我还不知道这是什么」记号；**具体编号每次运行可能不同**，所以我不写死。）

**这不是报错**，但它说明：**这个表达式的类型还没定下来**。修法很简单——**给人一点线索**：

```lean
#check fun (x y : Nat) => x + y    -- fun x y => x + y : Nat → Nat → Nat   ← 干净了
```

注意 `(x y : Nat)` 这种**两个名字共用一个类型标注**的写法——省事且常用。

> 💡 **记住这条边界**：省略类型标注是「Lean 能推就省」，不是「随便省」。
> 看到 `?m` 就说明推不出来，回去把类型补上。

## 5. 多参数：两种写法，同一个类型

要写「吃两个参数」的函数，有两种写法（实测，**两行输出逐字相同**）：

```lean
#check fun x : Nat => fun y : Nat => x + y   -- fun x y => x + y : Nat → Nat → Nat
#check fun (x : Nat) (y : Nat) => x + y      -- fun x y => x + y : Nat → Nat → Nat
```

- 第 1 行是**嵌套**写法：「吃一个 `Nat`，吐回一个函数（那个函数再吃一个 `Nat`）」。
- 第 2 行是**并列**写法：看起来像「一次吃两个」。

**它们的类型完全相同**（都是 `Nat → Nat → Nat`），Lean 也把第 1 行的嵌套直接**打印**成 `fun x y => ...`。

这正好接上 02-2 第 5 节的**箭头右结合**：

> `Nat → Nat → Nat` 本来就是 `Nat → (Nat → Nat)`。
> 所以「并列写两个参数」只是**写法上的方便**，本质仍是「一次吃一个」。
> 这也是 02-2 第 6 节**部分应用**能成立的原因。

## 6. 应用与求值

### 应用：把函数用在一个东西上

规则（原文的说法 + 实测）：

> 若 `t : α → β` 且 `s : α`，则 `t s : β`。

```lean
#check (fun x : Nat => x) 1       -- (fun x => x) 1 : Nat
#check (fun (_ : Nat) => true) 1  -- (fun x => true) 1 : Bool
```

读法：把函数写在前面、参数写在后面，中间**用空格**隔开（不是括号、不是逗号）。

### `#eval`：真的把它算出来

```lean
#eval (fun x : Nat => x + 5) 10   -- 15
#eval (fun x : Nat => x) 1        -- 1
#eval (fun (_ : Nat) => true) 1   -- true
```

原文说得很直接：**`#eval` 是测试你写的函数的首选办法**。以后写完函数，先 `#eval` 一个例子看看。

### 两个有名字的常见函数

原文举了两个「数学上常见」的函数：

```lean
#check fun x : Nat => x           -- fun x => x : Nat → Nat        ← 恒等函数：原样返回
#check fun (_ : Nat) => true      -- fun x => true : Nat → Bool    ← 常函数：永远返回 true
```

⚠️ **第 2 行有一处必须解释的细节**：我写的是 `(_ : Nat)`，**不是** `(x : Nat)`。

原因是——**`x` 在函数体里根本没被用到**，Lean 会对此报警告：

```
warning: Variable name `x` is not explicitly referenced.
Hint: The binding can be removed (if unused) or named `_` (if used implicitly).
```

它给的提示正是解法：**不需要用的参数名，写成 `_`**。这样警告就没了。（`_` 你已经在 02-2 第 8 节见过，就是「匿名/不在乎这个名字」的记号。）

> 还有个显示上的小陷阱：写 `(_ : Nat) => true`，**Lean 显示成 `fun x => true`**——那个 `x` 是
> **Lean 自己起的名字**，不是你起的。所以**别拿显示出来的名字当依据**（这正是 02-2 第 8 节的主题）。

### `#eval` 之后：什么叫「按定义相等」

原文在这里提了一个重要概念（我按你的水平改写）：

> 每个表达式都有**计算行为**，都能「算下去」（这个过程叫**归约**）。
> 原则上，**能算到同一个值的两个表达式叫「按定义相等」**（definitionally equal）——
> Lean 的类型检查器把它们当成**同一个东西**。

本课你只需要知道这个现象存在：`(fun x : Nat => x) 1` 和 `1` 在 Lean 眼里是同一个东西。

> ⚠️ **本课不引入**：怎么把「相等」这件事**写下来、证出来**——
> 那要用 `=` 和 `rfl`，是**第 3 章**的内容。现在不用会。

## 7. 绑定变量的名字只是占位符（alpha 等价）

看这两行（实测，**两者类型完全相同**）：

```lean
#check fun (a : Nat) (b : Nat) => a + b     -- fun a b => a + b : Nat → Nat → Nat
#check fun (u : Nat) (v : Nat) => u + v     -- fun u v => u + v : Nat → Nat → Nat
```

- **哪一点一样**：**类型一样**（都是 `Nat → Nat → Nat`），而且 Lean 把它们当作**同一个函数**。
- **哪一点不一样**：**显示出来的名字不一样**（一个是 `a b`，一个是 `u v`）——这无关紧要。

正式说法：`fun (x : α) => t` 里的 `x` 叫**绑定变量**（bound variable），它只是个**占位符**，
作用范围**不超出**它后面的那个表达式 `t`。**「只换了占位符名字」的两个表达式叫 alpha 等价**，
Lean 认为它们就是同一个东西。

### 顺带一个重要推论：作用域（scope）

既然绑定变量只在它自己的表达式里有效，那么**它跟外面的同名东西毫无关系**（实测）：

```lean
def seven : Nat := 7

#eval (fun seven : Nat => seven + 1) 10   -- 11   ← 用的是参数 10，不是外层的 7
```

结果是 `11` 而不是 `8`——说明函数体里的 `seven` 指的是**参数**，不是外层那个 `def seven := 7`。

> 💡 这个现象叫**遮蔽**（shadowing）：里层的新名字挡住了外层的同名者。
> 以后读别人的代码时，看到同名变量先想「它现在是哪一层定义的」。

## 8. 函数也可以当参数

函数是「一等公民」，所以**函数当然可以当参数传给另一个函数**。最常见的是**复合**两个函数：

```lean
#check fun (g : Nat → Nat) (f : Nat → Nat) (x : Nat) => g (f x)
-- fun g f x => g (f x) : (Nat → Nat) → (Nat → Nat) → Nat → Nat
```

读法：吃两个函数 `g`、`f` 和一个值 `x`，**先**对 `x` 用 `f`，**再**对结果用 `g`。

真的算一遍（实测）：

```lean
#eval (fun (g : Nat → Nat) (f : Nat → Nat) (x : Nat) => g (f x))
        (fun n => n * 2) (fun n => n + 1) 3      -- 8
```

怎么读这个 `8`：`f` 是「加一」，`g` 是「乘二」；`x = 3` → 先 `3 + 1 = 4` → 再 `4 * 2 = 8`。

### ⚠️ 本课**不**引入：把「类型」当参数

原文在这一节还举了一个例子：让函数直接吃**类型**（`α`、`β`、`γ`）和两个函数。它的类型长这样：

```
(α β γ : Type) → (β → γ) → (α → β) → α → γ
```

这个例子**本课不引入**，原因原文自己说了：理解它的类型需要先懂 **dependent products（依赖积）**。
那属于本项目 **2-9（依赖类型）** 一带的内容。等学到那里再回头看，会简单得多。

## 9. `fun` 与 `def` 的两种写法是同一件事

你已经见过 `def` 的两种句型，现在知道它们其实是**同一件事**（实测）：

```lean
def double1 : Nat → Nat := fun n => n * 2    -- 把函数体写成 fun
def double2 (n : Nat) : Nat := n * 2         -- 把参数写在 def 上

#check double1                    -- double1 : Nat → Nat
#check double2                    -- double2 (n : Nat) : Nat
#eval double1 5                   -- 10
#eval double2 5                   -- 10
```

- **哪一点一样**：**两个函数的类型和行为完全一样**（`#eval` 结果都是 `10`）。
- **哪一点不一样**：`#check` 的**显示形式**不一样——`double1` 显示成箭头式，`double2` 显示成望远镜式。
  这正是 **02-2 第 8 节**讲过的那件事：显示形式取决于**类型里 binder 有没有名字**，与含义无关。

> `def` 本身的细节（比如带参数、带返回值怎么写）是**下一课 2-5** 的主题，本课只要求你认出「这两种句型说的是同一件事」。

## 10. 小结

本课记住四件事：

1. **`fun (x : Nat) => x + 5` 就是一个函数**：从一个表达式造出函数，这叫 **lambda 抽象**；`λ` 与 `fun` 完全同义。
2. **多参数只是写法**：`fun x : Nat => fun y : Nat => ...` 与 `fun (x : Nat) (y : Nat) => ...` 的类型**完全相同**（都是 `Nat → Nat → Nat`）——因为箭头右结合（02-2 第 5 节）。
3. **应用与求值**：`t : α → β`、`s : α` ⟹ `t s : β`；`#eval` 是**测试函数的首选**。不用到的参数名要写 `_`，否则 Lean 会警告。
4. **名字只是占位符**：`fun (a : Nat) (b : Nat) => a + b` 与 `fun (u : Nat) (v : Nat) => u + v` 是**同一个函数**（alpha 等价）；绑定变量还会**遮蔽**外层同名常量。
