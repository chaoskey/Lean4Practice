# 第 4 章 · 第 8 课：证明语言的补充——匿名 `have` 与 `this`

> **本课范围**：原文 **4.5 More on the Proof Language** 的**前半**（原文那一节很短，主题就一个）。
>
> **本课一句话**：`have` 可以**不起名字**（`have : p := …`）；这种匿名 `have` 留下的那条事实，
> 用关键字 **`this`** 就能引到——**它永远指「最近那一次」**。
>
> ⚠️ **全节 tactic 0 处**：本课的新零件（匿名 `have` ＋ `this`）**全是项**。
> ⚠️ 原文这一节还给了两个**属于第 5 章**的写法（`by assumption`、`‹p›`）——**本课不引入**，但 §6 会**如实讲清它们是什么**。

---

## §1 先把三件旧零件摆出来

原文这一节开头说：`fun`、`have`、`show` 这些关键字让**形式证明项**能写出**非形式数学证明**的样子。
本课再加一件。先回顾（这三件你都已经在用了）：

| 零件 | 它干什么 | 你第一次用它在哪 |
|---|---|---|
| `fun x => …` | **造一个函数** | 03-x（`∀` 的证明就是函数） |
| `have h : p := …` | 在证明中途**插一条局部事实**，并**给它起名字** `h` | 03-7 |
| `show p from t` | **声明**「我接下来要证的**就是这个形状** `p`」，然后把 `t` 交上去 | 04-3 起 |

本课要加的第四件：**别有名字的 `have`**。

---

## §2 新零件①：匿名 `have`

`have` 后面的名字**可以省掉**：

```lean
section anon_basic
theorem anon_basic (p q : Prop) (hp : p) (hq : q) : q :=
  have : p := hp
  have : q := hq
  this
end anon_basic
```

写成 `have : p := hp`（**冒号前面没有名字**）就是**匿名 `have`**：事实插进来了，但**不给你一个名字去叫它**。

那怎么用它？——**`this`**。

---

## §3 新零件②：`this`（以及它**究竟**指哪个）

`this` 指的是「**最近一次**匿名 `have` 留下的那条事实」。三条实测结论：

### 3.1 它指**最近**那个（不是第一个）

```lean
section this_latest
theorem this_latest (p q : Prop) (hp : p) (hq : q) : q :=
  have : p := hp
  have : q := hq
  this
end this_latest
```

这一段能过，**正好说明 `this` 是第二个**（`q`）——如果它指第一个（`p`），目标 `q` 就交不上 ✗。

### 3.2 ⚠️ 它**只认匿名 `have`**——带标签的不算

```lean
section this_needs_anon
theorem this_needs_anon (p : Prop) (hp : p) : p :=
  have h1 : p := hp
  h1
end this_needs_anon
```

上面这版**必须**用名字 `h1`。你要是把最后一行写成 `this`，Lean 会报：

```
error: Unknown identifier `this`
```

——**因为 `have h1 : p := hp` 是「有名字」的那种，`this` 不管它**。
（这条是**实测**出来的；原文那句话的措辞是「the last expression introduced **in this way**」，这个 *in this way* 就是指「匿名」——它是对的。）

**再加一条更细的实测**：在匿名 `have` 之后**插一条带名字的 `have`**，`this` **不会被顶掉**：

```lean
section this_survives_named
theorem this_survives_named (p q : Prop) (hp : p) (hq : q) : p :=
  have : p := hp
  have _h1 : q := hq
  this
end this_survives_named
```

（`_h1` 开头的下划线只是为了避免「变量没用上」的警告；写成别的用得上 `h1` 的形式也一样。）

**所以准确说法是两条**：

> ① `this` **只认匿名 `have`**（带名字的引用不到）；
> ② **带名字的 `have` 既引用不到、也不会把 `this` 顶掉**——`this` 盯的是「**最近那条匿名 `have`**」。

### 3.3 一句话总结

> `this` ＝ **最近那条匿名 `have` 的命题的证明**。

## §4 它省了什么：两版对照

同一个证明，写两遍看差别。原文用的是 `≤` 与 `Nat.le_trans`，**但 `≤` 这个符号与它的引理本课程还没讲**，
所以下面**换成等号 `=` 与 `.trans`**（04-3 学过）——**结构一模一样**，只是关系换成你会的那个。

**带标签版**（每一条都起名字）：

```lean
section labeled
theorem labeled_chain (f : Nat → Nat) (h : ∀ x : Nat, f x = f (x + 1)) : f 0 = f 4 :=
  have h01 : f 0 = f 1 := h 0
  have h02 : f 0 = f 2 := h01.trans (h 1)
  have h03 : f 0 = f 3 := h02.trans (h 2)
  show f 0 = f 4 from h03.trans (h 3)
end labeled
```

**匿名版**（同一条链，一个名字都不起）：

```lean
section anonymous
theorem anonymous_chain (f : Nat → Nat) (h : ∀ x : Nat, f x = f (x + 1)) : f 0 = f 4 :=
  have : f 0 = f 1 := h 0
  have : f 0 = f 2 := this.trans (h 1)
  have : f 0 = f 3 := this.trans (h 2)
  show f 0 = f 4 from this.trans (h 3)
end anonymous
```

**两版证的是同一个命题、用的是同一批零件**，区别只在**有没有给中间结论起名字**。
链一长，名字会变成一堆垃圾（`h01`、`h02`、`h03`…），所以原文说这样能「去掉杂乱」。

## §5 ⚠️ 诚实的一面：`this` 的**代价**

`this` 只有**一个**——它永远指**最后一次**。所以：

> **只要你想「回头」引用更早的那条中间结论，就必须当初给它起名字。**

这不是空话，有实测。看这个目标 `f 0 = f 3 ∧ f 0 = f 2`：`f 0 = f 2` 这条**要用两次**
（一次接 `h 2` 得到 `f 0 = f 3`，另一次直接当作 `∧` 的右半边）。**两版对比**：

**够不着的写法**（都不起名字）：

```
  have : f 0 = f 2 := (h 0).trans (h 1)
  have : f 0 = f 3 := this.trans (h 2)
  ⟨this, this⟩
```

实跑报错（**逐字**）：

```
error: Application type mismatch: The last
  this
argument has type
  f 0 = f 3
but is expected to have type
  f 0 = f 2
```

**读法**：第二个 `this` 已经是 `f 0 = f 3` 了——**早先那条 `f 0 = f 2` 再也够不着**。

**起名字的写法**（给那条要用两次的起名）：

```lean
section naming_when_needed
theorem naming_when_needed (f : Nat → Nat) (h : ∀ x : Nat, f x = f (x + 1)) : f 0 = f 3 ∧ f 0 = f 2 :=
  have h02 : f 0 = f 2 := (h 0).trans (h 1)
  have : f 0 = f 3 := h02.trans (h 2)
  ⟨this, h02⟩
end naming_when_needed
```

**这条能过**，因为 `h02` 起了名字，**回头引用得到**。

> 📌 **本课的口诀**：**用完就不管 → 匿名；还要回头用 → 起名字。**
> （上面的例子就是「混用」：`h02` 起了名字，其余的都匿名。）

## §6 本课不引入：原文那两个**其实是 tactic** 的写法

原文这一节还给了 `by assumption` 和 `‹p›`，**本课不引入**——但我要**如实讲清它们是什么**，
因为这里藏着一个**很值得记住的陷阱**。

| 原文里的东西 | 是什么 | 归属 |
|---|---|---|
| `by assumption` | **`assumption` tactic**：让 Lean 自己去局部上下文里找一条能用的假设 | **第 5 章（Tactics）**（原文自己也说「we will learn more … in the next chapter」） |
| `‹p›`（法式引号，输入 `\f<` / `\f>`） | **是 `by assumption` 的语法糖**。Lean 里的定义就一行：`notation "‹" p "›" => show p by assumption` | **第 5 章** |
| `‹Nat›`（拿它引**数据**而不是命题） | 还是 `‹p›` 那个记法，只是里面放了个**类型**而不是命题；原文说「用它是有点怪」 | 第 5 章 |

### ⚠️ 顺手记住一个教训

`‹p›` **看起来**像个普通的项（就像 `⟨…⟩` 那样），可它的定义里**明明白白写着 `by assumption`** ——
**用 `‹p›` 就是在用 tactic**。

而且**实测**：这一条

```lean
section corner_quotes
theorem corner_quotes (p : Prop) (hp : p) : p := ‹p›
end corner_quotes
```

**能编译**，`#print axioms` 还会告诉你 `does not depend on any axioms`。

→ 所以：

> **`#print axioms` 只能判断「依不依赖公理」，判断不了「内部用没用 tactic」。**
> 想知道是否用了 tactic，只能看**它的定义**（或者**根本不用它**）。

（这和 03-8 那条「证明通过 ≠ 不需要经典」是**同一类**教训：**一个测试通过，不等于所有问题都回答了**。）
