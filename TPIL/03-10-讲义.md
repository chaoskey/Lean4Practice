## 2. 拿到目标，先看形状

前九课你学的是「这些零件分别是什么」。今天补上另一半：**看到目标怎么下手**。

下面这张表是本课最要紧的东西。**从左往右读三遍**：目标里出现了什么 → 第一步做什么 → 用哪个构造子。

| 目标里出现 | 第一步做什么 | 用哪个 |
|---|---|---|
| `↔` | **先拆成两个方向**，各写一个证明 | `Iff.intro`（简写 `⟨,⟩`） |
| 最外层是 `→` | 写一个 `fun`，把左边那个东西**收成假设** | `fun` |
| `∧`，且它在**要交的位置** | 你得**同时**造出两个东西 | `⟨,⟩` / `And.intro` |
| `∨`，且它在**要交的位置** | **挑一边**造——先想清楚挑哪一边 | `Or.inl` / `Or.inr` |
| 手上是 `∨`，但目标要**别的** | 对它**分情况**，而且**两个分支都要交出目标** | `Or.elim` |
| `¬` | 心里默念：**`¬x` 就是 `x → False`**，不是别的东西 | —— |
| 手上有一对矛盾（某个 `x` 和某个 `¬x`）| **炸**：`False.elim` 或 `absurd` | `False.elim` / `absurd` |
| ⚠️ **手上什么都没有**，你需要先知道某个命题的真假 | **只有到这一步**才动用经典 | `em` / `byCases` / `byContradiction` |

### 最后一行，是本课最值钱的一行

> **手上还有材料，就永远不必动用经典。**

`Or.elim` 只是问「手上这个析取式是哪一边」——**构造性的**。
`byCases` 是要判断「`p` 到底是不是真的」——**经典的**。

这两件事只差一个「手上有没有材料」。

> 📌 03-9 的 `ex1` 就是活例子：第一版你写了 `byCases`，第二版改成对 `h.left` 用 `Or.elim`——**同一个证明，从「带经典」变成「零公理」，只差把这一步换成「问手上有什么」**。

### 用表走一遍

**例 A**：`(p → q → r) → (p → q) → (p → r)`

```
最外层是 →          → 写 fun 收下 (p → q → r)
  收下后最外层还是 → → 再写 fun 收下 (p → q)
    再往里还是 →     → 再写 fun 收下 p
      此时手上：h1 : p → q → r   h2 : p → q   hp : p
      要交出 r，而 h1 能给 r   → h1 hp (h2 hp)
```

```lean
theorem exA (p q r : Prop) : (p → q → r) → (p → q) → (p → r) :=
  fun h1 h2 hp => h1 hp (h2 hp)
```

**例 B**：`(p ∨ q) → (q ∨ p)`

```
最外层是 →       → 写 fun 收下 (p ∨ q)
  手上是 ∨，目标是 ∨  → 用 Or.elim 分情况（不是 byCases！）
    分支一：hp : p  → 目标 q ∨ p，p 放右边 → Or.inr hp
    分支二：hq : q  → 目标 q ∨ p，q 放左边 → Or.inl hq
```

```lean
theorem exB (p q : Prop) : (p ∨ q) → (q ∨ p) :=
  fun h => Or.elim h (fun hp => Or.inr hp) (fun hq => Or.inl hq)
```

## 3. 工具箱：五族构造子

前九课按「语法」学的。今天按**用途**重排——做题时按用途去拿。

### 族一：合取 `∧` —— **同时**给两个东西

| | |
|---|---|
| **造** | `⟨a, b⟩` 或 `And.intro a b` |
| **取** | `h.left`（第一个）、`h.right`（第二个） |
| **要点** | `And` 是 `structure`，**只有 1 个构造子**，所以 `⟨,⟩` 可用 |

### 族二：析取 `∨` —— **挑一个**给

| | |
|---|---|
| **造** | `Or.inl a`（放**左边**）、`Or.inr a`（放**右边**） |
| **拆** | `Or.elim h (分支一) (分支二)`——**两个分支都必须交出同一个目标** |
| **⚠️ 要点** | `Or` 是 `inductive type`，**有 2 个构造子**，所以**不能用 `⟨,⟩`** |

> ⚠️ **`Or` 没有 `.left` / `.right`。** 那两个字段是 `And` 才有的。
> 写 `h.left` 而 `h : p ∨ q`，会报：
```
> error: Invalid field `left`: The environment does not contain `Or.left`
```

### 族三：等价 `↔` —— **一次**给两个方向

| | |
|---|---|
| **造** | `Iff.intro (正向) (反向)`，或简写 `⟨正向, 反向⟩`（**正向在前**） |
| **取** | `h.mp`（正向）、`h.mpr`（反向） |
| **⚠️ 要点** | `Iff` **没有** `.left` / `.right`，只有 `.mp` / `.mpr` |

### 族四：否定 `¬` 与矛盾

| | |
|---|---|
| **`¬p` 是什么** | 就是 `p → False`。**按定义相等**，不是「近似」 |
| **造 `¬p`** | `fun hp => <造出 False>` |
| **两个矛盾** | `absurd : p → ¬p → <任何>` |
| **手上已有 `False`** | `False.elim : False → <任何>` |
| **要点** | `absurd` **自己造**矛盾；`False.elim` **要求你已经有** `False` |

### 族五：经典逻辑 —— **最后才用**

| 工具 | 类型形状 |
|---|---|
| `em` | `p → p ∨ ¬p` |
| `byContradiction` | `(¬p → False) → p` |
| `byCases` | `(p → q) → (¬p → q) → q` |

> ⚠️ 这三个**全部**是经典原理的证明项。用了它们，`#print axioms` 就会显示 `[propext, choice, Quot.sound]`。

## 4. 「要不要经典」：判据与查法

### 4.1 判据只有一条：**你手上有没有材料**

```
手上是 ∨        → Or.elim（零公理）
手上是一对矛盾  → False.elim / absurd（零公理）
手上什么都没有，需要判断真假 → 才用经典（带公理）
```

### 4.2 「需要经典」不等于「用了经典」

这两件事要分开：

| | 说的是 |
|---|---|
| **「这条命题需要经典」** | 它**构造性不可证**——不管你怎么写都要用经典 |
| **「我的证明用了经典」** | 我**这一版**用了经典——可能只是绕了远路 |

**判定第一条要靠反模型**（本课不展开）；**判定第二条只要能造出一个零公理版本**。

> 📌 03-9 的 `ex5`、`ex6` 就是「需要经典」的真例子——那两条有 2 世界 Kripke 反模型。
> 而 03-9 的 `ex1` 是「**不**需要经典」的例子：库里和手写版都是零公理。

### 4.3 唯一可靠的查法

```
#print axioms 你的定理名
```

三种可能的输出，各有含义：

| 输出 | 含义 |
|---|---|
| `'名字' does not depend on any axioms` | **零公理**——纯构造 |
| `'名字' depends on axioms: [propext, choice, Quot.sound]` | **用了经典** |
| `'名字' depends on axioms: [sorryAx]` | ⚠️ **文件里还有 `sorry`**——题没做完 |

> ⚠️ **「能编译」不能当判据**。03-9 你已经亲手撞过一次：去掉 `open Classical`，`byCases` 立刻变成 `Unknown identifier`。

## 5. 你一定会撞到的五个坑

这五个都是前九课里**真实出现过**的。撞到时先来这里对一遍。

### 坑一：`Or.inl` 和 `Or.inr` 拿反了

`Or.inl` 把东西放**左边**，`Or.inr` 放**右边**。

**例 B 如果写反**（`hp : p` 却用 `Or.inl`，`hq : q` 却用 `Or.inr`）：

```
error: Application type mismatch: The argument hp
  has type p
  but is expected to have type q
```

> ⚠️ **目标换了，边就换了。** 目标是 `q ∨ p` 时，手上的 `p` 要用 **`Or.inr`**。
> **每写一个 `inl`/`inr` 就问一句：「它要的是不是我要喂的那一边？」**

### 坑二：给 `Or` 用 `.left` / `.right`

`.left` / `.right` 是 **`And` 的字段**。`Or` 没有，报 `Invalid field`。

`Or` 只有两个构造子，要拆它只能用 **`Or.elim`**。

### 坑三：给 `Iff` 用 `.left` / `.right`

`Iff` 的两个字段叫 **`mp`** 和 **`mpr`**。写 `h.left` 会报 `Invalid field`。

### 坑四：目标是 `¬X` 时改成写 `False`

当你要交出一个「把 `fun` 交给否定假设」的证明时：

```
目标写成 X → False          ✅ 稳
目标写成 X → ¬Y             ⚠️ 容易出 Application type mismatch
```

> 📌 03-5 实测过这两种写法的差别：**内层 `fun` 的函数体是「应用」时，写 `False` 才稳。**

### 坑五：隐式参数钉不住

`byCases` 的「要分类的命题」是**隐式参数**。如果你传给它的两个分支都是 `sorry`，Lean 没有任何信息能确定那个参数是谁：

```
error: don't know how to synthesize implicit argument `p`
    @byCases (?m.3 p A1) (p ∨ ¬p) sorry sorry
```

**解法：用具名参数钉住它**：

```
byCases (p := p) (分支一) (分支二)
```

> 📌 读这类报错的窍门：**Lean 会把 `@函数` 展开给你看，带 `?` 的那一项就是还没定下来的隐式参数。**
