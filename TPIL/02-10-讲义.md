# 第 2 章 · 第 10 课：隐式参数（implicit arguments）

> 📄 **示例**：`02-10-示例.lean`（我写的，已通过编译、零 warning）
> ✍️ **习题**：`02-10-习题.lean`（**你写**）
> 📖 **原文**：<https://lean-lang.org/theorem_proving_in_lean4/Dependent-Type-Theory/#implicit-arguments> 的 **2.9** 小节
> 🔤 **打不出符号时**：看 [`Unicode速查.md`](./Unicode速查.md)（跨课参考）
> **本课的一句话**：**有些参数不用你写**——Lean 能推出来；把它们放进**花括号**，就变成**隐式参数**。

---

## 1. 本课的一句话

- **`{α : Type}`（花括号）**：声明一个**隐式参数**——**调用时默认不用写**，Lean 自己推。
- **`_`（下划线）**：在**用**的时候说「这里**让 Lean 自己填**」。
- **`@foo`**：把 `foo` 的**所有**参数都变回**显式**，需要手动指定时用。

---

## 2. 问题：类型参数写起来太啰嗦

先看一个例子（下面三个定义只是把 `List` 换了个名字）：

```lean
def Lst (α : Type) : Type := List α
def Lst.cons (α : Type) (a : α) (as : Lst α) : Lst α := List.cons a as
def Lst.nil (α : Type) : Lst α := List.nil

#check Lst.cons Nat 0 (Lst.nil Nat)
def as : Lst Nat := Lst.nil Nat
def bs : Lst Nat := Lst.cons Nat 5 (Lst.nil Nat)
```

实测（3 行）：

```
Lst.cons Nat 0 (Lst.nil Nat) : Lst Nat
Lst.cons Nat 0 (Lst.nil Nat) : Lst Nat
```

**看出来了吗**：`Nat` 被写了 **4 遍**（`Lst.cons Nat`、`Lst.nil Nat`、`Lst.cons Nat`、`Lst.nil Nat`），
而这些 `Nat` **一个都不需要你写**——它们**能从上下文推出来**：

- `Lst.cons Nat 0 …` 里的 `Nat`：**从第二个参数 `0` 的类型**就能知道（`0` 是 `Nat`）；
- `Lst.nil Nat` 里的 `Nat`：**从它被送进的位置**就能知道（`Lst.cons` 的第三个参数要求 `Lst α`，而 `α` 已经定成 `Nat`）。

原文对此有一句总结（我翻译）：

> 这是**依赖类型论的核心特征**：**项（term）携带了大量信息**，而其中一些信息**可以从上下文中推断出来**。

---

## 3. 下划线 `_`：让 Lean 自己填

原文（我翻译）：

> 在 Lean 里，**用下划线 `_` 表示「系统应该自动把这条信息填上」**。这被称为「**隐式参数**（implicit argument）」。

实测（**和写全 `Nat` 的输出一模一样**）：

```lean
#check Lst.cons _ 0 (Lst.nil _)
def as2 : Lst Nat := Lst.nil _
def bs2 : Lst Nat := Lst.cons _ 5 (Lst.nil _)
```

实测（2 行）：

```
Lst.cons Nat 0 (Lst.nil Nat) : Lst Nat
```

（上面 `Lst`、`Lst.cons`、`Lst.nil` 就是 **§2** 定义的那三个。）

**看第一行**：我写的是 `Lst.cons _ 0 (Lst.nil _)`，Lean 打出来的是 `Lst.cons Nat 0 (Lst.nil Nat)`——
**两个 `_` 都被填成了 `Nat`**。

---

## 4. 花括号 `{}`：默认就不用写

可是**到处写 `_` 也很烦**。原文（我翻译）：

> 不过要打这么多下划线还是很累。当一个参数**通常能从上下文推出来**时，
> Lean 允许你声明：这个参数**默认就是隐式的**。做法是**把参数放进花括号**里。

实测：

```lean
def Lst2.cons {α : Type} (a : α) (as : List α) : List α := List.cons a as
def Lst2.nil {α : Type} : List α := List.nil

#check Lst2.cons 0 Lst2.nil
def as3 : List Nat := Lst2.nil
def bs3 : List Nat := Lst2.cons 5 Lst2.nil
```

实测：

```
Lst2.cons 0 Lst2.nil : List Nat
```

**注意**：调用时写的是 `Lst2.cons 0 Lst2.nil`——**`Nat` 一次都没出现**，可类型还是 `List Nat`。
原文说得很准：

> **唯一的变化**就是 `α : Type` **外面多了花括号**。

### 花括号也能用在**普通函数定义**里

```lean
def myId {α : Type} (x : α) : α := x

#check (myId)
#check myId 1
#check myId true
#check @myId
```

实测（4 行）：

```
myId : ?m.1 → ?m.1
myId 1 : Nat
myId true : Bool
@myId : {α : Type} → α → α
```

逐行看：

- **第 1 行 `myId : ?m.1 → ?m.1`**：⚠️ 这里的 **`?m.1` 是「待定」（占位符）**——
  因为 `#check (myId)` 里**没给它任何线索**，Lean 只好留一个「以后再说」的位置。
  （`?m` 这种编号 **02-4** 见过：那是「待定」被创建时的序号。）
  > 原文对此有一句话：**检查 `myId` 的类型时要加括号** `#check (myId)`——
  > 不加括号的话，Lean 会把 `myId` 当成**一条命令**，而不是**一个表达式**。
- **第 2、3 行**：一旦**给了参数**（`1`、`true`），Lean 立刻从参数类型推出 `α`——
  所以 `myId 1 : Nat`、`myId true : Bool`。**同一个 `myId`，两个不同的类型。**
- **第 4 行**：`@myId : {α : Type} → α → α`——见 **§7**（`@`）。

## 5. `variable` 也能声明隐式（接 02-7）

**02-7** 学过用 `variable` 声明变量；那里也能直接写**花括号**：

```lean
section
  variable {α : Type}
  variable (x : α)
  def myId2 := x
end

#check myId2
#check myId2 4
#check myId2 true
```

实测（3 行）：

```
myId2 {α : Type} (x : α) : α
myId2 4 : Nat
myId2 true : Bool
```

**看第 1 行**：`#check` 打出的类型里，**`α` 带着花括号** `{α : Type}`——
**这说明它是个隐式参数**。而 `(x : α)` 是圆括号 → 显式，要写。

> 原文说：这样定义的 `myId2` 与上面那个 `myId` **效果一样**——
> **哪一点一样**：都是「`α` 隐式、`x` 显式」，调用时都只写一个参数。

---

## 6. `(e : T)`：给它一个类型，帮 Lean 把隐式参数定下来

原文（我翻译）：

> 你**总是**可以用 `(e : T)` 的形式给表达式 `e` **指定类型 `T`**。
> 这会告诉 Lean 的**推演器**：在解析隐式参数时，**把 `T` 当作 `e` 的类型**来用。

实测——**对比着看**：

```lean
#check (List.nil)
#check (List.nil : List Nat)
#check (myId)
#check (myId : Nat → Nat)
```

实测（4 行）：

```
[] : List ?m.1
[] : List Nat
myId : ?m.1 → ?m.1
myId : Nat → Nat
```

**第 1 行 vs 第 2 行**：`List.nil` 平时打印成 **`[]`**（这是它的显示形式）。
不给类型时是 `[] : List ?m.1`（**待定**）；给了 `: List Nat` 就**定下来了** → `[] : List Nat`。
**第 3、4 行**同理（`myId` 是 **§4** 定义的那个）。

> 💡 **这就是「信息不够」时的救命写法**：Lean 推不出来，你就**告诉它**。

---

## 7. `@foo`：把**所有**参数都变回显式

原文（我翻译）：

> 有时候我们已经把某个参数声明成**隐式**了，却**现在想显式地把它传进去**。
> 如果 `foo` 是这样的函数，那么记号 **`@foo`** 表示**把所有参数都变成显式**之后的同一个函数。

实测：

（`myId` 就是 **§4** 定义的那个。）

```lean
#check @myId
#check @myId Nat
#check @myId Nat 1
#check (@myId Bool true)
```

实测（4 行）：

```
@myId : {α : Type} → α → α
myId : Nat → Nat
myId 1 : Nat
myId true : Bool
```

**盯着第 1 行看——这里有个容易误会的地方**：

```
@myId : {α : Type} → α → α
        ↑ 花括号还在！
```

**`@` 并没有把花括号去掉**。它表示的是：**这个参数「本质上」仍然是隐式的，但你现在必须显式地把它交出来**。
所以：

- `@myId` 的**类型**里，第一个参数**仍显示为 `{α : Type}`**（它是在告诉你「这条是隐式的」）；
- 但**用**的时候，你**必须**写出来：`@myId Nat 1` ✅（而 `myId Nat 1` ❌ 会把 `Nat` 当成 `x`）。

> 📌 **这就是 02-8 里那个 `@List.cons` 的来历**——那时我让你「先别管它」，现在你知道了。

## 8. 「数字是多态的」——你 02-9 问过的那个，本课正名

原文（我翻译）：

> 数字在 Lean 里是**重载（overloaded）**的；当**数字的类型推不出来**时，Lean **默认把它当成自然数**。

实测：

```lean
#check 2
#check (2 : Nat)
#check (2 : Int)
```

实测（3 行）：

```
2 : Nat
2 : Nat
2 : Int
```

- 第 1 行：**没给任何线索** → 默认 `Nat`；
- 第 2 行：明说 `Nat` → 一样；
- 第 3 行：明说 `Int` → 这次**当成整数**。

> 📌 **连回 02-9**：你在那一课问「`0 : Fin (n+1)` 凭什么能写」——
> 那靠的**正是本课这套机制**（「数字的类型由上下文决定」）。
> ⚠️ 具体的实现细节（**类型类实例**）属**第 10 章**，本课**不引入**——本课只讲清「它靠上下文推断」这一层。

### 顺带一个术语：**elaboration（推演）**

原文（我翻译）：

> Lean 有一套很复杂的机制来实例化隐式参数……
> 把这些「**洞**」「**占位符**」填上的过程，通常叫做 **elaboration**。
> 隐式参数的存在意味着：**有时候信息不足以唯一确定一个表达式的含义**。
> 像 `myId` 或 `List.nil` 这样的表达式被称为**多态的（polymorphic）**——它在不同上下文里可以有不同的含义。

**回看 §4 第 1 行那个 `?m.1`**：那就是「**信息不足**」留下的洞。

1. **`universe u` / `Type u` / `Sort`**：原文 2.9 的例子都写了 `universe u`、把类型写成 `Type u`，

## 10. 小结

本课记住四件事：

1. **`_`**：用的时候说「**让 Lean 自己填**」——`Lst.cons _ 0 (Lst.nil _)` 与写全 `Nat` **输出一样**。
2. **`{α : Type}`**：**声明**成隐式——调用时**默认不用写**；`#check` 打出的类型里它会**带花括号**。
   **`variable {α : Type}`** 也能这么声明。
3. **`(e : T)`**：**给类型**，帮 Lean 把隐式参数定下来（`[] : List ?m.1` → `[] : List Nat`）。
4. **`@foo`**：把参数**全变显式**（想手动指定时用）——
   注意 **`@` 不会去掉花括号**，它只是说「这条现在必须你给」。
   **`?m.1`** 是「信息不足」留下的**待定**；数字推不出来时**默认 `Nat`**。
