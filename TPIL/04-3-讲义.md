## 2. `=` 的三条性质

原文说：`=` 首先是一个**等价关系**（equivalence relation）——自反、对称、传递。Lean 里对应三个函数：

```lean
section eq_basics
#check @Eq.refl
#check @Eq.symm
#check @Eq.trans
end eq_basics
```

**实测输出**：

```
@Eq.refl : ∀ {α : Sort u_1} (a : α), a = a
@Eq.symm : ∀ {α : Sort u_1} {a b : α}, a = b → b = a
@Eq.trans : ∀ {α : Sort u_1} {a b c : α}, a = b → b = c → a = c
```

逐条读：

| 函数 | 类型（去掉 `@` 的显式写法就是它） | 读作 |
|---|---|---|
| `Eq.refl a` | `a = a` | **自反**：任何东西都等于自己 |
| `Eq.symm h` | `b = a`（当 `h : a = b`） | **对称**：把等式掉个头 |
| `Eq.trans h₁ h₂` | `a = c`（当 `h₁ : a = b`、`h₂ : b = c`） | **传递**：接起来 |

**三个参数的隐显**（沿用 04-2 §3 的读法）：

- `{α}`、`{a b c}` 都是**隐式**（花括号）——由上下文推出来。
- `Eq.symm` 的 `h`、`Eq.trans` 的 `h₁ h₂` 是**显式**——要你写。

> ⚠️ **本课不要求理解的部分**：输出里的 **`Sort u_1`**。
> 那是**宇宙**（后面的章节才讲）。本课把它**读作「任意类型」**即可——`{α : Sort u_1}` 就是「`α` 是任意一个类型」。
> （04-2 §6 里已经见过一次 `Type 1`，当时也只要求看结论。）

## 3. `=` 是什么：`#print Eq`

`Eq` 不是一个「语法符号」，它是库里一个**真正的类型**。用 `#print` 看它（`#print` 在 2-5 学过）：

```lean
section eq_print
#print Eq
end eq_print
```

**实测输出**：

```
inductive Eq.{u_1} : {α : Sort u_1} → α → α → Prop
number of parameters: 2
constructors:
Eq.refl : ∀ {α : Sort u_1} (a : α), a = a
```

**从这三行里读出两件事**（其余都不用管）：

| 读什么 | 读出来 |
|---|---|
| `Eq : {α : Sort u_1} → α → α → Prop` | `Eq` 收两个 `α` 的元素、吐一个 **`Prop`**——**所以 `a = b` 是一个「命题」，是要你去证明的东西** |
| `constructors:` 下面只有 `Eq.refl` | `=` 的**唯一构造子**就是 `Eq.refl`——**所有「相等」的证明最终都从它来** |

> ⚠️ **本课不要求理解的部分**：`inductive`（归纳类型）、`number of parameters`。
> 那是**第 7 章**的内容。本课只需要上面那两行结论。

## 4. `rfl`：`Eq.refl _` 的记号

原文说：`rfl` 就是 `Eq.refl _` 的**记号**（notation）。

先看它能证什么——**注意：下面三条都 _不是_ `x = x` 的形状**：

```lean
section rfl_power
variable (α β : Type)

example (f : α → β) (a : α) : (fun x => f x) a = f a := rfl
example (a : α) (b : β) : (a, b).1 = a := rfl
example : 2 + 3 = 5 := rfl
end rfl_power
```

三条都通过。为什么？**因为它们左右两边「算出来是同一个东西」**：

| 等式 | 左边算成 | 右边 | 算完是不是同一个 |
|---|---|---|---|
| `(fun x => f x) a = f a` | `f a`（把 `a` 代进去） | `f a` | ✅ 是 |
| `(a, b).1 = a` | `a`（取第一个分量） | `a` | ✅ 是 |
| `2 + 3 = 5` | `5` | `5` | ✅ 是 |

> ## ⭐ 关键
> **Lean 把「算出来一样」的两个项当作同一个项。**
> 所以 `rfl` 能证的，远不止 `x = x`。

同一件事，用 `Eq.refl _` 写出来（`_` 是 2-10 学过的「让 Lean 自己填」）：

```lean
section rfl_is_eq_refl
example : 2 + 3 = 5 := Eq.refl _
end rfl_is_eq_refl
```

两条都通过——**`rfl` 与 `Eq.refl _` 是同一个东西的两种写法**。

## 5. ⭐ 定义相等 vs 命题相等（本课核心）

上面那句「算出来一样」，在 Lean 里有个正式名字：**定义相等**（definitional equality）。
而 `a = b` 这个**命题**叫**命题相等**（propositional equality）。**这是两种不同的东西：**

| | **定义相等** | **命题相等** |
|---|---|---|
| 说的是什么 | 「这两个项**算出来是不是同一个**」 | 「`a = b` 这个**命题**」 |
| 谁来判断 | **Lean 的类型检查器**（自动算，不用你证） | 需要**一个证明** |
| 怎么用 | `rfl`（以及类型检查本身） | 手上拿到 `h : a = b`，再用 `h` |
| 不属于 | 不是命题、没有证明 | 是 `Prop`（§3 的 `#print` 读出来的） |

### 5.1 三个判定实验（全部实测）

```lean
section boundary_ok
-- ✅ 能：`n + 0` 算出来就是 `n`
example (n : Nat) : n + 0 = n := rfl
end boundary_ok
```

```lean
section boundary_lib
-- `rfl` 证不出的，不代表命题不成立——它可能要靠别的引理
#check Nat.zero_add
#check Nat.add_zero
example (n : Nat) : 0 + n = n := Nat.zero_add n
end boundary_lib
```

**上面两个块通过；下面两个是故意写错的**（所以它们没有用 ```lean 标记）：

```
example (n : Nat) : 0 + n = n := rfl
```

实测报错（逐字）：

```
error: Type mismatch
  rfl
has type
  ?m.9 = ?m.9
but is expected to have type
  0 + n = n
```

```
example (a b : Nat) (h : a = b) : a = b := rfl
```

实测报错（逐字）：

```
error: Type mismatch
  rfl
has type
  ?m.4 = ?m.4
but is expected to have type
  a = b
```

> ⚠️ `?m.9`、`?m.4` 这类**编号**是 Lean 内部的，**会随文件内容变化**（04-2 §3.2 讲过）。
> 要紧的是报错在说什么：**`rfl` 只能交出 `?m = ?m` 这种形状，而目标不是那个形状。**

### 5.2 为什么？逐条说

| 目标 | 能不能 `rfl` | 为什么 |
|---|---|---|
| `n + 0 = n` | ✅ | **加法是按第二个参数递归定义的**：`n + 0` 走递归的**基**那一步，**算出来就是 `n`** |
| `0 + n = n` | ❌ | 第二个参数是**变量 `n`**，递归走不动 → **算不出结果**。它**是真的**，但要靠 `Nat.zero_add n` 来证 |
| `2 + 3 = 5` | ✅ | 两边都是具体数字，**都算成 `5`** |
| `h : a = b` ⊢ `a = b` | ❌ | `h` 是**命题相等的一个证明**；`a` 与 `b` 是**两个不同的变量**，算不成同一个项 |

> ## ⚠️ 一条硬规矩（03-8 学过的教训，这里第一次真正用上）
> **「`rfl` 报错」≠「这个等式不成立」。**
> `0 + n = n` 用 `rfl` 证不出，可它是**真命题**——`Nat.zero_add n` 就是它的证明。
> 报错只能否掉**你写的那个证明**，不能否掉**命题本身**。

### 5.3 一句话

> **`rfl` 能证的，恰好是「两边定义相等」的那些等式。**
> 定义相等 **证不出**、但命题为真的等式（如 `0 + n = n`），要靠**别的证明**——比如库里的引理，
> 或者 04-4 要学的**替换**（`Eq.subst` / `▸`）。

## 6. 投影写法：`h.symm` / `h.trans`

`Eq.symm h` 可以写成 `h.symm`，`Eq.trans h₁ h₂` 可以写成 `h₁.trans h₂`——就是 3-6 学的**点号记法**
（那时是 `h.mp` / `h.left`，这里是 `h.symm` / `h.trans`）：

```lean
section dot_notation
variable (α : Type) (a b c d : α)
variable (hab : a = b) (hcb : c = b) (hcd : c = d)

example : a = d := Eq.trans (Eq.trans hab (Eq.symm hcb)) hcd
example : a = d := (hab.trans hcb.symm).trans hcd
end dot_notation
```

两个 `example` 说**同一件事**，只是第二个用了点号。

---

## 7. 把两个例子逐层拆开

上面第二个 `example` 拆开看类型（每一步都是 04-2 学的「消去」）：

| 表达式 | 类型 | 做了什么 |
|---|---|---|
| `hab` | `a = b` | 手上的材料 |
| `hcb` | `c = b` | 手上的材料 |
| `hcb.symm` | `b = c` | 把 `hcb` **掉个头** |
| `hab.trans hcb.symm` | `a = c` | 从 `a` 接到 `c` |
| `hcd` | `c = d` | 手上的材料 |
| `(hab.trans hcb.symm).trans hcd` | `a = d` | 从 `a` 接到 `d` |

> 📌 与 04-2 §4 那个「等价关系」的例子**结构完全一样**——
> 那里用的是任意关系 `r` 的 `symm_r` / `trans_r`，这里用的是**取 `r` 为 `=` 时库里的那两个**。
