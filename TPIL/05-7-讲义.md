## §1 为什么需要「结构化」

原文（5.4 第一段，**逐字翻译**）：

> 策略（tactic）常常能高效地构造证明，但**一长串指令会掩盖论证的结构**。
> 本节介绍一些手段，帮助给「策略式证明」**提供结构**，让这样的证明**更好读、更稳**。

我们前几课的证据：05-6 §2.3 那个 `p ∨ q → r` 的证明，两个分支是**靠「一行交一个」**的顺序隐式对应的——
读者得自己数「这一行是交给哪个目标的」。本课就是把这个对应关系**写出来**。

## §2 子弹 `·`（与原文用的 `.`）：把每个子目标**包成一块**

原文（5.4 第十一段，**逐字翻译**）：

> 我们用 `.` 来创建**嵌套的策略块**。在嵌套块里，Lean **聚焦于第一个目标**；
> 如果这个块**结束时它还没有被完全解决**，就会**报错**。这有助于**指明**
> 由某个策略引入的**多个子目标各自对应的证明**。
> `.` 这个记号是**对空格敏感的**——它靠**缩进**判断策略块在哪里结束。
> 另一种做法是用**花括号与分号**来定义策略块。

### §2.1 基本写法：一行一个块

```lean
example (p q : Prop) (h : p ∧ q) : q ∧ p := by
  constructor
  · exact h.right
  · exact h.left
```

**实测**：上面这段 **rc=0** ✓。（`·` 是 U+00B7；**原文写的是 `.`**，实测两种都能用：）

```lean
example (p q : Prop) (h : p ∧ q) : q ∧ p := by
  constructor
  . exact h.right
  . exact h.left
```

### §2.2 ⭐ 块「没解完」就报错（这是块的价值所在）

（**故意写错**：第一个块里 `constructor` 造出两个目标，却只交了一个。）

```text
example (p q : Prop) (h : p ∧ q) : (p ∧ p) ∧ q := by
  constructor
  · constructor
    exact h.left
  · exact h.right
```

```text
error: unsolved goals
case left.right
p q : Prop
h : p ∧ q
⊢ p
```

⚠️ 注意目标名 **`case left.right`**——它把「这个目标在**哪一层、哪一支**」也写出来了
（`left` 是外层 `∧` 的第一支，`right` 是它里面的第二支）。
**这就是块的用处**：它把「哪个子目标归谁」从「靠数行」变成**写清楚**。

### §2.3 ⚠️ `·` 对缩进敏感（原文原话）

（**故意写错**：第二个 `·` 多缩进了一个空格。）

```text
example (p q : Prop) (h : p ∧ q) : q ∧ p := by
  constructor
  · exact h.right
   · exact h.left
```

```text
error: unexpected token '·'; expected command
```

所以：**同一层的 `·` 必须对齐**（原文说的「靠缩进判断块在哪里结束」就是这个意思）。

### §2.4 花括号块 `{ … }`（原文给的另一种写法）

```lean
example (p q : Prop) (h : p ∧ q) : q ∧ p := by
  constructor
  { exact h.right }
  { exact h.left }
```

**实测 rc=0** ✓。原文还提到「**花括号与分号**」那套写法；⚠️ 但 **`;` 有它自己的坑**（05-3 §6 已实测：

```text
example (p q : Prop) (h : p ∧ q) : q ∧ p := by
  constructor
  · exact h.right; exact h.left
```
```text
error: No goals to be solved
```
——`;` 会把后面的指令作用到**所有**子目标，和 `·` 的「只聚焦一个」冲突）。**本课一律用 `·`／`case`／`{ }`。**

### §2.5 `·` 里还能再嵌 `·`

```lean
example (p q r : Prop) (h : p ∧ q ∧ r) : r ∧ p := by
  constructor
  · exact h.right.right
  · exact h.left
```

（`h : p ∧ q ∧ r` 在 Lean 里结合成 `p ∧ (q ∧ r)`，所以 `h.right.right : r` ✓。）

## §3 `case 标签 =>`：**事后再聚焦**，顺便命名

`cases h`（不带 `with`）会把假设拆开，但**名字不可引用**（05-4 见过：`h✝`）。
`case` 让你**事后**挑一个子目标、**并且给它命名**：

```lean
example (p q : Prop) (h : p ∨ q) : q ∨ p := by
  cases h
  case inl hp => exact Or.inr hp
  case inr hq => exact Or.inl hq
```

**实测 rc=0** ✓。要点：

- 写法是 **`case 标签 名字… =>`**（标签就是构造子的**短名**，和 05-4／05-6 学的 `inl`／`inr`／`intro` 同一套）；
- 也可以**不写名字**：`case inl => …`（实测通过 ✓）；
- **各支的顺序可以调换**（原文 5.3 明说「新的子目标可以按**任意顺序**解决」）——
  这正是 `case` 比「一行交一个」强的地方：**你可以先做你认为容易的那一支**。

### §3.1 ⚠️ 标签写错会怎样（实测）

```text
example (p q : Prop) (h : p ∨ q) : q ∨ p := by
  cases h
  case zzz => exact Or.inr ‹p›
  case inr hq => exact Or.inl hq
```

```text
error: Case tag `zzz` not found.

Hint: Available tags:
  • `inl`: z̵z̵z̵i̲n̲l̲
  • `inr`: z̵z̵z̵i̲n̲r̲
```

⭐ **报错自己把可用标签列出来了**（和 05-6 §4.2 的 `[match_pattern]` Hint 是同一套好意）。
⚠️ 上面那段里的 **`‹p›` 是「匿名假设」记号**（05-4 §2.4 提过），本课**不要求**用它——
**能用 `case inl hp =>` 起名字，就别用 `‹…›`**。

## §4 `intro | 模式 => …`：请进来的**同时**分两条路

（**原文 5.3 的写法**；05-2／05-6 都把它记在本课。）

```lean
example (p q : Prop) : p ∨ q → q ∨ p := by
  intro
  | Or.inl hp => exact Or.inr hp
  | Or.inr hq => exact Or.inl hq
```

**实测 rc=0** ✓。⚠️ 两条规矩（都是 05-6 §4.2 那条的同一件事）：

- 模式里写的是**构造子**（`Or.inl`）——写短名 `inl` 会报 `Invalid pattern: Expected a constructor or constant marked with `[match_pattern]``；
- 也可以用**匿名构造子记号** `⟨…⟩`（`intro | ⟨hp, hq⟩ => …` ✓）。

## §5 缩进即结构（原文 5.4 第十二段）

原文说：**每当一个策略留下多于一个子目标，就把剩下的子目标用块包起来并缩进**。
拿 05-6 §2.3 那道题对比一下，两种写法并列：

```lean
-- 05-6 的写法：靠「一行交一个」的顺序
example (p q r : Prop) (f : p → r) (g : q → r) : p ∨ q → r := by
  rintro (hp | hq)
  exact f hp
  exact g hq

-- 本课的写法：每个子目标一块，对应关系写在纸面上
example (p q r : Prop) (f : p → r) (g : q → r) : p ∨ q → r := by
  rintro (hp | hq)
  · exact f hp
  · exact g hq
```

两段**都通过** ✓，做的事完全一样——区别只在**可读性**（第二种一眼看出「哪个证明对应哪一支」）。

## §6 判据表：三种聚焦写法怎么选

| 你要干的事 | 写法 | 什么时候用 |
|---|---|---|
| 依次交给两个子目标，**各包一块** | `· 策略` ×2（或 `. 策略`，原文用 `.`） | 最常用；块**没解完会报错**，帮你抓漏 |
| **事后**挑一支、**并且命名** | `case 标签 名字… => 策略` | 目标来自「不带 `with` 的 `cases`／`match`」，名字本来是 ✗ |
| 只想**圈一块**（不想打点） | `{ 策略 }` | 原文给的另一种写法；实测可用 ✓ |
| 请进来的**同时**分两支 | `intro` ＋ `\| 构造子 名字 => 策略` | 原文 5.3 的写法；模式要**构造子**（或 `⟨…⟩`） |

⚠️ **别把 `;` 和 `·` 混用**（§2.4 实测：`No goals to be solved`）。

## §9 一页速查

| 写法 | 对象 ／ 做了什么 |
|---|---|
| `· 策略`（或 `. 策略`） | 聚焦**当前第一个**子目标，把它包成一块；**块没解完就报错**（目标名会印成 `case left.right` 这种**路径**）；⚠️ **同一层的 `·` 必须对齐** |
| `{ 策略 }` | 和 `·` 一样是「圈一块」（原文给的另一种写法）✓ |
| `case 标签 名字… => 策略` | **事后**聚焦到标签对应的子目标，并给它的参数**命名**；标签是构造子**短名**；**各支顺序任意**；写错标签会 Hint 可用标签 |
| `intro` ＋ `\| 模式 => 策略` | 请进来的**同时**分两支；模式要**构造子**（`Or.inl`）或 `⟨…⟩` |
| ⛔ `;` | **别与 `·` 混用**（实测 `No goals to be solved`）；`;` 是 05-9 的话题 |
