## 1. 三个连接词学过之后，来了第四个

| 已学 | 造它（引入） | 用它（消去） |
|---|---|---|
| `→`（3-2） | `fun hp : p => …` | 应用 `hf hp` |
| `∧`（3-3） | `⟨hp, hq⟩` | `.left` / `.right` |
| `∨`（3-4） | `Or.inl hp` / `Or.inr hq` | `Or.elim`（分情况） |
| **`¬`（本课）** | **`fun hp : p => …`（同 `→`！）** | **`False.elim` / `absurd`** |

⚠️ **注意第一行**：`¬` 的「造法」**和 `→` 完全一样**（都是 `fun`）——因为它**根本不是一个新的构造子**，而是**已学过的 `→` 的一个缩写**。这是本课最重要的一件事。

## 2. `False`：一个「没有任何构造子」的命题

`False` 读作「**假**」。实测它长什么样：

```lean
#check Not
#check False
#print False
```

实测输出：

```
Not (a : Prop) : Prop
False : Prop
inductive False : Prop
number of parameters: 0
constructors:
```

⚠️ **请仔细看最后一行**：`constructors:` 后面**是空的**——`False` **一个构造子都没有**。和前两课对比：

| | 头一行 | `constructors:` 后面 |
|---|---|---|
| `#print And`（3-3） | `structure And (a b : Prop) : Prop` | `And.intro`（**1 个**） |
| `#print Or`（3-4） | `inductive Or : Prop → Prop → Prop` | `Or.inl`、`Or.inr`（**2 个**） |
| **`#print False`（本课）** | `inductive False : Prop` | **什么都没有（0 个）** |

**怎么理解「0 个构造子」**：`And` 的证明是「把两样都交出来」，`Or` 的证明是「交左边或交右边」；而 `False` 的证明**必须是某个构造子造出来的**——它一个都没有，所以**你永远造不出 `False` 的证明**。这就是「假」在 Lean 里的全部含义。

（`inductive` 这个词属**第 7 章**，本课只要会数「有几个构造子」即可。）

### ⚠️ 但「造不出」**不等于**「不存在」（2026-09-19 补，学生提问引发的）

一个常见误解是：「`False` 没有构造子，所以它的证明**必须由别的构造子造出来**」。**这半句不对**——`False` 根本没有构造子，**一个都没有**，所以**没有「别的构造子」可以用**。

**实测**：把 §3 那个例子的证明体改成裸的 `False`，会得到这条报错：

```
error: Type mismatch
  False
has type
  Prop
of sort `Type` but is expected to have type
  False
of sort `Prop`
```

**怎么读它**：你写的那个 `False` 是**一个类型的名字**（它的类型是 `Prop`），而**那个位置要的是一份 `False` 的证明**（类型是 `False`）——**两样东西，类型不匹配**。⚠️ 注意 Lean **没有**说「找不到构造子」，它说的是**类型不匹配**。

**那 `False` 的证明从哪来？——「搬」，不是「造」**（这一条实测通过）：

```lean
variable (p q : Prop)

-- 手上**已经有一份** `False` 的证明：直接搬过来，一个构造子都不需要
example (h : False) : False := h

-- 从否定假设**得到**矛盾：靠的是「应用」（3-2 学的），不是构造子
example (hp : p) (hnp : ¬p) : False := hnp hp
```

所以准确的说法是三条：

1. **`False` 的证明不能「从零造出来」**（Lean 不会替你发明矛盾）；
2. **但只要矛盾已经存在，那份证明就在那里**——**可以直接引用**（上面第一行）；
3. **矛盾通常从「已有假设」里来**：把一份证明**喂给否定假设**（`hnq (hpq hp)`、`hnp hp`），或者把「对」交给否定假设（`h ⟨hp, hq⟩`）。

⚠️ **最后分清两件常被混起来的事**：

| | 干什么 | 靠什么 |
|---|---|---|
| **造矛盾** | 造出一份 `False` 的证明 | **应用**已有假设（喂给否定假设） |
| **用矛盾** | `False.elim` / `absurd`：把一份 `False` **消耗掉**，换来任意 `C` | Lean 提供（§4） |

**`False.elim` 不生产矛盾，它只「花掉」矛盾**——这也正好解释了 §4 说的那句话：`False` **只有消去规则、没有引入规则**。

## 3. `¬p` 就是 `p → False`（本课的核心）

`¬p` 读作「**非 `p`**」「**不 `p`**」。它的**定义**是：

```
¬p  ≡  p → False
```

**这不是「打个比方」，而是按定义相等。** 两个方向都实测通过：

```lean
variable (p : Prop)

example (h : ¬p) : p → False := h
example (h : p → False) : ¬p := h
```

**这个定义为什么这么设计？** 因为它把「否定」**翻译成了你已经会的东西**：

> 「`p` 不成立」= 「**如果 `p` 成立，我就能造出一个矛盾**」

于是**证 `¬p` 的套路就出来了**：

1. 先 `fun hp : p => …` **假装 `p` 成立**（把假设引进来的 `fun`，3-2 学的）；
2. 在里面**造出一个 `False`**（矛盾）。

原文的第一个例子就是这个套路：

```lean
variable (p q : Prop)

example (hpq : p → q) (hnq : ¬q) : ¬p :=
  fun hp : p =>
  show False from hnq (hpq hp)
```

**逐行拆**（`show … from` 是 3-2 学的）：

| 这一行 | 在干什么 |
|---|---|
| `fun hp : p =>` | 假装 `p` 成立（`¬p` 就是 `p → …`） |
| `show False from` | 我要造的东西是**矛盾** |
| `hpq hp` | 由 `hp : p` 和 `hpq : p → q` 得 `q`（**应用**，3-2 学的） |
| `hnq (hpq hp)` | 已有 `¬q`，喂给它一个 `q` → 得到 `False`（**因为 `¬q` 就是 `q → False`**） |

## 4. 爆炸原理：`False.elim`（「从矛盾可以推出任何东西」）

原文（我译）：

> 命题 `False` 有一条消去规则 `False.elim`，它表达的是「**anything follows from a contradiction**（矛盾推出任何事）」。这条规则也叫 **ex falso quodlibet**（拉丁语，「由假命题可得出任何结论」），或**爆炸原理（principle of explosion）**。

`False.elim` 的类型（实测）：

```lean
#check False.elim
#check absurd
#check True.intro
```

实测输出：

```
False.elim.{u} {C : Sort u} (h : False) : C
absurd.{v} {a : Prop} {b : Sort v} (h₁ : a) (h₂ : ¬a) : b
True.intro : True
```

**读 `False.elim` 的类型**：

- `{C : Sort u}` 是**隐式参数**（花括号，02-10 学的）——它就是「**要证的那个命题 `C`**」，**你不用写，Lean 自己推**；
- `(h : False)` 是**你唯一要交的东西**：一份矛盾的证明；
- `: C` 是结果——**任意命题**。

**用它**（原文例子）：

```lean
variable (p q : Prop)

example (hp : p) (hnp : ¬p) : q := False.elim (hnp hp)
```

**逐段拆**：`hnp hp` 是「**把 `hp` 喂给否定假设**」，得到 `False`；`False.elim …` 把它交给爆炸原理，于是**任意 `q` 都出来了**——哪怕 `q` 跟 `p` 毫无关系。

**最直白的写法**（等价，实测通过）：

```lean
variable (p q : Prop)

example (h : ¬p) (hp : p) : False := h hp
```

## 5. `absurd`：同一件事的便捷写法

`absurd` 就是「**矛盾**」这个数学词本身。原文（我译）：

> `False.elim` 里那个任意的结论 `q` 是**隐式参数**，由 Lean 自动推断。这个「**从互相矛盾的两个假设推出任意结论**」的模式非常常见，Lean 给它起了个名字叫 **`absurd`**。

`absurd` 的类型（实测，见 §4）：`absurd.{v} {a : Prop} {b : Sort v} (h₁ : a) (h₂ : ¬a) : b`。

**两个显式参数的顺序**：

| 位置 | 类型 | 是什么 |
|---|---|---|
| 第 1 个 `h₁` | `a` | **证明本身** |
| 第 2 个 `h₂` | `¬a` | **对这个证明的否定** |

⚠️ **顺序是「先证明、后否定」**——和 `False.elim (hnp hp)` 那种「先造 `False`」的写法**方向相反**，别弄混。

```lean
variable (p q : Prop)

example (hp : p) (hnp : ¬p) : q := absurd hp hnp
```

**和 §4 的 `False.elim (hnp hp)` 是同一条定理的两种写法**（实测两条都通过）。`absurd` 的好处：**不用先造出 `False` 再交出去**。

原文的另一个例子（把 `absurd` 用在嵌套的假设上）：

```lean
variable (p q r : Prop)

example (hnp : ¬p) (hq : q) (hqp : q → p) : r :=
  absurd (hqp hq) hnp
```

**拆**：`hqp hq : p`（用 `hqp` 把 `hq : q` 变成 `p`）→ 把它交给 `absurd` 的第 1 个参数，第 2 个参数是已有的 `hnp : ¬p` → 得到**任意的 `r`**。

**再来一个把「对」交给否定假设的例子**（`⟨,⟩` 的新用法）：

```lean
variable (p q : Prop)

example (h : ¬(p ∧ q)) (hp : p) : ¬q := fun hq => h ⟨hp, hq⟩
```

**拆**：目标是 `¬q` → `fun hq => …` 假装 `q` 成立；`⟨hp, hq⟩` 造出「`p` 且 `q`」的证明；喂给 `h : ¬(p ∧ q)` → 矛盾。

## 6. ⚠️ 一个 Lean 的 elaboration 小坑（实测，会绊人）

**现象**：当你**把一个 `fun` 交给否定假设**时，**目标怎么写会影响能不能过**。同一个证明（`h` 是「`¬(p → q)`」）：

```lean
variable (p q : Prop)

-- ✅ 目标最后写的是 False —— 通过
theorem u : q → ¬(p → q) → False := fun hq h => h (fun hp : p => hq)
```

而**目标写成那个否定本身**，就会报错：

```
error: Application type mismatch: The argument
  fun hp => hq
has type
  p → q
but is expected to have type
  p
in the application
  h fun hp => hq
```

（故意写错的对照，所以**不放** ```lean 标记——它是「跑不过去」的写法。）

**规律与对策**：

- ✅ **目标里最后那个类型写成 `False`**（也就是「显式地证矛盾」）——**能过**；
- ❌ 把否定**留在目标里**（`: … → ¬(p → q)`）——**报 `Application type mismatch`**；
- **拿不准就先写 `example` 试一遍**（它不检查声明，错了立刻能看到）。

## 7. `True`：顺带认识一句

原文在同一节的末尾提了一句（我译）：

> 就像 `False` 只有一条消去规则一样，`True` 只有一条**引入**规则 `True.intro : True`。换句话说，`True` 就是**真**，并且它有一个**标准的证明** `True.intro`。

**本课只要认识它**：它和 `False` 正好相反——`False` **没有**构造子（造不出证明），`True` **有且只有**一个构造子 `True.intro`（不需要任何前提就能造出来）。

## 8. `False.elim` 里面是什么（看一眼）

```lean
#print False.elim
#print absurd
```

实测输出：

```
def False.elim.{u} : {C : Sort u} → False → C :=
fun {C} h => False.rec (fun x => C) h
def absurd.{v} : {a : Prop} → {b : Sort v} → a → ¬a → b :=
fun {a} {b} h₁ h₂ => False.rec (fun x => b) ⋯
```

⚠️ `False.rec`（**recursor**，「递归子」）属**第 7 章**，**本课不必理解语法**。你只要知道**意思**：

> 「手上有一份 `False` 的证明，就能造出**任何**类型的值。」

**这正是「爆炸原理」在代码里的全部实现。**

## 9. 四个连接词总表

| | 读作 | 造它 | 用它 |
|---|---|---|---|
| `p → q` | 若 `p` 则 `q` | `fun hp : p => …` | `hf hp` |
| `p ∧ q` | 并且 | `⟨hp, hq⟩` | `.left` / `.right` |
| `p ∨ q` | 或 | `Or.inl` / `Or.inr` | `Or.elim` |
| **`¬p`** | **非 `p`** | **`fun hp : p => …`（造出 `False`）** | **`False.elim` / `absurd`（矛盾 → 任意）** |

⚠️ 一句提醒：**`¬` 的优先级比 `→` 高**——`¬p → q` 读作「`(¬p) → q`」，不是「`¬(p → q)`」；要表达后者**必须加括号**（实测 `#check (¬p → q)` 打印 `¬p → q`）。

## 11. 小结

1. **`¬p` 就是 `p → False`**——**按定义相等**（§3 两个方向都实测）。
2. **造 `False` 的唯一办法**：让一个否定假设吃到一份证明（`hnp hp`、`h ⟨hp, hq⟩`）。
3. **`False` 没有构造子** → 造不出它的证明 → 这就是「假」。
4. **爆炸原理**：`False.elim` / `absurd`——**矛盾能推出任意结论**。⚠️ `absurd` 的参数顺序是「**先证明、后否定**」。
5. ⚠️ **把 `fun` 交给否定假设时，目标写成 `False` 更稳**（§6）。
