# 第 5 章 · 第 4 课：**拆开假设**——`cases` 与 `intro ⟨…⟩` 模式

> **原文链接**（想深挖时再看，**不是**理解本课的前提）：
> <https://lean-lang.org/theorem_proving_in_lean4/Tactics/>
>
> **本课范围**：原文 **5.3 More Tactics** 的前段——`cases` 用在 `∨`／`∧`／`∃` 上，以及 `intro` 的模式写法。
> （「前段」是**本项目自己的拆法**：5.3 里还有 `constructor`／`exists`／`rcases` 等，分别归 05-5／05-6。）
>
> **本课一句话**：05-2 的 `intro` 请进假设的**永远是一个名字**；可你手上的假设经常是**一包东西**
> （`p ∧ q`、`p ∨ q`、`∃ x, P x`）——本课学**把它们拆开**（`cases`），
> 以及反过来在**请进来的同时就拆**（`intro ⟨…⟩`）。
>
> ⚠️ **只引入这两件**：`cases`（带／不带 `with` 两种写法）与 `intro ⟨…⟩` 模式；
> `constructor`／`exists`／`rcases`／`rintro`／`case`／`·`／`;` **都不在本课**（§7 有归属表）。

## §1 上一课留下的缺口

05-2 的 `intro` 有个特点：**请进来的永远是一个名字**。

```lean
example (p q : Prop) : p ∧ q → p := by
  intro h          -- 请进来的是「一整包」：h : p ∧ q
  exact h.left     -- 想要 p，得自己从包里取
```

上面这行 `exact h.left` 能用（`.left`／`.right` 是第 4 章学的）——**可要是包里装的**不止一件**东西，
或者包口的形状是 `∨`／`∃`，光靠 `.left`／`.right` 就不够了**。比如：

- `h : p ∨ q`：这包**有两种可能的装法**（左边装 `p`，或者右边装 `q`），你得**分开讨论**；
- `h : ∃ x, P x`：包里装着**一个具体的东西 `x`** 和**它满足 `P` 的证据**，你得把这两样都拿出来；
- 反过来，**目标**左边是 `p ∧ q` 或 `∃ x, P x` 时，`intro h` 请进来的还是一整包。

本课就是办这两件事：

| 手上的情况 | 谁管 |
|---|---|
| 假设是**一包**（`∧`／`∨`／`∃`），要**拆开** | **`cases`**（§2／§3） |
| **目标**左边是 `∧`／`∃`，想**请进来的同时就拆** | **`intro ⟨…⟩`**（§4） |

## §2 `cases` 不带 `with`：先看看包里有什么

**规则（一句话）**：`cases h` 把假设 `h` **按它类型的「造法」拆开**，每一种造法给你一个（或几个）新目标。

下面三段都是**故意不写完**的（只有 `cases`），Lean 报「还有目标没证完」时会把状态印出来。

### §2.1 `h : p ∨ q`

```text
example (p q : Prop) (h : p ∨ q) : q ∨ p := by
  cases h
```

```text
error: unsolved goals
case inl
p q : Prop
h✝ : p
⊢ q ∨ p

case inr
p q : Prop
h✝ : q
⊢ q ∨ p
```

**两个目标**：一个是「假设是 `p`」的情形（标签 `case inl`），一个是「假设是 `q`」的情形（标签 `case inr`）。
注意原来那条 `h` 已经没了——它被换成了 `h✝ : p`（第一支）或 `h✝ : q`（第二支）。

### §2.2 `h : p ∧ q`

```text
example (p q : Prop) (h : p ∧ q) : q := by
  cases h
```

```text
error: unsolved goals
case intro
p q : Prop
left✝ : p
right✝ : q
⊢ q
```

**只有一个目标**——因为 `∧` 只有**一种**造法：把两块一起交出来。于是 `cases` 直接把两块都摆进假设。

### §2.3 `h : ∃ x, P x`

```text
example (α : Type) (P : α → Prop) (h : ∃ x, P x) : True := by
  cases h
```

```text
error: unsolved goals
case intro
α : Type
P : α → Prop
w✝ : α
h✝ : P w✝
⊢ True
```

也是**一个目标**，但摆进来的是**两样**：`w✝ : α`（那个具体的东西）和 `h✝ : P w✝`（它满足 `P` 的证据）。

### §2.4 ⭐ 记住这张表：标签名就是「构造子名」

| `h` 的类型 | 造法有几种 | 目标标签 | 新假设的名字 |
|---|---|---|---|
| `p ∧ q` | **1** 种 | `case intro` | `left✝`／`right✝` |
| `p ∨ q` | **2** 种 | `case inl`／`case inr` | `h✝`（每支一个） |
| `∃ x, P x` | **1** 种 | `case intro` | `w✝`／`h✝` |

**「造法」在 Lean 里叫「构造子」（constructor）**——就是第 4 章见过的那些名字：
`And.intro`、`Or.inl`、`Or.inr`、`Exists.intro`。
Lean 打印出来的 `case inl` / `case intro` 里的字，**正是构造子名的后半截**。
§3 的 `with | …` 就要用这些名字——**这张表下面还会用到**。
（⚠️ 「inductive 类型」「构造子」的一般理论是**第 7 章**的事；本课只要认得 `∧`／`∨`／`∃` 这三个。）

### §2.5 ⚠️ 带 `✝` 的名字引用不到，但**单目标**时可以用 `rename_i` 补

`h✝`、`left✝`、`w✝` 都带 `✝`——05-3 §3 讲过：**这些名字你引用不到**。
想点名，有两条路（第二条正是 05-3 学的 `rename_i`）：

```lean
example (p q : Prop) (h : p ∧ q) : q ∧ p := by
  cases h
  rename_i hp hq
  exact ⟨hq, hp⟩
```

`cases h` 在 `∧` 上只产生**一个**目标，所以这里不需要别的工具，`rename_i` 就够。
⚠️ 但在 `∨` 上是**两个**目标，`rename_i` 只作用于当前那一个；要让两个分支都走一遍还需要
`·`／`;` 之类的**聚焦与分派**工具——那是 **05-9**。所以下一节我们直接用 `with`。

## §3 `cases … with`：给每种造法写一支

**规则**：

```text
cases h with
| 构造子 名字… => 这一支的证明
| 构造子 名字… => 这一支的证明
```

- **构造子名**：§2.4 那张表里的（`inl`／`inr`／`intro`）；
- **名字**：你想给新摆进来的东西起的名字（写几个由该构造子带几样东西决定）。

### §3.1 `∨`：两支各写各的

```lean
example (p q : Prop) (h : p ∨ q) : q ∨ p := by
  cases h with
  | inl hp => exact Or.inr hp
  | inr hq => exact Or.inl hq
```

- `inl` 那一支里 `hp : p`，于是交 `Or.inr hp : q ∨ p`；
- `inr` 那一支里 `hq : q`，于是交 `Or.inl hq : q ∨ p`。
（`Or.inl` 吃左边、`Or.inr` 吃右边——03-4 那条，别喂反。）

### §3.2 `∧`：一支，两样东西

```lean
example (p q : Prop) (h : p ∧ q) : q ∧ p := by
  cases h with
  | intro hp hq => exact ⟨hq, hp⟩
```

`∧` 只有一种造法，所以**只有一支**；`intro hp hq` 里两个名字按顺序对上（先 `p` 后 `q`）。

### §3.3 `∃`：一支，拿出发觉者与证据

```lean
example (α : Type) (P : α → Prop) (h : ∃ x, P x) : ∃ x, P x := by
  cases h with
  | intro w hw => exact ⟨w, hw⟩
```

`w` 是那个具体的东西、`hw : P w` 是证据；`⟨w, hw⟩` 又把它重新打包成一个 `∃`（04-6 的匿名构造子）。

### §3.4 名字写错了会怎样（实测）

```text
example (p q : Prop) (h : p ∨ q) : q ∨ p := by
  cases h with
  | left hp => exact Or.inr hp
  | right hq => exact Or.inl hq
```

```text
error: Invalid alternative name `left`: Expected `inl` or `inr`
error: Invalid alternative name `right`: Expected `inl` or `inr`
error: Alternative `inl` has not been provided
error: Alternative `inr` has not been provided
```

⭐ 报错**直接把该用的名字告诉你**（`Expected \`inl\` or \`inr\``）。
看到这一条，回去对着 §2.4 那张表改名字就行。

## §4 `intro ⟨…⟩`：请进来的同时就拆

05-2 的 `intro` 只请进来「一个名字」；**现在可以让它一步把包拆开**：

**规则**：目标左边是 `p ∧ q`、`∃ x, P x` 这类**有结构的东西**时，`intro ⟨a, b⟩` 一步把它的两块
分别请进假设（名字叫 `a`、`b`）。

### §4.1 `∧` 在目标左边

```lean
example (p q r : Prop) (h : p → q → r) : p ∧ q → r := by
  intro ⟨hp, hq⟩
  exact h hp hq
```

`intro ⟨hp, hq⟩` 之后，假设里多了 `hp : p` 与 `hq : q`，目标从 `p ∧ q → r` 变成 `r`。

### §4.2 `∃` 在目标左边

```lean
example (α : Type) (P : α → Prop) (Q : Prop) (h : ∀ x, P x → Q) : (∃ x, P x) → Q := by
  intro ⟨w, hw⟩
  exact h w hw
```

`intro ⟨w, hw⟩` 之后拿到 `w : α` 与 `hw : P w`。

### §4.3 ⚠️ 同一个 `⟨⟩`，两个角色——别混

`⟨…⟩` 你在 04-6 见过；这里又出现。**它出现的位置不同，干的事正好相反**：

| 写在哪 | 角色 | 在干什么 |
|---|---|---|
| `intro ⟨hp, hq⟩`（**`intro` 后面**） | **模式**（pattern） | **拆开**手上的东西 |
| `exact h ⟨hp, hq⟩`（**项的位置**） | **项**（term） | **造出**一个 `∧`／`∃` |

同一份材料里两件事一起出现时，就看它**在箭头左边还是右边**：

```lean
example (p q r : Prop) (h : p ∧ q → r) : q → p → r := by
  intro hq hp
  exact h ⟨hp, hq⟩     -- ← 这里的 ⟨hp, hq⟩ 是【项】：造一个 p ∧ q 交给 h
```

## §5 判据：什么时候用哪个

| 你面对的东西 | 用哪个 | 理由 |
|---|---|---|
| 假设 `h : p ∧ q`／`p ∨ q`／`∃ x, P x`——**已经在你手上**、要拆 | `cases h`（想点名就 `with`） | 拆**已有**的东西 |
| **目标**左边是 `p ∧ q`／`∃ x, P x`（即目标形如 `… → …`） | `intro ⟨…⟩` | **请进来**的同时拆，省一步 |
| 只要从 `∧` 里取一块、且**只想取那一块** | `h.left`／`h.right`（第 4 章） | 不分支、不用 `cases` |
| 目标**本身就是** `p ∧ q`／`∃ x, P x`（不是箭头左边）——要**造** | ⛔ **`constructor`／`exists`** | **那是 05-5** |

⚠️ 最后一行最容易混：**`cases` 与 `intro ⟨…⟩` 都是「拆」，不是「造」**。
目标是 `p ∧ q`（直接就是）时，`intro ⟨…⟩` 用不上（目标不是箭头），得用 05-5 的 `constructor`。

## §6 `cases` 能用在什么上（点到为止）

`cases h` 要求 `h` 的类型是** inductive 类型**（即「造法」是有限几种、能一一列举的那种）。
`∧`／`∨`／`∃` 都是——所以本课能用。

⚠️ **完整的理论在第 7 章**（inductive types）。本课只当它是一条**工具规则**：
「`h` 的类型是 `∧`／`∨`／`∃`（或别的 inductive 类型）→ 可以 `cases`」。

| 原文 5.3 附近的 | 属于哪一课 | 现在为什么不必理解 |
|---|---|---|
| `constructor`／`exists`／`left`／`right`（**造**目标） | **05-5** | 本课全是「拆」，造目标下一课讲 |
| `rcases`／`rintro`（把 `cases … with` 与 `intro ⟨…⟩` 合成一步，写法更短） | **05-6** | 它们**也**是模式匹配；先把本课这套长的写熟 |
| `intro` 后面跟 `\| … => …` 分支配模式、`intro (hp \| hq)` 交替模式 | **05-6** | 交替模式会产生**多个**目标，要靠聚焦工具分派（→ 05-9） |
| `case inl => …`／`·`／`;`／`<;>`／`all_goals`（聚焦与分派） | **05-9** | 本课只用「`with` 自带分支」这一种分派方式 |
| tactic 里的 `match` | **05-6**／第 7 章 | 那是另一种模式匹配语法 |
| `cases h : e`（多留一条等式假设）、`cases` 用在**等式**假设上 | 后面（重写那一带） | 本课只拆 `∧`／`∨`／`∃` |
| `cases n`（在 `Nat` 上分类，会引出 `zero`／`succ` 两目标） | **第 8 章**（`induction`） | 那是归纳法的入口，不是本课的工具 |
| `intro rfl`、`intro (a, b)`（`×` 的元组模式） | 后面 | 本课只用 `⟨…⟩` 这一种模式 |

## §9 一页速查

| 写法 | 意思 |
|---|---|
| `cases h` | 把假设 `h` **按构造子拆开**；每支一个新目标（`∨` 两支、`∧`／`∃` 一支） |
| `cases h with \| 构造子 名字… => 证明` | 也把 `h` 按构造子拆开，但**自己给新假设起名字**（不带 `with` 的名字带 `✝`、引用不到） |
| 构造子名 | 看 Lean 打的 `case …` 标签：`And.intro`→`intro`、`Or.inl`→`inl`、`Or.inr`→`inr`、`Exists.intro`→`intro` |
| `intro ⟨a, b⟩` | 目标左边是 `∧`／`∃` 时，**请进来的同时拆**（这里的 `⟨⟩` 是**模式**） |
| `rename_i 名字…` | 不带 `with` 时补名字的办法（05-3 学的；**只有一个目标**时直接可用） |
| `⟨a, b⟩` 在**项**的位置 | 那是 04-6 的**匿名构造子**：**造**一个 `∧`／`∃`（与上面的「模式」正好相反） |
