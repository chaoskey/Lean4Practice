### 02-4 讲义：`?m.7` 的编号与「类型推断的边界」讲得不够（2026-09-19，已修正）

用户在订正完 02-4 习题后**继续追问**（这是本课最有价值的一个问题）：

> 「`#check fun x y => x + y` 打印的 `(x : ?m.7) → _`，其中 `.7` 从何而来？后面 `-> _` 又是为何？」

- **先澄清事实**：Lean 打的**不是** `-> _`（那个 `_` 是用户自己写在注释里的简写）。原文是
  `fun x y => x + y : (x : ?m.7) → (y : ?m.9 x) → ?m.10 x y`。
- **编号规律（实测）**：换表达式就变（`x + y` → `?m.7 / ?m.9 / ?m.10`；`x + y + z` → `?m.8 / ?m.15 / ?m.16 / ?m.18`），
  但**同一个表达式重复跑，编号稳定不变**（连跑三次完全一样）→ 它是「待定」的**创建序号**，
  **不是**行号、不是错误码、也不是随机数。
  最直接的证据：**只要多给一点线索**（写成 `(fun x y => x + y) 3`），待定就**全部被定下来**，
  输出变成干净的 `Nat → Nat`——说明那些待定本来都存在，只是被解出来了。
- **`?m.9 x` 后面那个 `x`**：表示这个待定**可能依赖 `x`**——这正是「依赖类型」这个名字的字面来源（归 **2-9**）。
- ⚠️ **我的讲义原来有一句是错的**：「具体编号每次运行可能不同」——**实测是稳定的**。
  已改正，并在讲义第 4 节新增一小节「`?m.7` 是什么？后面为什么跟着 `x`？」专门回答这两个问题；
  同时按 D14 第 3 条把「依赖类型」标为本课不引入（归 2-9）。

- **诚实回答**：它由**四个都讲过**的零件拼成——02-2 的箭头类型 `Nat → Nat`、02-4 的 `fun`、02-5 的

- **已做的修正**（均已实测、输出逐字核对）：

### 02-7 §5 继续追问两轮：`fun` 到底是谁带来的（2026-09-19，已修正）

用户在上一条之后**接着追了两问**（两问都很准，第二问戳到了根子上）：

> ① 「『`x` 是用 `variable` 声明的变量』——**我在讲义里没找到你在哪里声明的 `x`**！」
> ② 「你说的是 `variable (f : Nat → Nat) (x : Nat)` 里的 `x`？**但由此看不出和 `fun` 的关系呀！**」

- **① 成立**：`x` 确实在 **§4** 声明过（`variable (f : Nat → Nat) (x : Nat)`），
  但 **§5 的代码块只写了 `variable (b : Bool)`，正文也**没交代 `x` 的来历**——单独读 §5 就是找不到。
- **② 更关键：`fun` 根本不是我那条因果链的产物。** 实测三行对照（**注意中间那个完全没用 `variable`**）：

  | 定义 | 有参数吗 | `#print` 里有 `fun` 吗 |
  |---|---|---|
  | `def five : Nat := 5` | 没有 | **没有** |
  | `def incZ (x : Nat) : Nat := x + 1` | 有（**手写**的） | **有** |
  | `def incX := x + 1`（配 `variable (x : Nat)`） | 有（**Lean 补**的） | **有** |

  → **`fun` 来自「这个定义有参数」，与 `variable` 无关**；`variable` 只是**替你补参数**。
  我上一轮的解释（「补参数 = 造函数 = 用 `fun`」）**方向没错，但缺一个反证**，
  于是读者很容易误以为「是 `variable` 那一行变出了 `fun`」——**这个误解是我没排除的**。
- **已做的修正**（均已实测）：

     让 §5 的代码块**单独可编译**；
  2. 讲义 §5 新增小节「**再澄清一步：那个 `fun` 不是 `variable` 带来的**」——三行对照表 + 结论；
  3. 讲义 §4 加一句前向提醒；§4 里「用到别处名字」的两处都补了显式出处（`doTwiceA` 属第 2 节、`doTwiceB` 属本节）；
  4. `02-7-示例.lean` §3 同步补 `x` 的来历 + 三行对照。
- **新发现的检查盲区（已固化 `AGENTS.md` §6.25）**：我原来的抽块检查（§6.21）是把**所有块拼成一个文件**跑的——
  **跨块依赖正好被满足，所以永远检不出「某一块单独看其实不自包含」**。

> **说明我的解释停在「名字从哪来」，没走到「`fun` 这个形状从哪来」。**
> **凡讲一个现象，要一直讲到「为什么偏偏长成这样」，并且用一个「去掉某个条件它就不出现」的反证钉死。**

### 02-7 §5 第三次：用户自己提出「`variable` 就是参数」的理解（2026-09-19，**基本正确**，已收进讲义）

用户主动给出自己的复述：

> 「这个 `variable` 其实不是一般意义上的变量，而是**参数**的意思——它本质上是**预定义了函数的参数**，
> 所以它必然跟函数（`fun`）有关。一旦右边表达式中出现了这种参数，我们就可以把右边理解成定义了一个函数。」

- **判定：大方向完全正确，两处措辞要修正。**
  - ✅ **对**：`variable` 声明的**就是参数**，不是「可变的存储」——原文 2.6 用的词正是 **bound variables（绑定变量）**。
    **实测钉死**：三种写法 `#print` **一字不差**——
    `def incVar := x + 1`（variable 版）/ `def incParam (x : Nat) : Nat := x + 1`（手写参数版）/
    `def incFun : Nat → Nat := fun x => x + 1`（手写 `fun` 版）→ 三行都打印
    `def … : Nat → Nat := fun x => x + 1`。**① ② ③ 里的 `x` 是同一种东西**；`variable` 只是把 ② **自动化**。
  - ✅ **另一条实测支持**「它不是一个共享的值」：`def plus1 := x + 1` 与 `def plus2 := x + 2` **各得一份自己的 `x`**
    （分别打印 `fun x => x + 1` / `fun x => x + 2`）——若 `x` 是普通变量（一个值），两个定义就该共用它。
  - ⚠️ **要改的第一句**：「它**必然**跟函数有关」→ 应改成「**用到它的定义**必然变成函数」。
    `variable` 那一行**单独不产生任何东西**；定义**没用到它**时也不进参数（§5 的 `b` 即例）。
  - ⚠️ **要改的第二句**：「把**右边**理解成定义了一个函数」→ **右边本身不是函数**（`x + 1 : Nat`）；
    是 Lean 在右边**外面套了一层 `fun x =>`**，于是**整个 `def`** 成了函数。**右边是函数体，`fun x => 右边` 才是函数。**
- **已做的修正**：讲义 §5 新增小节「✅ 一句话把 `variable` 说准：它声明的**就是参数**」——
  含三写法对照（实测）+「不是共享的值」的反证 + 上面两处措辞的订正 + 一句精确总结；`02-7-示例.lean` §3 补 `incFun` 凑齐三种写法。
- **验证**：讲义 **13 段**代码块拼接实跑（零 error 零 warning）；**逐块单独编译 9/13 自包含**，
  其余 4 块（`doTwiceA`/`doTwiceB`/`five`/`incX`/`x`）**均已注明出处**；示例零 warning；`check.sh 02-7` 退出码 0。

> **教学上的收获（已并入 `AGENTS.md` §6.26）**：**让学习者用自己的话复述**，是最好的检验方式——
> 这次他复述得**基本对**，而我要做的是**逐句判定 + 标出「过强/过弱」的措辞**（「必然」「就是」这类词最常出问题），
> 并顺手给出**「三种等价写法 #print 一致」**这种一锤定音的对照。
