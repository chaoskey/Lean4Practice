# 第 5 章 · 第 5 课：**造出目标**——`constructor` 与 `exists`

> **原文链接**（想深挖时再看，**不是**理解本课的前提）：
> <https://lean-lang.org/theorem_proving_in_lean4/Tactics/>
>
> **本课范围**：原文 **5.3 More Tactics** 的中段——`constructor`／`exists`，以及 `∨` 目标的 `left`／`right`。
> （「中段」是**本项目自己的拆法**：5.3 里还有 `rcases`／`rintro`（→ 05-6）、`contradiction`（→ 05-6）等。）

>
> ⚠️ **只引入这三件**：`constructor`、`left`／`right`、`exists`；
> `refine`／`trivial`／`try`／`use`／`split`／`contradiction` **都不在本课**（§7 有归属表）。

## §1 上一课留下的另一半

05-4 的判据表最后一行是这么写的：

> | 目标**本身就是** `p ∧ q`／`∃ x, P x`（不是箭头左边）——要**造** | ⛔ **`constructor`／`exists`** | **那是 05-5** |

现在来补这一格。区别只有一句话：

- **假设**里有一条 `h : p ∧ q` → 你要**拆**它（05-4 的 `cases`）；
- **目标**是 `⊢ p ∧ q` → 你要**造**它（本课的 `constructor`）。

| 你面对的东西 | 用哪个 | 在哪一课 |
|---|---|---|
| **假设**是 `∧`／`∨`／`∃` | `cases`（＋ `with`） | 05-4 |
| **目标**左边是 `∧`／`∃`（即目标形如 `… → …`） | `intro ⟨…⟩` | 05-4 |
| **目标本身**是 `∧` | **`constructor`** | **本课 §2** |
| **目标本身**是 `∨` | **`left`／`right`** | **本课 §3** |
| **目标本身**是 `∃` | **`exists w`** | **本课 §4** |

## §2 `constructor`：让 Lean 自己挑构造子

官方文档（`Init/Tactics.lean`，**逐字**）：

> If the main goal's target type is an inductive type, `constructor` solves it with
> the first matching constructor, or else fails.

翻成中文：**目标类型是归纳类型时，`constructor` 用「第一个对得上的构造子」去解它；否则失败。**

### §2.1 目标 `⊢ p ∧ q`：造出两个子目标

```lean
example (p q : Prop) (hp : p) (hq : q) : p ∧ q := by
  constructor
  exact hp
  exact hq
```

`constructor` 之后**变成两个目标**（一行交一个）。它们的状态是：

```text
example (p q : Prop) : p ∧ q := by
  constructor
```

```text
error: unsolved goals
case left
p q : Prop
⊢ p

case right
p q : Prop
⊢ q
```

⭐ 对照 05-4 §2.4 那张表：`case left`／`case right` 正是 `And` 的**两个字段名**，
也就是「造的时候从哪一格来」。**造**（本课）与**拆**（05-4）用的是同一套名字。

### §2.2 目标 `⊢ True`：一个构造子、没有参数 → 直接收工

```lean
example : True := by
  constructor
```

这一条**没有任何子目标**——`True` 只有一种造法（`True.intro`），而且不带参数，
所以 `constructor` 一步就把目标证完了。

### §2.3 ⚠️ 目标 `⊢ p ∨ q`：它**只挑第一个**，挑错就没法回头

`∨` 有**两个**构造子，而 `constructor` 只会挑「**第一个**对得上的」。实测（下面这段**故意写错**）：

```text
example (p q : Prop) (hq : q) : p ∨ q := by
  constructor
  exact hq
```

```text
error: Type mismatch
  hq
has type
  q
but is expected to have type
  p
```

读法：`constructor` 挑了 `Or.inl`（要 `p`），可你手上只有 `hq : q`——
**它不会替你换到另一边**。`∨` 目标要用 §3 的 `left`／`right` **指定**。

### §2.4 ⚠️ 目标不是归纳类型（比如箭头）→ 直接失败

```text
example (p q : Prop) (hp : p) : p → q := by
  constructor
```

```text
error: Tactic `constructor` failed: target is not an inductive datatype

p q : Prop
hp : p
⊢ p → q
```

`p → q` 不是归纳类型的**目标**（箭头是函数类型），所以 `constructor` 用不上——
箭头目标要用 `intro`（05-2）／`exact`／`apply`。

## §3 `left`／`right`：`∨` 目标指定哪一边

官方文档（**逐字**，两条）：

> Applies the first constructor when the goal is an inductive type with exactly two constructors, or else fails otherwise.
>
> Applies the second constructor when the goal is an inductive type with exactly two constructors, or else fails otherwise.

**`left` = 用第一个构造子（`Or.inl`，取左边）；`right` = 用第二个（`Or.inr`，取右边）。**

### §3.1 两个方向各自的完整例子

```lean
example (p q : Prop) (hp : p) : p ∨ q := by
  left
  exact hp

example (p q : Prop) (hq : q) : p ∨ q := by
  right
  exact hq
```

各自只留**一个**子目标（`⊢ p` 或 `⊢ q`），所以不需要「一行交一个」的排法。

### §3.2 ⚠️ 它们只管「恰好两个构造子」的类型

```text
example (p q : Prop) : p ∧ q := by
  left
```

```text
error: Tactic `left` failed: left tactic works for inductive types with exactly 2 constructors

p q : Prop
⊢ p ∧ q
```

`∧` 只有**一个**构造子 → `left`／`right` 报错（这时该用 `constructor`，§2.1）。

## §4 `exists w`：给 `∃` 目标一个 witness

### §4.1 行为

目标 `⊢ ∃ x, P x` 时，写 **`exists w`** 就是把 **witness（见证者）`w`** 交出去；
目标随即从 `∃ x, P x` 变成 **`P w`**（剩下要证的，就是「`w` 确实满足 `P`」）。

```lean
example (α : Type) (P Q : α → Prop) (w : α) (hw : P w) (f : ∀ x, P x → Q x) : ∃ x, Q x := by
  exists w
  exact f w hw
```

（这里剩下的目标是 `Q w`，而 `f w hw : Q w`——一行交掉。）

### §4.2 ⚠️ 它是**宏**：实现里藏着三个本课不讲的词

源码（`Init/Tactics.lean`，**逐字**）：

```text
/-- `exists e₁, e₂, ...` is shorthand for `refine ⟨e₁, e₂, ...⟩; try trivial`.
It is useful for existential goals. -/
macro "exists " es:term,+ : tactic =>
  `(tactic| (refine ⟨$es,*, ?_⟩; try trivial))
```

也就是：**`exists w` 就是 `refine ⟨w, ?_⟩; try trivial` 的简写**。

⚠️ 其中 `refine`、`try`、`trivial` **都还没学过**（`try` 属于 **05-9**；`refine` 与 `trivial` 路线图尚未排课）。
**本课不需要理解它们**——只需知道 `exists w` 的**行为**（§4.1）和**副作用**（§4.3）。

### §4.3 ⚠️⚠️ 那个 `try trivial` 会**顺手收尾**——别以为后面一定还有目标

实测两种情况：

**情况一：上下文里已经有能直接用的东西 → `exists w` 一行就证完**

```lean
example (α : Type) (P : α → Prop) (w : α) (hw : P w) : ∃ x, P x := by
  exists w
```

（这一条**通过**：剩下的 `⊢ P w` 被那句 `try trivial` 用上下文里的 `hw` 收掉了。）

另一种情况：剩下的是 `rfl` 能证的——也**一行就够**：

```lean
example : ∃ n : Nat, n = n := by
  exists 0
```

（`⊢ 0 = 0` 被 `rfl` 收掉，也**通过**。）

**情况二：剩下的目标既不在上下文里、也不是 `rfl` → 真的还剩一个**

就是 §4.1 那个例子（`⊢ Q w` 要靠 `f w hw` 才算得出）。

⚠️ **所以多写一行会报错**。实测（在情况一下面接着写）：

```text
example (α : Type) (P : α → Prop) (w : α) (hw : P w) : ∃ x, P x := by
  exists w
  exact hw
```

```text
error: No goals to be solved
```

**目标已经被收完了，你再动手就没有目标可动。**

### §4.4 对照：`constructor` 也能用在 `∃` 上，但它**不指定** witness

```text
example (α : Type) (P : α → Prop) (w : α) (hw : P w) : ∃ x, P x := by
  constructor
```

```text
error: unsolved goals
case h
α : Type
P : α → Prop
w : α
hw : P w
⊢ P ?w

case w
α : Type
P : α → Prop
w : α
hw : P w
⊢ α
```

两个要点：

1. 它把「**给出 witness**」也变成了一个**要你去证的目标**（`case w : ⊢ α`）；
2. 第一个目标里那个 **`?w` 是「还没定下来的 witness」**——`constructor` 把选谁的活儿留给了 Lean。

⭐ 实测一个反直觉的现象：**把第一个目标证掉之后，第二个目标不用你管**——
`constructor` 后面**只写** `exact hw` 就通过（`?w` 随之确定成 `w`）；
反而多写一行 `exact w` 会报 `No goals to be solved`。

**结论**：`∃` 目标**首选 `exists w`**（witness 由你明确给出，读起来清楚）；
`constructor` 虽然也能用，但它把 witness 变成待定元变量，形状更绕。

## §5 两条路：**tactic 造目标** 还是 **项造证明**

本课教的都是 tactic，但它们干的事**用项也能干**（前几课学过）：

| 目标 | tactic 写法 | 项的写法（前几课） |
|---|---|---|
| `⊢ p ∧ q` | `constructor`（或 `apply And.intro`） | `exact ⟨hp, hq⟩`／`exact And.intro hp hq` |
| `⊢ p ∨ q` | `left`／`right` | `exact Or.inl hp`／`exact Or.inr hq` |
| `⊢ ∃ x, P x` | `exists w` | `exact ⟨w, hw⟩`／`exact Exists.intro w hw` |

实测：`apply And.intro` 与 `constructor` 造出的子目标**一样**（都是 `⊢ p`、`⊢ q`）：

```lean
example (p q : Prop) (hp : p) (hq : q) : p ∧ q := by
  apply And.intro
  exact hp
  exact hq
```

**什么时候用哪个**：要**分步**做、或者想让 Lean 自己挑构造子 → 用 tactic；
一步就能把证明项交出来 → 直接 `exact`（更短）。

## §6 把 05-4 的表补全

| 你面对的东西 | 用哪个 |
|---|---|
| **假设** `h : p ∧ q`／`p ∨ q`／`∃ x, P x`——要**拆** | `cases h`（＋ `with`） |
| **目标**左边是 `p ∧ q`／`∃ x, P x`（形如 `… → …`） | `intro ⟨…⟩` |
| **目标本身**是 `p ∧ q`——要**造** | `constructor` |
| **目标本身**是 `p ∨ q`——要**造** | `left`／`right`（`constructor` 只会挑左边） |
| **目标本身**是 `∃ x, P x`——要**造** | `exists w` |
| **目标本身**是 `True` | `constructor`（一步收工） |

⚠️ 一句话记牢：**`cases` 是「拆已有的」，`constructor`／`left`／`right`／`exists` 是「造要证的」。**

## §9 一页速查

| 写法 | 在**当前目标**上做了什么 |
|---|---|
| `constructor` | 目标类型是归纳类型 → 用**第一个对得上的构造子**；`∧` 给**两个**子目标（`case left`／`case right`），`True` 直接收工；`∨` 上只挑 `Or.inl`；非归纳目标（箭头）→ 报错 |
| `left` | 目标有**恰好两个**构造子 → 用**第一个**（`∨` 上就是左边 `Or.inl`）；`∧` 上报错 |
| `right` | 目标有**恰好两个**构造子 → 用**第二个**（`∨` 上就是右边 `Or.inr`）；`∧` 上报错 |
| `exists w` | 目标 `⊢ ∃ x, P x` → 交出 witness `w`，目标变成 `⊢ P w`；⚠️ 它是 `refine ⟨w, ?_⟩; try trivial` 的简写——剩下那个目标**可能已被顺手收掉**，多写一行会报 `No goals to be solved` |
| 项写法对照 | `constructor` ＝ `apply And.intro`；`left`／`right` ＝ `Or.inl`／`Or.inr`；`exists w` ＝ `⟨w, hw⟩`／`Exists.intro w hw` |
