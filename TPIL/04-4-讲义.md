## 1. 本课要做什么

| 序 | 内容 | 一句话 |

## 2. 替换的核心：`Eq.subst`

原文说：相等的**要害**不只是「等价关系」，而是**每个命题都尊重它**——
`a = b` 时，把命题里的 `a` 换成 `b`，真假不变。

把这句话写成规则，就是 `Eq.subst`：

```lean
section subst_basics
#check Eq.subst
#check @Eq.subst
end subst_basics
```

**实测输出**：

```
Eq.subst.{u} {α : Sort u} {motive : α → Prop} {a b : α} (h₁ : a = b) (h₂ : motive a) : motive b
@Eq.subst : ∀ {α : Sort u_1} {motive : α → Prop} {a b : α}, a = b → motive a → motive b
```

**逐段读**（用 04-2 §3 那套「消去」的读法）：

| 这一段 | 读作 |
|---|---|
| `{motive : α → Prop}` | 一个**「带一个洞的句子」**：喂给它一个 `α` 的元素，它吐出一个命题 |
| `(h₁ : a = b)` | 洞外面是 `a`、洞里面是 `b` |
| `(h₂ : motive a)` | 「洞填 `a` 时」那句话的证明 |
| 结果 `motive b` | 「洞填 `b` 时」那句话的证明 |

> 📌 **一句话**：`Eq.subst` 就是**把洞里的 `a` 换成 `b`**，证明照样能用。

原文的例子：

```lean
section subst_example
variable (α : Type) (a b : α) (p : α → Prop)
variable (h1 : a = b) (h2 : p a)

example : p b := Eq.subst h1 h2
end subst_example
```

这里洞是 `fun x => p x`（也就是 `p` 自己）：`h2 : p a` 填的是 `a`，换成 `b` 就得到 `p b`。

> ⚠️ **本课不要求理解的部分**：输出里的 `Sort u`、`.{u}`——那是**宇宙**（后续章节讲）。
> 沿用 04-3 §2 的办法：把 `{α : Sort u}` **读作「任意类型」**。

## 3. `▸`：替换的顺手写法

同一个例子，也可以用那个**三角记号**：

```lean
section triangle_example
variable (α : Type) (a b : α) (p : α → Prop)
variable (h1 : a = b) (h2 : p a)

example : p b := h1 ▸ h2
end triangle_example
```

**怎么打**：`\t` + 空格（`\t` 是编辑器缩写，见 [`Unicode速查.md`](./Unicode速查.md)）。

**怎么读**：`h1 ▸ h2` 读作「**用 `h1` 把 `h2` 改一下**」。
配 04-3 学的方向感——`h1 : a = b` 时，`h1 ▸ h2` 是**把 `a` 换成 `b`**。

## 4. ⭐ `Eq.subst` 的三种「不听话」（全部实测）

原文有一句很重要的话：**`Eq.subst` 并不总是按你想的来**（`Eq.subst doesn't always do what you want to`）。
这句话我**逐条测了**，下面是三份实测记录。**三处都是 `Eq.subst` 报错、`▸` 通过。**

### 4.1 第一种：方向不对就不行

```lean
section orient_ok
variable (α : Type) (p : α → Prop) (a b : α)
variable (h : b = a) (h2 : p a)

-- 注意 h 给的是 `b = a`（反的），目标却是 `p b`
example : p b := h ▸ h2
end orient_ok
```

上面这个 `example` **通过**——但下面这个**故意写错的**不通过（所以它没有用 ```lean 标记）：

```
example (α : Type) (p : α → Prop) (a b : α) (h : b = a) (h2 : p a) : p b := Eq.subst h h2
```

实测报错（逐字）：

```
error: Application type mismatch: The argument
  h
has type
  b = a
but is expected to have type
  a = b
in the application
  Eq.subst h
```

→ **`Eq.subst` 要求 `h₁ : a = b`**（洞外面是 `a`）。`h` 反了就得自己写 `.symm`：

```lean
section orient_symm
variable (α : Type) (p : α → Prop) (a b : α)
variable (h : b = a) (h2 : p a)

example : p b := Eq.subst h.symm h2
end orient_symm
```

### 4.2 第二种：`motive` 猜错（目标里那个变量出现在好几处）

```
example (α : Type) (a b : α) (F : α → α → Prop) (h : a = b) (h2 : F a b) : F b b := Eq.subst h h2
```

实测报错（逐字）：

```
error: Application type mismatch: The argument
  h2
has type
  F a b
but is expected to have type
  F b a
in the application
  Eq.subst h h2
```

**它在说什么**：目标是 `F b b`——`b` 出现了**两次**。Lean 得自己猜那个「带洞的句子」，
结果猜成了 **`fun x => F b x`**（洞在**第二个**位置），于是它要的是 `F b a`，而你手上是 `F a b`。

**两个办法都能救**：

```lean
section motive_explicit
variable (α : Type) (a b : α) (F : α → α → Prop) (h : a = b) (h2 : F a b)

-- 办法一：把 motive 直接写出来（下面讲这个 `(motive := …)` 是什么）
example : F b b := Eq.subst h (motive := fun x => F x b) h2

-- 办法二：直接交给 ▸
example : F b b := h ▸ h2
end motive_explicit
```

### 4.3 第三种：`motive` 只能是**命题**，不能是类型

```
example (α : Type) (p : α → Type) (a b : α) (h : a = b) (x : p a) : p b := Eq.subst h x
```

实测报错（逐字）：

```
error: Type mismatch
  Eq.subst h ?m.6
has type
  ?m.3 b
of sort `Prop` but is expected to have type
  p b
of sort `Type`
```

**它在说什么**：`Eq.subst` 的 `motive` 规定为 **`α → Prop`**（见 §2 的实测签名）——
它只能在**命题**里换，**换不进类型**。本例的目标 `p b` 是 `Type`（因为 `p : α → Type`），所以不行。

**`▸` 可以**：

```lean
section type_motive
variable (α : Type) (p : α → Type) (a b : α) (h : a = b) (x : p a)

example : p b := h ▸ x
end type_motive
```

### 4.4 为什么 `▸` 更稳（**Lean 源码里的官方说明**）

`▸` 的说明就写在 Lean 自己的源码里（实测：`Lean/Parser/Term.lean` 里那个记号的定义上方）。
原文照抄要点：

> `h ▸ e` is a macro built on top of `Eq.rec` and `Eq.symm` definitions.
> Given `h : a = b` and `e : p a`, the term `h ▸ e` has type `p b`.
> The macro **tries both orientations** of `h`. If the context provides an expected type,
> it **rewrites the expected type**, else it rewrites the type of `e`.

翻成中文，三条都对上了上面的实测：

| 源码说法 | 对应哪条实测 |
|---|---|
| 建在 **`Eq.rec`** 上（不只是 `Eq.subst`） | 所以 §4.3 那种**类型**里的替换它也能干 |
| **两个方向都试** | 所以 §4.1 反过来给的 `h` 它也能用 |
| **上下文给了目标，它就照目标来** | 所以 §4.2 里目标 `F b b` 能帮它选对洞的位置 |

> 📌 **原文把原因归到「高阶合一（higher-order unification）不可判定、只能近似」**——那是更底层的说法。
> **我实测到的就是上面三类**（方向 / 猜错 / 只能是 `Prop`），你按这三条用就够。

### 4.5 那个 `(motive := …)` 是什么

```lean
section motive_named_arg
variable (α : Type) (a b : α) (F : α → α → Prop) (h : a = b) (h2 : F a b)

example : F b b := Eq.subst h (motive := fun x => F x b) h2
end motive_named_arg
```

**写法是 `(名字 := 值)`**——`motive` 是**隐式参数**（花括号包着的）。
04-2 讲过两种对付隐式参数的办法：**不写让 Lean 猜**、**加 `@` 全变显式**；
这里用的是**第三种**：**只把某一个具名参数钉死**，其余照样让 Lean 猜。

好处：只把这一个参数钉死，**其余的照样让 Lean 猜**。

## 5. `congr` 三兄弟：在「函数应用」上替换

原文说：`Eq.subst` 还被用来定义几个**更针对「函数应用 `s t`」**的规则。先看它们的类型：

```lean
section congr_checks
#check congrArg
#check congrFun
#check congr
end congr_checks
```

**实测输出**：

```
congrArg.{u, v} {α : Sort u} {β : Sort v} {a₁ a₂ : α} (f : α → β) (h : a₁ = a₂) : f a₁ = f a₂
congrFun.{u, v} {α : Sort u} {β : α → Sort v} {f g : (x : α) → β x} (h : f = g) (a : α) : f a = g a
congr.{u, v} {α : Sort u} {β : Sort v} {f₁ f₂ : α → β} {a₁ a₂ : α} (h₁ : f₁ = f₂) (h₂ : a₁ = a₂) : f₁ a₁ = f₂ a₂
```

**一句话各自管什么**（原文的说法）：

| 工具 | 换哪个位置 | 记法 |
|---|---|---|
| `congrArg` | 换**参数**（函数不变） | `congrArg f h` |
| `congrFun` | 换**被应用的函数**（参数不变） | `congrFun h a` |
| `congr` | **两个一起**换 | `congr h₁ h₂` |

原文的例子：

```lean
section congr_examples
variable (α : Type)
variable (a b : α)
variable (f g : α → Nat)
variable (h₁ : a = b)
variable (h₂ : f = g)

example : f a = f b := congrArg f h₁
example : f a = g a := congrFun h₂ a
example : f a = g b := congr h₂ h₁
end congr_examples
```

> ⚠️ **本课不要求理解的部分**：`congrFun` 输出里的 `β : α → Sort v` 与 `(x : α) → β x`。
> 后者就是 **04-1 学的依赖函数类型**（`(x : α) → β x` 与 `∀ x : α, β x` 是同一个东西）；
> 前者那个 `Sort v` 是**宇宙**，读作「任意类型」即可。

## 6. ⚠️ 三兄弟给的是**等式**，`▸` / `Eq.subst` 是**消费**等式的

这是本课最容易踩的一处，**我实测过**。

已知 `P Q : α → Prop`、`h : P = Q`、`h2 : P a`。要证 `Q a`。

下面这条**故意写错**（`congrFun` 给的**不是** `Q a`）：

```
example (α : Type) (P Q : α → Prop) (a : α) (h : P = Q) (h2 : P a) : Q a := congrFun h a
```

实测报错（逐字）：

```
error: Type mismatch
  congrFun h a
has type
  P a = Q a
but is expected to have type
  Q a
```

**看清楚了**：`congrFun h a` 的类型是 **`P a = Q a`**，是一个**等式**，不是「改写过后的证明」。
两类工具的分工是：

| 角色 | 工具 | 给出/需要什么 |
|---|---|---|
| **造**等式 | `congrArg` / `congrFun` / `congr`（还有 `rfl`、`Eq.symm`、`Eq.trans`、`Nat.*`） | 给出一条**等式** |
| **用**等式 | `▸` / `Eq.subst` | 拿一条等式**去改**别的东西 |

所以上面那题，正确的写法是**两件套**：

```lean
section congr_then_rewrite
variable (α : Type) (P Q : α → Prop) (a : α)
variable (h : P = Q) (h2 : P a)

example : Q a := (congrFun h a) ▸ h2
end congr_then_rewrite
```

先用 `congrFun` 造出 `P a = Q a`，再用 `▸` 把 `h2 : P a` 改成 `Q a`。

## 7. `Nat` 的常用等式表

原文列了一批「库里现成的」等式。**逐条实测通过**：

```lean
section nat_table
variable (a b c : Nat)

example : a + 0 = a := Nat.add_zero a
example : 0 + a = a := Nat.zero_add a
example : a * 1 = a := Nat.mul_one a
example : 1 * a = a := Nat.one_mul a
example : a + b = b + a := Nat.add_comm a b
example : a + b + c = a + (b + c) := Nat.add_assoc a b c
example : a * b = b * a := Nat.mul_comm a b
example : a * b * c = a * (b * c) := Nat.mul_assoc a b c
example : a * (b + c) = a * b + a * c := Nat.mul_add a b c
example : a * (b + c) = a * b + a * c := Nat.left_distrib a b c
example : (a + b) * c = a * c + b * c := Nat.add_mul a b c
example : (a + b) * c = a * c + b * c := Nat.right_distrib a b c
end nat_table
```

**一句话各自是哪条律**（括号里只说「是哪一条」，不解释命题在说什么）：

| 名字 | 是哪一条 |
|---|---|
| `Nat.add_zero` / `Nat.zero_add` | 加法单位元（右 / 左） |
| `Nat.mul_one` / `Nat.one_mul` | 乘法单位元（右 / 左） |
| `Nat.add_comm` / `Nat.mul_comm` | 交换律（`+` / `*`） |
| `Nat.add_assoc` / `Nat.mul_assoc` | 结合律（`+` / `*`） |
| `Nat.mul_add` / `Nat.left_distrib` | 分配律（`*` 对 `+`，右） |
| `Nat.add_mul` / `Nat.right_distrib` | 分配律（`+` 对 `*`，左） |

> 📌 **末两行是「同一条式子的两个名字」**（原文也这么说，实测两条各自都能证出上面那两行）：
> `Nat.mul_add` 与 `Nat.left_distrib` **指同一条**；`Nat.add_mul` 与 `Nat.right_distrib` **指同一条**。

## 8. 综合例子：把 `(x + y) * (x + y)` 展开

原文最后给了一个用「替换 + 结合律 + 分配律」拼起来的例子。**逐字照抄，实测通过**：

```lean
section big_example
example (x y : Nat) :
    (x + y) * (x + y) =
    x * x + y * x + x * y + y * y :=
  have h1 : (x + y) * (x + y) = (x + y) * x + (x + y) * y :=
    Nat.mul_add (x + y) x y
  have h2 : (x + y) * (x + y) = x * x + y * x + (x * y + y * y) :=
    (Nat.add_mul x y x) ▸ (Nat.add_mul x y y) ▸ h1
  h2.trans (Nat.add_assoc (x * x + y * x) (x * y) (y * y)).symm
end big_example
```

**逐步拆**（`have` 的用法见 03-7；这里只说每一步在干什么）：

| 步 | 表达式 | 做了什么 |
|---|---|---|
| `h1` | `Nat.mul_add (x + y) x y` | 把 `(x+y)*(x+y)` 按**分配律**拆成 `(x+y)*x + (x+y)*y` |
| `h2` | `(Nat.add_mul x y x) ▸ (Nat.add_mul x y y) ▸ h1` | **两次替换**：把 `h1` 右边的两个 `(x+y)*_` 各自换成 `x*_ + y*_` |
| 最后 | `h2.trans (…).symm` | 目标右边是**右结合**的 `x*x + y*x + (x*y + y*y)`，而 `h2` 右边**没加括号**（即左结合）→ 用 `Nat.add_assoc` **掉个头**把括号挪过去，再 `.trans` 接上 |

> 📌 **`(Nat.add_mul x y x) ▸ (Nat.add_mul x y y) ▸ h1` 是从左往右连着的两次替换**——
> `▸` 的优先级是 75，`a ▸ b ▸ c` 按左边先结合。
