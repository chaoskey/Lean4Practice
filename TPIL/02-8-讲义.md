# 第 2 章 · 第 8 课：命名空间（`namespace`）

> 📄 **示例**：`02-8-示例.lean`（我写的，已通过编译、零 warning）
> ✍️ **习题**：`02-8-习题.lean`（**你写**）
> 📖 **原文**：<https://lean-lang.org/theorem_proving_in_lean4/Dependent-Type-Theory/#namespaces> 的 **2.7** 小节（想深挖时再看；**读不懂不影响本课**）
> 本课只讲一件事：**给名字加「前缀」，让不同的东西可以叫同一个名字。**

---

## 1. 本课的一句话

- **`namespace Foo` … `end Foo`**：把一组定义**装进一个盒子**——盒子里每个名字的**全名**都带上 `Foo.` 前缀。
- **`open Foo`**：把盒子里的**短名字**拿出来用。

---

## 2. 问题：名字会撞车（实测）

**下面这段是故意写错的**（所以它没有 `lean` 标记——讲义抽块检查不会编译它）：

```
def v : Nat := 1
def v : Nat := 2
```

报错原文：

```
error: `v` has already been declared
```

**一个 Lean 文件里，同一个名字只能有一个。** 可你总会有「这个名字我已经想好了，但我想再用一次」的时候
——尤其当代码来自不同的地方（你写的、标准库的、别人的）时。

`namespace` 就是为这个准备的。

---

## 3. `namespace` 登场：给名字加前缀（实测）

```lean
namespace Box1
  def a : Nat := 5
  def f (x : Nat) : Nat := x + 7

  #check a
  #check f
end Box1

#check Box1.a
#check Box1.f
```

实测输出（4 行）：

```
Box1.a : Nat
Box1.f (x : Nat) : Nat
Box1.a : Nat
Box1.f (x : Nat) : Nat
```

⚠️ **注意第 1 行**：我在盒子里写的是 `#check a`，打印出来却是 **`Box1.a`**——
**`#check` 打的永远是全名**，**即使在 namespace 里面**。

**盒子里 vs 盒子外**：

| 位置 | `#check a`（短名） | `#check Box1.a`（全名） |
|---|---|---|
| `namespace Box1` **里面** | ✅ 可以（打印 `Box1.a : Nat`） | ✅ 可以 |
| `end Box1` **之后** | ❌ `Unknown identifier 'a'` | ✅ 可以 |

原文的两条（我翻译）：

> 当你在 `namespace Box1` 里工作时，你声明的**每个标识符的全名都带 `Box1.` 前缀**。
> 在 namespace **里面**你可以用短名，但一旦 `end`，就必须用**长名**。
> 和 `section` **不同**：**namespace 必须起名字**——根层只有唯一一个「匿名 namespace」。

「**必须起名字**」实测（**下面这段是故意写错的**）：

```
namespace
  def z : Nat := 1
end
```

报错原文：

```
error: unexpected token 'def'; expected identifier
error: Invalid `end`: There is no current scope to end
```

（第一句的意思就是：`namespace` 后面**必须跟一个名字**。）

---

## 4. `open`：把短名字拿出来用

`end` 之后短名就没了。要是你还想用短名，就 `open` 一下（实测）：

```lean
namespace Box2
  def b : Nat := 5
end Box2

open Box2

#check b
#check Box2.b
```

实测输出（2 行）：

```
Box2.b : Nat
Box2.b : Nat
```

⚠️ **两行输出一模一样**——**`open` 不会改变名字本身**，
它只是让你**多一个短名字可用**；打印的时候 Lean 仍然用**全名**。

> 💡 **一句话记住**：`open Foo` = 「**我允许你用短名**」，**不是**「把名字改短了」。

### 顺带一个现象（只影响显示，不影响含义）

```lean
namespace Box3
  def p : Nat := 5
  def g (x : Nat) : Nat := x + 7
  def gp : Nat := g p
end Box3

#print Box3.gp
-- 打印（两行）：
--   def Box3.gp : Nat :=
--   Box3.g Box3.p        ← 定义体里用的是【全名】

open Box3
#print Box3.gp
-- 打印（两行）：
--   def Box3.gp : Nat :=
--   g p                  ← open 之后，显示成【短名】
```

**名字一点没变**（两处都叫 `Box3.gp`），变的只是**打印时用哪种写法**——
这又是 **02-2 §8** 那条「**显示形式 ≠ 含义**」的又一次出现。

## 5. 嵌套 namespace；必须按开顺序关；关掉可以重开

### 嵌套（实测）

```lean
namespace Out1
  def a : Nat := 5
  def f (x : Nat) : Nat := x + 7
  def fa : Nat := f a

  namespace In1
    def ffa : Nat := f (f a)
    #check fa
    #check ffa
  end In1

  #check fa
  #check In1.ffa
end Out1

#check Out1.fa
#check Out1.In1.ffa

open Out1
#check fa
#check In1.ffa
```

实测输出（6 行）：

```
Out1.fa : Nat
Out1.In1.ffa : Nat
Out1.fa : Nat
Out1.In1.ffa : Nat
Out1.fa : Nat
Out1.In1.ffa : Nat
```

三处要看清楚：

- **在 `In1` 里面**：外层的 `f`、`a` **可以直接用短名**——所以 `def ffa : Nat := f (f a)` 能通过；
  但 `#check fa` 打印的**仍然是** `Out1.fa`。
- **回到 `Out1` 这一层**：内层的东西要用**下一级前缀** `In1.ffa`。
- **`end Out1` 之后**：要用**完整前缀** `Out1.In1.ffa`。

### 关的顺序：**后开的先关**（实测）

**下面这段是故意写错的**：

```
namespace Outer
  namespace Inner
    def z : Nat := 1
  end Outer
end Inner
```

报错原文：

```
error: Invalid name after `end`: Expected `Inner`, but found `Outer`
Hint: If you meant to end the outer scope(s) `Outer`, you must end all the intervening scopes `Outer.Inner`:
  end Outer.Inner
```

—— 规则和 `section` **一样**：**后开的先关**（先 `end Inner`，再 `end Outer`）。

### 关掉的 namespace 还能**重开**（实测）

```lean
namespace Box4
  def a : Nat := 5
end Box4

namespace Box4
  def ffa : Nat := a + a
  #check ffa
end Box4

#check Box4.ffa
```

实测输出（2 行）：

```
Box4.ffa : Nat
Box4.ffa : Nat
```

两段 `Box4` 里的东西合起来算**同一个** `Box4`——所以**第二段里能直接用短名 `a`**。

## 6. `namespace` 与 `section` 的关系

原文特意比较过这两者（我翻译）：

> namespace 与 section 的**用途不同**：**namespace 组织名字，section 声明变量**（变量会被插进定义里）。
> 不过**在很多方面，`namespace … end` 的行为就像 `section … end`**。

| | `section`（02-7 学的） | `namespace`（本课） |
|---|---|---|
| 要不要名字 | **可以匿名** | **必须起名字** |
| 主要用途 | 声明 `variable`（让 Lean 把参数插进定义） | **给名字加前缀**（组织名字） |
| 怎么结束 | `end`（命名的话要同名） | `end 名字`（要同名） |
| 能否嵌套 | 可以 | 可以 |
| 关闭顺序 | 后开的先关 | 后开的先关 |

**两条「像 section」的证据**（都实测）：

**① `variable` 写进 namespace，作用范围只到 namespace 结束**：

```lean
namespace VarBox
  variable (n : Nat)
  def doubleN := n + n
end VarBox

#check VarBox.doubleN
```

实测：`VarBox.doubleN (n : Nat) : Nat`——**`variable` 照样生效**（`n` 被补成参数），
但**出了 namespace 之后 `n` 就用不到了**（`#check n` 会报 `Unknown identifier 'n'`）。

**② 在 namespace 里 `open` 别的 namespace，关闭之后失效**：

```lean
namespace Tool2
  def h : Nat := 1
end Tool2

namespace UseBox
  open Tool2
  def useIt : Nat := h + 1
  #check useIt
end UseBox

#check UseBox.useIt
```

实测：两行都是 `… : Nat`；而**出了 `UseBox` 之后，短名 `h` 就没了**（`#check h` 会报 `Unknown identifier 'h'`）。

## 7. 标准库的例子：`List`

原文举了标准库的例子：Lean 把**列表相关**的定义和定理都放进 `List` 这个名字空间，
所以它们的全名是 `List.nil` / `List.cons` / `List.map` 这种。`open List` 之后就能用短名（实测）：

```lean
#check List.nil
#check List.cons
#check List.map
open List
#check nil
#check map
#check List.map
```

> ⚠️ **上面这些输出里有两样东西本课不引入**——你**只要看名字那一部分**就行：
> - `{α : Type u}` 里那种**花括号**是**隐式参数**——归 **2-10**；
> - 那个 **`u`（宇宙）** 属**宇宙多态**——还没有归属的课（见 `学习计划.md` §三 的注）。
>
> 本课你只需要看出：**它们的全名都带 `List.` 前缀**，而 `open List` 之后短名就能用。

## 9. 小结

本课记住四件事：

1. **`namespace N … end N`**：给名字加前缀 `N.`；**里面**可用短名，**出了 `end`** 必须用全名；
   **namespace 必须起名字**（这一点和 `section` 不同）。
2. **`open N`**：让你**多一个短名字可用**——**它不改名字本身**（全名照样能用）。
   另外：**`#check` 打印的永远是全名**（在 namespace 里、`open` 之后，都一样）。
3. **可以嵌套**（全名 `Out1.In1.x`）、**必须按开的顺序关**、**关掉之后可以重开**（重开后算同一个盒子）。
4. **`namespace` 像 `section` 的地方**：都靠 `end` 结束、嵌套都要按序关、`variable` 的作用范围被限定、
   `open` 的效果一关闭就消失。**差别**：namespace **必须有名**，而且它的本职是**组织名字**，不是声明变量。
