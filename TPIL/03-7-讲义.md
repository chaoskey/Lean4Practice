# 第 3 章 · 第 7 课：辅助子目标 `have` / `suffices`

> 📄 **示例**：`03-7-示例.lean`（我写的，已通过编译、零 warning）
> ✍️ **习题**：`03-7-习题.lean`（**你写**）
> 📖 **原文**：<https://lean-lang.org/theorem_proving_in_lean4/Propositions-and-Proofs/#introducing-auxiliary-subgoals> 的 **3.4「Introducing Auxiliary Subgoals」**（我用中文讲透）
> **本课的一句话**：**长证明要拆成小步**——`have h : p := …` 是「**先证出一个中间事实，后面当假设用**」，`suffices h : p from …` 是「**倒着想：只要有这个就够了**」；而它们**不是新语法**——`have h : p := s` 接上 `t`，**展开就是 `(fun (h : p) => t) s`**，也就是你 02-4 / 03-2 已经会的 **`fun` + 应用**。

---

## 1. 定位：为什么要「辅助子目标」

原文（我译）：

> 这是引入 `have` 的好时机——`have` 能**给长证明搭结构**，做法是**引入一个辅助子目标**。

**问题是什么**：像 `q ∧ p` 这种目标，答案往往是「**把两样东西凑起来**」，而那两样**各自要几步才能拿到**。如果全挤在一行，就成了一堵墙：

```lean
-- 挤成一行的样子（能过，但难读）
variable (p q : Prop)

theorem hard (h : p ∧ q) : q ∧ p := And.intro h.right h.left
```

`have` 做的事就是：**先证出一个中间事实，给它起个名字，然后剩下的用这个名字来写。**

---

## 2. `have`：先证一个中间事实，再拿它当假设用

原文的例子（实测逐字通过）：

```lean
variable (p q : Prop)

theorem t1 (h : p ∧ q) : q ∧ p :=
  have hp : p := h.left
  have hq : q := h.right
  show q ∧ p from And.intro hq hp
```

**逐行拆**：

| 这一行 | 在干什么 |
|---|---|
| `have hp : p := h.left` | **证出** `hp : p`（方法：从 `h` 取左边） |
| `have hq : q := h.right` | **证出** `hq : q`（从 `h` 取右边） |
| `show q ∧ p from And.intro hq hp` | 目标 `q ∧ p`——**用刚拿到的 `hp`、`hq` 凑出来**（注意**顺序换过来了**） |

⚠️ **三个要点**：

1. **它是一条「声明 + 赋值」**：`have 名字 : 类型 := 证明`——**左边是新的假设名，右边是证明**；
2. **类型必须写全**（`have hp : p := …`，**不能省 `: p`**——省了 Lean 不知道该把 `h.left` 看成什么）；
3. **写错类型立刻报错**（实测）：
（下面这段**故意写错**，所以用**普通**代码块）

```
have hp : q := h.left
```
   ```
   error: Type mismatch
   ```
   → **`have` 的类型是被检查的**，它就是一条新的假设。

---

## 3. ⚠️ 关键：`have` **不是新东西**，它就是 `fun` + 应用

原文（我逐字译）：

> 内部地，表达式 `have h : p := s; t` 产生的是项 **`(fun (h : p) => t) s`**。换句话说，`s` 是 `p` 的证明，`t` 是「**假设 `h : p`** 时目标」的证明，两者由**一个 lambda 抽象加一次应用**结合起来。

### ⚠️ `s` 和 `t` 到底是什么？（一次只管一行）

⚠️ **这一步最容易卡住**：上面那句话里的 `s`、`t` 是**位置**，不是某一行。规则是：

> **对每一行 `have 名字 : 类型 := 证明`：**
> **`s` = `:=` 后面的那个证明；**
> **`t` = 这一行之后剩下的全部内容**（后面**还有几行** `have`／`show`，**全部算进 `t`**）。

把它**逐行**套到 §2 的 `t1` 上（注意 `t1` 有**两个** `have`）：

| 行 | `s` 是什么 | `t` 是什么 |
|---|---|---|
| `have hp : p := h.left` | **`h.left`** | **后面全部**：`have hq : q := h.right` **和** `show q ∧ p from And.intro hq hp` |
| `have hq : q := h.right` | **`h.right`** | `show q ∧ p from And.intro hq hp`（这次只剩一行） |

**第一行展开后长这样**（把「后面全部」包进一个参数为 `hp` 的 `fun`，再用 `h.left` 喂给它）——实测通过：

```lean
variable (p q : Prop)

theorem t1a (h : p ∧ q) : q ∧ p :=
  (fun (hp : p) => have hq : q := h.right
                    show q ∧ p from And.intro hq hp) h.left
```

**第二行展开后**是 `(fun (hq : q) => show q ∧ p from And.intro hq hp) h.right`。

⚠️ **两行接起来的顺序**：**后写的 `have` 在外面**、先写的在里面（因为第二行的 `t` 里含着第一行的 `have`）。拼起来就是 §3 下面那个 `t3`。

**一句话记法**：`s` 是**右边那一小段证明**，`t` 是**下面所有还没写完的部分**；`have` ＝「**把 `t` 包进一个 `fun`，再用 `s` 喂给它**」。

### 全部展开：手动写出 `fun` + 应用

**这段话可以自己验证**——把 §2 那个 `have` 例子**手动展开**成 `fun` + 应用（实测逐字通过）：

```lean
variable (p q : Prop)

theorem t3 (h : p ∧ q) : q ∧ p :=
  (fun (hq : q) => (fun (hp : p) => And.intro hq hp) h.left) h.right
```

⚠️ **两段代码是同一个证明**：`#print` 出来只有「有没有 `have` 糖」的差别：

```
#print t1
fun p q h => have hp := h.left; have hq := h.right; have this := ⟨hq, hp⟩; this

#print t3
fun p q h => (fun hq => (fun hp => ⟨hq, hp⟩) h.left) h.right
```

（这两条 `#print` 的**可运行版在 `03-7-示例.lean` §2**；讲义只贴输出，免得每块重复声明 `t1`/`t3`——**否则拼接会报 `already been declared`**。）

**这就是本课最值钱的一条**：**`have` 是你已学的东西的语法糖**。看懂它，「`have` 到底加了什么」这个问题就不存在了——**它加的假设，就是那个 `fun` 的参数**。

## 4. 那 `let` 和 `have` 有什么区别？（02-6 的 `let` 也能用）

**实测：两个都能在证明里用**：

```lean
variable (p q : Prop)

-- 用 `let`（02-6 学的）
theorem t4 (h : p ∧ q) : q ∧ p :=
  let hp : p := h.left
  let hq : q := h.right
  show q ∧ p from And.intro hq hp

-- 用 `have`（本课）
theorem t5 (h : p ∧ q) : q ∧ p :=
  have hp : p := h.left
  have hq : q := h.right
  show q ∧ p from And.intro hq hp
```

**两条都通过**。所以**不要记「`let` 在证明里不行」**——那是不存在的规则。差别只在**读起来的意思**：

| | 读作 | 什么时候用 |
|---|---|---|
| `let x : T := e` | 「**定义**一个中间值 `x`」 | 值是**数据**（02-6 的 `Nat` 例子） |
| `have h : p := e` | 「**已经证出**一个事实 `h`」 | 值是**证明**（`Prop`） |

**同一个证明写 `let` 也不算错**；本课统一用 `have`，是因为它把「这是我从假设里挖出来的事实」这件事写在了明面上。

## 5. `suffices`：倒着想——「**只要有这个就够了**」

原文（我译）：

> Lean 还支持一种**从目标倒着推理**的结构化方式，对应普通数学里「**suffices to show**（只需证明……就够了）」这种说法。

原文的例子（实测逐字通过）：

```lean
variable (p q : Prop)

theorem t2 (h : p ∧ q) : q ∧ p :=
  have hp : p := h.left
  suffices hq : q from And.intro hq hp
  show q from And.right h
```

**注意它和 §2 那个例子的关系**：原文说「**下一个例子只是把前一个的后两行换个顺序**」。

**逐行拆**（⚠️ **这是本课最容易看错的地方**）：

| 这一行 | 在干什么 |
|---|---|
| `have hp : p := h.left` | 和 §2 一样：先拿到 `hp : p` |
| `suffices hq : q from And.intro hq hp` | 读作「**只要有 `hq : q` 就够了**」——右边 `And.intro hq hp` 是**「有了 `hq` 之后，怎么做出原目标」**的证明 |
| `show q from And.right h` | 然后才去**把 `hq` 证出来**（从 `h` 取右边） |

⚠️ **顺序正好反过来**：`have` 是「**先做小步骤，再做结论**」；`suffices` 是「**先说结论需要什么，再去做那个步骤**」。

⚠️ **`suffices` 后面必须还有「怎么证它」**——只写 `suffices hq : q` 就结束，会得到**语法错**（实测）：

```
error: unexpected end of input; expected 'by' or ...
```

**并且它其实还是 `have`**——`#print t2` 实测：

```
fun p q h => have hp := h.left;
  have hq := (have this := h.right; this);
  ⟨hq, hp⟩
```

（`#print t2` 的**可运行版在 `03-7-示例.lean` §4**。）

（Lean 内部把 `suffices` 也记成了 `have`——**两个词，一个机制**。）

## 6. 三个「组织证明」的工具对照

| 写什么 | 断言什么 | 什么时候用 |
|---|---|---|
| `show T from e` | 「**这个东西的类型就是 `T`**」 | 你已经知道类型，但要**让 Lean 认出来**（§3-2 学的） |
| `have h : p := e` | 「**我又证出了一个事实 `h : p`**」 | 证明**长**、需要**踏脚石** |
| `suffices h : p from e` | 「**有了 `h : p` 就够**」 | 你**倒着想**更顺：先说清「还差什么」 |

⚠️ 三者的共同点：**它们都只是 `fun` + 应用**（§3）。**遇到不会写的组合，先问「这在 `fun` 里是哪个部分」。**

## 8. 小结

1. **`have h : p := e`** = 「**再证一个 `p`**，起名 `h`」——**类型不能省、写错当场报错**；
2. ⚠️ **`have h : p := e` 接 `t`，展开就是 `(fun (h : p) => t) e`**（原文原话，**实测**：手写展开版与 `have` 版是同一个证明）——**它是你已学的东西的语法糖**；
3. **`let` 也能用**（02-6）——差别是**读法**（数据 vs 事实），不是**能不能**；
4. **`suffices h : p from e`** = 「**有了 `h` 就够**」，**行序反过来**：先写 `from` 那一半，再证 `h`；它内部**也是 `have`**；
5. **`suffices` 漏了后半句会语法错**（实测）。
