# 第 4 章 · 第 5 课：计算式证明 `calc`

> **本课范围**：原文 **4.3 Calculational Proofs**（`calc` 的语法与语义）。
>
> **本课一句话**：`calc` 是**把「`A = B`、`B = C`、所以 `A = C`」写成一条链**的记法——
> 它**就是 `trans`**，只是摆成了人读得顺的样子。
>
> ⚠️ **本课只讲 `=` 的链**。原文后半还写了「`calc` 也能串**别的关系**（`<`、`≤`），还能自己加 `Trans` 实例」，
> 以及同一节的 `rw` / `simp` 版本——那些**本课不引入**，最后一节 §7 会逐条说清它们属于哪一章、现在为什么不必理解。
>
> ⚠️ **全节 tactic 0 处**：本课**只用证明项**（`calc` 本身不是 tactic，是**项**的写法）。

---

## §1 为什么需要 `calc`

04-4 你学了 `▸`：**把目标改一下**。但还有一种常见情形它帮不上：

> 手上有一串等式 `h1 : a = b`、`h2 : b = c`、`h3 : c = d`，要证 `a = d`。

用 **`trans`**（04-3 学的传递性）当然能写：

```lean
example (a b c d : Nat) (h1 : a = b) (h2 : b = c) (h3 : c = d) : a = d :=
  (h1.trans h2).trans h3
```

能过，但有两个毛病：

1. **括号**：三、四步还好，十步就是括号地狱；
2. **读起来是倒着的**：`(h1.trans h2).trans h3` 从里往外读才是 `a → b → c → d`，
   而人看等式链的习惯是**从上往下**。

`calc` 就是来解决这个的——**同一条链，换个摆法**。

---

## §2 两种写法

### 写法一：每一行都是完整的等式

```lean
section calc_basic
example (a b c d : Nat) (h1 : a = b) (h2 : b = c) (h3 : c = d) : a = d :=
  calc
    a = b := h1
    _ = c := h2
    _ = d := h3
end calc_basic
```

读法：

- 第一行写**起点**：`a = b`，右边给这一步的**证明** `h1`；
- 后面每行**开头是 `_`**——它的意思是「**接着上一行右边的那个东西**」；
  所以第二行 `_ = c` 其实是 `b = c`，第三行 `_ = d` 其实是 `c = d`；
- 整条链的类型是 `a = d`，正好是目标。

### 写法二：对齐写法（第一行只写起点）

重复写 `a = b`、`b = c` 有点啰嗦，`calc` 允许**把起点单独提出来**：

```lean
section calc_aligned
example (a b c : Nat) (h1 : a = b) (h2 : b = c) : a = c :=
  calc a
    _ = b := h1
    _ = c := h2
end calc_aligned
```

这里第一行 `calc a` 只给**起点表达式**（没有 `=`、也没有证明），
后面每行都以 `_` 开头——`_` 依然是「接着上一个表达式的右边」。

> 📌 **两种写法只是排版不同**。原文特别强调一点：**同一条 `calc` 里，所有关系符要在同一个缩进上**
> （「the calc relations all have the same indentation」）——也就是上面例子里每个 `=` 都对齐在那一列。

---

## §3 `calc` 到底是什么

### 每一格给的是什么

`calc` 里每写一行

```
A_i  op  A_{i+1}  :=  证明
```

右边的「证明」要证的**就是这一步**：`A_i op A_{i+1}`。
所以：

- `a = b := h1` —— 右边要给 `a = b` 的证明，`h1` 正好是；
- `_ = c := h2` —— 这一行实际是 `b = c`，`h2` 正好是；
- 每一步**只需要管自己那一小步**，不用管整条链。

### 整条 `calc` 是什么

整条 `calc` 的**类型**是 `A_0 = A_n`（从第一行左边，到最后一行右边）。

### ⭐ 实测：它就是 `trans`

我们写一个最小的两格 `calc`，然后让 Lean 把它的证明项**打印出来**：

```lean
section calc_print
theorem tsmall (a b c : Nat) (h1 : a = b) (h2 : b = c) : a = c :=
  calc
    a = b := h1
    _ = c := h2

set_option pp.proofs true in
#print tsmall
end calc_print
```

实跑输出（**逐字**）：

```
theorem tsmall : ∀ (a b c : Nat), a = b → b = c → a = c :=
fun a b c h1 h2 => trans h1 h2
```

**Lean 把整条 `calc` 推成了 `trans h1 h2`。** 所以：

> **`calc` 里一点也不新**——它和 04-3 的 `rfl`/`symm`/`trans`、04-4 的 `congr` 三兄弟一样，
> 是**你已经会的东西的另一种摆法**。本课要学的只是「怎么摆」，不是「新原理」。

## §4 原文的例子，逐步拆

原文 4.3 的主例子（**逐字照抄**）：

```lean
section calc_original
variable (a b c d e : Nat)

theorem T43
    (h1 : a = b)
    (h2 : b = c + 1)
    (h3 : c = d)
    (h4 : e = 1 + d) :
    a = e :=
  calc
    a = b      := h1
    _ = c + 1  := h2
    _ = d + 1  := congrArg Nat.succ h3
    _ = 1 + d  := Nat.add_comm d 1
    _ = e      := Eq.symm h4
end calc_original
```

它是怎么「接」起来的：

| 行 | 实际要证的那一小步 | 右边给的证明 | 这个证明从哪来 |
|---|---|---|---|
| 1 | `a = b` | `h1` | 假设 |
| 2 | `b = c + 1` | `h2` | 假设 |
| 3 | `c + 1 = d + 1` | `congrArg Nat.succ h3` | 04-4 的 `congrArg`（见 §5，**这格最值得看**） |
| 4 | `d + 1 = 1 + d` | `Nat.add_comm d 1` | 04-4 的 `Nat` 表（交换律） |
| 5 | `1 + d = e` | `Eq.symm h4` | 04-3 的 `.symm`（`h4` 是反的） |

**注意：五格里没有一格需要「看整条链」**——每格只交自己那一小步的证明。
把它们拼成整条链，是 **`calc` 自己的活儿**（也就是 §3 那个 `trans`）。

## §5 ⭐ 第 3 格：一个「定义相等」的格子

这一格是 `c + 1 = d + 1`，可你手上的 `h3` 是 **`c = d`**——**根本不是同一个命题**！
那 `congrArg Nat.succ h3` 凭什么能填进去？

- `congrArg Nat.succ h3` 的类型是 **`Nat.succ c = Nat.succ d`**（`Nat.succ` 是「后继」，即 `+1`）；
- 而这一格要的是 **`c + 1 = d + 1`**。

**两个类型为什么算同一个？** 因为 `Nat.succ c` 与 `c + 1` **定义相等**——`c + 1` 算一步就是 `Nat.succ c`。
（这就是 04-3 §5 学的**定义相等 vs 命题相等**：Lean 判类型时用的是**定义相等**，所以两边写法不同也能对上。）

**实测**（两个方向都成立，说明它们确实是「同一个东西的两种写法」，而不是「碰巧能推」）：

```lean
section calc_defeq
example (c : Nat) : c + 1 = Nat.succ c := rfl
example (c : Nat) : Nat.succ c = c + 1 := rfl
end calc_defeq
```

> 📌 这一格是本课**最值钱**的地方：它把 04-3 的「定义相等」用在了真实证明里。
> 你也可以把这一格写成更啰嗦但更直白的形式：先用 `congrArg` 得到 `Nat.succ c = Nat.succ d`，
> 靠**定义相等**直接当 `c + 1 = d + 1` 用——`calc` 不会因此报错。

## §6 `▸` / `trans` / `calc` 三者的分工

| 工具 | 它给你什么 | 什么时候用 |
|---|---|---|
| `trans`（04-3） | **一条等式**（把两条接成一条） | 你**需要这条等式本身**（比如还要喂给别人） |
| `▸`（04-4） | **改写后的结果**（不是等式） | 目标只差「换个写法」，一步到位 |
| **`calc`（本课）** | **一条等式**，但**多步**、**排版成链** | 你要**写出一条多步的推导**给人看 |

> **一句话**：`calc` 是**多步版的 `trans`**——它能干的事 `trans` 嵌套也能干（§3 已实测），
> 但 `calc` **把「每一步是什么」摆在了明面上**，所以**读起来像数学课本**。

## §7 本课不引入（明确标注）

原文 4.3 里还出现了下面这些，**本课一律不引入**，看到时**不必理解**：

| 原文里的东西 | 属于哪里 | 现在为什么不必理解 |
|---|---|---|
| `by rw [h1]` / `by rw [h1, h2, h3]` | **第 5 章（Tactics）** | `rw` 是 **tactic**；本课只写**项**。原文给这些写法，是为了跟 `calc` **对照**（同样的链，用 tactic 能更短） |
| `by simp [h1, h2, …]` | **第 5 章** | `simp` 也是 tactic |
| `by …`（`by` 开头） | **第 5 章** | `by` 是「进入 tactic 模式」的开关——本课不碰 |
| `a < d`、`b ≤ c` 那种**混着 `<`/`≤` 的链** | 符号本身**本章没讲** | 原文用它说明「`calc` 不止能串 `=`」；**机制**（`Trans` 实例）在**第 9/10 章**（类型类） |
| `instance : Trans divides divides divides where …` | **第 9/10 章** | 类型类实例；而且例子里的 `divides` 用到了 **`∃`**（**4.4**，下一课才讲） |
| `infix:50 " | " => divides` | 更后面的章节 | 自定义中缀记法 |
| `∃ k, k*x = y`、`⟨k, rfl⟩`、`let ⟨k₁, d₁⟩ := h₁` | **4.4**（下一课） | 存在量词与它的构造/拆解 |

> ⚠️ **一句提醒**：这些**不影响本课**。本课的 `calc` **只用 `=`**，只用你已经有的东西：
> 假设、`rfl` / `.symm` / `.trans`、`congrArg` / `congr`、`Nat` 常用等式表。
