## 1. 定位：前面学的规则都是「构造性」的

原文（我译）：

> 到目前为止我们见过的引入与消去规则全都是**构造性**的，也就是说，它们反映的是基于**命题即类型**对应、**带计算性理解**的逻辑连接词。普通的经典逻辑在此之上加上**排中律** `p ∨ ¬p`。

**「构造性」是什么意思**：在这套规则里，**「我证明了 `p ∨ q`」意味着「**我真的知道**是 `p` 还是 `q`」**——因为构造 `Or.inl` 必须交出一个 `p` 的证明，构造 `Or.inr` 必须交出一个 `q` 的证明，**没有第三种办法**（03-4 实测过：只有一个构造子时 Lean 知道用哪个，有两个时它**无从选择**，于是你必须用 `Or.elim` 说明两种情况怎么处理）。

原文接着给了一个很好的比喻：

> 构造性的「或」非常强：断言 `p ∨ q` 等价于**知道是哪一个**。如果 `RH` 代表**黎曼猜想**，一个**经典**数学家愿意断言 `RH ∨ ¬RH`，**尽管我们还不能断言其中任何一个分支**。

⚠️ **关键区别**：`p ∨ ¬p`（排中律）**不需要你先知道 `p` 是真是假**——它只说「**两者必居其一**」。

## 2. 排中律：**必须先 `open Classical`**

实测（原文例子）：

```lean
open Classical

variable (p : Prop)

#check em p
```

输出：

```
em p : p ∨ ¬p
```

⚠️ **实测：不 `open Classical` 就写 `em`，会直接报错**：

```
error(lean.unknownIdentifier): Unknown identifier `em`
```

- `em`（**excluded middle**，排中律）**在 `Classical` 命名空间里**（02-8 讲过 `namespace` / `open`）；
- `open Classical` 的意思是「**把这个命名空间里的名字拿进来用**」；
- 也**可以不 open、直接写全名** `Classical.em p`（实测可用）。

## 3. ⚠️ 构造性地**证不出** `p ∨ ¬p`

**实测**：不用 `Classical` 去证，会得到**类型错**（不是「没写完」，是**写不下去**）：

```
theorem em0 (p : Prop) : p ∨ ¬p :=
  Or.elim p (fun hp => Or.inl hp) (fun hnp => Or.inr hnp)
```

```
error: Application type mismatch: The argument
  p
has type
  Prop
of sort `Type` but is expected to have type
  ?m.1 ∨ ?m.2
of sort `Prop` in the application
  Or.elim p
```

⚠️ **读懂这个错**：`Or.elim` 的**第一个参数是那个「或」的证明**（`p ∨ ¬p`），**不是** `p` 本身。`p` 只是个 `Prop`，**它不是 `p ∨ ¬p` 的证明**——而 Lean 里**没有构造子能把一个不知道内容的 `p` 直接变成 `p ∨ ¬p`**。

### ⚠️⚠️ 关键：「我们把式子写错了」和「根本写不出来」是**两件事**

⚠️ 上面那个类型错**只能证明「这一个表达式不对」**，**不足以证明「不存在任何表达式」**——后者需要**另外的证据**。这两层必须分清：

**第一层（直观）：同一形状，喂对参数就过**

```lean
variable (p : Prop)

theorem shape_ok (h : p ∨ ¬p) : p ∨ ¬p :=
  Or.elim h (fun hp => Or.inl hp) (fun hnp => Or.inr hnp)
```

⚠️ 实测：**通过**，且 `#print axioms shape_ok` → **`does not depend on any axioms`**。
→ 说明**两个分支都没写错**，缺的**正是那个「或」本身**。

**第二层（机械证据）：`#print axioms` 看「公理依赖」**

```lean
open Classical

#print axioms Classical.em
```

实测输出：

```
'Classical.em' depends on axioms: [propext, choice, Quot.sound]
```

⚠️ **这就是「它不可能在构造性核心里被证出来」的机械信号**：一条**能被证出来**的定理，公理依赖是**空的**（本课前面所有构造性定理实测都是 `does not depend on any axioms`）；而 `em` **必须靠公理**（那三条是什么，**第 10 章**讲）。**如果它是可证的，库就不需要把它设成公理。**

**第三层（我们能走到多近）：`¬¬(p ∨ ¬p)` 是「构造性可证」的**

```lean
theorem my_not_not_em (p : Prop) : ¬¬(p ∨ ¬p) :=
  fun h => h (Or.inr (fun hp => h (Or.inl hp)))
```

⚠️ 实测：**通过**，且**不依赖任何公理**（Lean 库里本来就有 `not_not_em (a : Prop) : ¬¬(a ∨ ¬a)`）。
→ **我们能证明「排中律不可能失败」，就是不能证明「排中律成立」**——**差的那一步正好是双重否定消去**，而它要 `Classical`。

**第四层（数学事实，⚠️ 我在本机「无法实测」）：反模型**

**两世界模型**（Kripke 反例，我译述）：

- 设想两个「知识阶段」：**0**（现在）与 **1**（以后，知道得更多）；
- 让命题 `p` 的含义是「**到阶段 1 才成立**」——即**现在既不能断言 `p`，也不能断言 `¬p`**；
- 在阶段 0 检验 `p ∨ ¬p`：
  - 左支 `p`：阶段 0 **不成立** → 给不出来；
  - 右支 `¬p`：`¬p` 的意思是「**往后所有阶段都不成立**」，而阶段 1 里成立 → **也给不出来**；
- 所以 `p ∨ ¬p` **在阶段 0 不成立** → 这个模型**不满足排中律**；
- 而**构造性逻辑的定理必须在所有这类模型里都成立** → **`p ∨ ¬p` 不是构造性定理，任何表达式都证不出它**。

💡 **「阶段」正是「证明 = 构造/程序」的语义对应物**：一个 `p ∨ ¬p` 的证明会是一个**能对任意命题下判断**的程序——而那样的程序不存在（否则它连黎曼猜想都能判定）。

⚠️ **诚实标注**：第 1～3 层我都在本机**实测**过；**第 4 层是数学事实（模型论），我无法在这台机器上验证**，所以在这里**明确分开写**。

**用 `Classical` 就一行**（实测）：

```lean
open Classical

variable (p : Prop)

theorem em0 (p : Prop) : p ∨ ¬p := Classical.em p
```

## 4. 双重否定消去：排中律的第一个推论

原文（我译）：

> 排中律的一个推论是**双重否定消去**原理。

原文的例子（实测逐字通过）：

```lean
open Classical

theorem dne {p : Prop} (h : ¬¬p) : p :=
  Or.elim (em p)
    (fun hp : p => hp)
    (fun hnp : ¬p => absurd hnp h)
```

**逐行拆**（`Or.elim` 用法同 03-4）：

| 这一行 | 在干什么 |
|---|---|
| `Or.elim (em p)` | 拿排中律：**要么 `p`，要么 `¬p`** |
| `(fun hp : p => hp)` | **情况一**：如果 `p` 成立，**目标就是 `p`**，直接交出 `hp` |
| `(fun hnp : ¬p => absurd hnp h)` | **情况二**：如果 `¬p` 成立——手上**同时有**「`¬p`」和「`¬¬p`」→ `absurd` 出 `False`（03-5 学的） |

⚠️ **为什么这条「推论」值得学**：它让**反证法**变得合法——**「假设 `¬p`，推出 `False`」就等于证明了 `p`**，因为那恰好就是 `¬¬p → p`。

**已证的名字**：`Classical.not_not` 也是同一条原理（实测 `#check` 通过）——但本课统一手写 `dne`，**看懂上面这三行比记住名字重要**。

## 5. 两种证明模式：`byCases` 与 `byContradiction`

原文（我译）：

> 经典公理还给了你**另外两种证明模式**，它们都可以靠 `em` 来正当化：**分情况证明**……或者**反证**。

⚠️ **原文这两个例子用的就是「证明项」写法**（不是 tactic）——本课就用它们：

**分情况**（`byCases`：把 `p` / `¬p` 两种情况各写一份）：

```lean
open Classical

variable (p : Prop)

example (h : ¬¬p) : p :=
  byCases
    (fun h1 : p => h1)
    (fun h1 : ¬p => absurd h1 h)
```

**反证**（`byContradiction`：只写「假设 `¬p`」那一半）：

```lean
open Classical

variable (p : Prop)

example (h : ¬¬p) : p :=
  byContradiction
    (fun h1 : ¬p =>
     show False from h h1)
```

⚠️ **`byContradiction` 帮你省掉的那半句**：它**替你做了**「先把 `¬p` 当假设递进来」这一步（03-5 §6.37 那条坑就在这里）——所以**你只写「从 `¬p` 出发怎么推出矛盾」**。

⚠️ **不要混淆**：tactic 版写作 `by_cases h : p` / `by_contradiction h`（**带下划线**）——那是**第 5 章**的内容，本课不引入。

## 6. 什么时候**真的**需要经典逻辑

原文（我译）：

> 如果你不习惯构造性地思考，可能要过一阵子才能体会**经典推理出现在哪里**。下面这个例子需要它，因为**从构造的角度，「`p` 和 `q` 不同时为真」并不一定告诉你哪一个是假的**。

原文的例子（实测逐字通过，**必须 `open Classical`**）：

```lean
open Classical

variable (p q : Prop)

example (h : ¬(p ∧ q)) : ¬p ∨ ¬q :=
  Or.elim (em p)
    (fun hp : p =>
      Or.inr
        (show ¬q from
          fun hq : q =>
          h ⟨hp, hq⟩))
    (fun hp : ¬p =>
      Or.inl hp)
```

**逐行拆**（`Or.elim (em p)` 分两种情况，**每一支要交出 `¬p ∨ ¬q` 的一个证明**）：

| 情况 | 手上有什么 | 要交出什么 | 怎么得到 |
|---|---|---|---|
| `p` 成立 | `hp : p` | **`¬q`**（所以 `Or.inr`） | 若还有 `hq : q`，则 `⟨hp, hq⟩ : p ∧ q`，与 `h` 矛盾 → `fun hq => h ⟨hp, hq⟩` |
| `¬p` 成立 | `hp : ¬p` | **`¬p`**（所以 `Or.inl`） | 直接交出 `hp` |

⚠️ **为什么构造性地做不到**：`h : ¬(p ∧ q)` 只告诉你**两个都不同时成立**；**它没告诉你「到底是 `p` 不成立，还是 `q` 不成立」**——要**二选一**，就得靠排中律。（**不 open 的实测报错**：`Unknown identifier em`）

### ⚠️ 对照：有一类**不需要**经典

**同一个道理，反过来却构造性地就能证**（实测通过，**完全没有 `Classical`**）：

```lean
variable (p q : Prop)

example (h : ¬(p ∨ q)) : ¬p ∧ ¬q :=
  ⟨fun hp => h (Or.inl hp), fun hq => h (Or.inr hq)⟩
```

⚠️ **为什么不需要**：目标 `¬p ∧ ¬q` 要求**两个都给出来**——**不用二选一**。原文在 3.5 末尾也提过：构造逻辑里**有些情形**是允许这样分类讨论的，Lean 支持那种情形**而不必依赖排中律**（那些内容属**第 6 章**，本课不引入）。

### 📐 判准：到底什么时候要、什么时候不要

⚠️ 原文 3.5 有一句**判准**（我译）：

> 要点是：**在很多推理里，`∧`、`∨`、`¬`、`→` 都是可以直接用的，不必碰经典逻辑**……我们真正需要经典逻辑，**是在使用排中律的时候**。

把它变成可操作的**三盏信号灯**：

| 灯 | 判据 | 例子（**全部实测**） | 公理依赖 |
|---|---|---|---|
| 🟢 **绿** | 目标里是 **`∧`**，且要**两个都给** | `¬(p ∨ q) ⊢ ¬p ∧ ¬q` | **无** |
| 🟢 **绿** | 目标里是 **`∨`，但你手上已经有一支** | `hp : p ⊢ p ∨ q`（`Or.inl hp`） | **无** |
| 🟢 **绿** | 只想「**两种情况下都能推出结论**」 | `(p → q) ⊢ ¬q → ¬p`（逆否） | **无** |
| 🔴 **红** | 需要「**判定 `p` 的真假**」，而 `p` **算不出来** | `¬¬p ⊢ p`（双重否定消去） | `[propext, choice, Quot.sound]` |
| 🔴 **红** | 同上，且两个分支**都缺东西** | `¬(p ∧ q) ⊢ ¬p ∨ ¬q` | 同上 |
| 🔴 **红** | 「**已知 `p → q`，要么 `p` 不成立要么 `q` 成立**」 | `(p → q) ⊢ ¬p ∨ q` | 同上 |

⚠️ **绿/红之间那条最细的分界**（实测对照，这一对最能说明问题）：

```lean
variable (p q : Prop)

-- 🟢 绿：只是把「假设 p 假」化成「假设 q 假」——**不需要经典**
theorem B5a (h : p → q) (hnq : ¬q) (hp : p) : False := hnq (h hp)
```

⚠️ **注意**：`A2` 那块**需要 `open Classical`**（它用了 `em`），单独编译时要**自带这一行**：

```lean
open Classical

variable (p q : Prop)

-- 🔴 红：想**判定 p** 好用它做分类——**需要经典**
theorem A2 (h : p → q) : ¬p ∨ q :=
  Or.elim (em p) (fun hp => Or.inr (h hp)) (fun hn => Or.inl hn)
```

`#print axioms B5a` → **`does not depend on any axioms`**；
`#print axioms A2` → **`depends on axioms: [propext, choice, Quot.sound]`**。

💡 **一句话判准**：**你这一步是要「**判断** `p` 的真假」，还是「**不管真假都能推出结论**」？** 要**判断** → 需要经典；只要**两种情形都写得出来** → 构造性就够。

### 🎁 第三类：有些命题**本来就能算出来**——**连红都不亮**

⚠️ 这是最重要的一条**例外**（属**第 6 章**，本课**只给实测、不展开**）：

```lean
theorem C1 (n : Nat) : n = 0 ∨ ¬(n = 0) := Decidable.em (n = 0)

#print axioms C1
```

实测：`'C1' does not depend on any axioms` —— **零公理！**

⚠️ **和 §2 的 `em p` 对照看**：**同一个形状 `p ∨ ¬p`**

- `p` 是**任意命题** → 依赖 `[propext, choice, Quot.sound]`（**红**）；
- `p` 是 **`n = 0` 这种能算的** → **零公理**（**绿**）。

💡 因为 `n = 0` **有办法判定**：Lean 能**实际算出**它，所以**根本不需要排中律**——它自己就是一个「程序」。

→ **所以完整的判准是**：

> **需要经典 = 「我要二选一」 + 「这个二选一算不出来」。**
> **两个条件同时满足才需要。**

### ⚠️ 我在这条上踩过的两个坑（记下来别再犯）

1. 我一度想用 `(p → q) ⊢ ¬q → p` 当「需要经典」的例子——**它根本不是定理**：取 `p := False`、`q := False`，左边成立而右边是 `False`。（**先问「这是不是定理」**）
2. 我把逆否命题的**方向写反了**（`¬q → ¬p` **加** `p`，推不出 `¬q`）——**逆否是 `(p → q) ↔ (¬q → ¬p)`，两个方向都是构造性的**。

## 8. 三种「二选一」写法对照

| 写法 | 形状 | 你要写几份 |
|---|---|---|
| `Or.elim (em p) …` | 经典原理 + 分情况 | **两份**（`p` 那支、`¬p` 那支） |
| `byCases (fun hp : p => …) (fun hn : ¬p => …)` | 经典模式（**语法糖**） | **两份** |
| `byContradiction (fun h1 : ¬p => …)` | 经典模式 | **一份**（只写「从 `¬p` 怎么出矛盾」） |

⚠️ 三者**都能用**（实测），选哪个看**你要写几支**。

## 9. 小结

1. **构造性**：前面所有规则；`p ∨ q` 意味着「**知道是哪一个**」；
2. **排中律** `p ∨ ¬p` = `em p`，**在 `Classical` 命名空间里**，要 `open Classical`（实测：不 open → `Unknown identifier em`）；
3. ⚠️ **构造性证不出** `p ∨ ¬p`（实测类型错）——**只能整条买**；
4. **双重否定消去** `¬¬p → p`（原文 `dne` 的三行）→ **反证法合法**；
5. **两种模式**：`byCases`（两支）、`byContradiction`（一支）；⚠️ **tactic 版属第 5 章**；
6. **真需要经典的例子**：`¬(p ∧ q) ⊢ ¬p ∨ ¬q`（**要二选一**）；**反例**：`¬(p ∨ q) ⊢ ¬p ∧ ¬q`（**不用二选一**，构造性就行）。
